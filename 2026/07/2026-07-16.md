## Advanced search for Projects is generally available

**URL:** https://github.blog/changelog/2026-07-16-advanced-search-for-projects-is-generally-available

### 要約
GitHub Projects のフィルターバーで、AND/OR を使った複雑な検索式が一般提供になりました。あわせて、pull request アイテムを review state で絞り込む `reviews:` フィルタと、deployment statuses の 90 日保持ポリシーも導入されています。

### ユーザーにとって良いこと
目的に合う Project view を 1 つに集約しやすくなり、用途ごとにビューを増やしすぎずに済みます。PR のレビュー状況や deployment 履歴の扱いも整理され、トリアージと可視化がしやすくなります。

### アクションプラン
- Project views を使っているチームは、既存の分割ビューを AND/OR 条件にまとめ直してください。
- PR を Projects に載せている場合は、`reviews:` フィルタでレビュー待ち・承認済みの見え方を確認してください。
- ⚠️ deployment statuses は 90 日を超えると API から削除されるため、長期保管が必要な監査・レポートは別ストアに退避してください。

## Repository admins can archive pull requests

**URL:** https://github.blog/changelog/2026-07-16-repository-admins-can-archive-pull-requests

### 要約
Repository admins が pull request を archive して、公開表示から外せるようになりました。archived PR は close かつ lock され、非 admin には 404 を返しますが、admin には履歴として残ります。

### ユーザーにとって良いこと
スパムや荒らし、法務・ポリシー対応が必要な PR を、削除せずに整理できます。公開面からは隠しつつ管理者には残せるため、モデレーションと証跡保持の両立がしやすくなります。

### アクションプラン
- リポジトリ運営ルールに、削除ではなく archive を使うケースを明記してください。
- `is:archived` フィルタを使う triage 手順を maintainer に共有してください。
- ⚠️ unarchive 後も PR は closed/locked のままなので、再公開時の扱いを運用に組み込んでください。

### リファレンス
- [Repository admins can archive pull requests](https://github.blog/changelog/2026-07-16-repository-admins-can-archive-pull-requests)

## REST API endpoints for Visual Studio Subscription management

**URL:** https://github.blog/changelog/2026-07-16-rest-api-endpoints-for-visual-studio-subscription-management

### 要約
GitHub Enterprise Cloud の admin 向けに、Visual Studio Subscription の割り当てを REST API で管理するエンドポイントが追加されました。UPN と GitHub handle の対応付け、割り当ての一覧取得、手動マッチ解除をプログラムから実行できます。

### ユーザーにとって良いこと
SCIM と UPN の形式が合わずに手作業になっていた割り当て作業を、自動化しやすくなります。大規模な enterprise でも、修正漏れや再マッチの対応をスクリプト化して運用負荷を下げられます。

### アクションプラン
- enterprise の VSS 割り当てを管理している場合は、`GET /enterprises/{enterprise}/visual-studio-subscriptions` で現状を棚卸ししてください。
- UPN-to-handle の crosswalk を用意し、`PUT` エンドポイントで一括マッチを自動化してください。
- 誤割り当てがある運用では、`DELETE /enterprises/{enterprise}/visual-studio-subscriptions/{visual_studio_subscription_id}` で手動修正できるフローを整備してください。

### リファレンス
- [REST API endpoints for Visual Studio Subscription management](https://github.blog/changelog/2026-07-16-rest-api-endpoints-for-visual-studio-subscription-management)

## Xcode 27 runner image now in public preview

**URL:** https://github.blog/changelog/2026-07-16-xcode-27-runner-image-now-in-public-preview

### 要約
GitHub-hosted macOS runners で Xcode 27 の runner image が public preview になりました。新しい macOS image は major Xcode version ベースのサポートモデルに移行し、arm64 でのみ利用できます。

### ユーザーにとって良いこと
最新の Xcode と Apple SDK を早めに使って、互換性問題を先回りして見つけやすくなります。CI の対象ツールチェーンを明示しやすくなり、Apple 向けビルドの検証を新しい環境に寄せられます。

### アクションプラン
- GitHub Actions の `runs-on` を `xcode-27` または `xcode-27-xlarge` に切り替えて、必要な workflow を先行検証してください。
- ⚠️ Intel macOS runner では利用できないため、対象ジョブが arm64 前提で問題ないか確認してください。
- 既存のビルド依存ツールや SDK 差分を確認し、Xcode 27 での失敗パターンをリリース前に洗い出してください。

### リファレンス
- [Xcode 27 runner image now in public preview](https://github.blog/changelog/2026-07-16-xcode-27-runner-image-now-in-public-preview)
