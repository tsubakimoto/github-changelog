## GitHub Models is now retired

**URL:** https://github.blog/changelog/2026-07-30-github-models-is-now-retired

### 要約
GitHub Models は 2026 年 7 月 30 日で終了し、playground、model catalog、inference API、BYOK はすべて利用できなくなりました。7 月 1 日に告知されていた退役が完了した形です。

### ユーザーにとって良いこと
既存の選択肢が整理され、GitHub 上での AI 利用は GitHub Copilot、外部のモデル利用は Microsoft Foundry に寄せやすくなります。移行先が明確なので、今後の構成を決めやすくなります。

### アクションプラン
- GitHub Models を使っているワークフローや検証手順を停止し、依存箇所を洗い出してください。
- GitHub 上で AI を使う用途は GitHub Copilot に、モデルアクセスが必要な用途は Microsoft Foundry に移行してください。
- ⚠️ 既存の playground / inference API / BYOK 前提の自動化は動作しないため、代替実装へ切り替えてください。

- [GitHub Models is now retired](https://github.blog/changelog/2026-07-30-github-models-is-now-retired)

## Reference same-repository actions with self-repository syntax

**URL:** https://github.blog/changelog/2026-07-30-reference-same-repository-actions-with-self-repository-syntax

### 要約
同じリポジトリ内の action や reusable workflow を、`$/.` から始まる self-repository syntax で参照できるようになりました。checkout を不要にしつつ、実行中の commit と同じ ref を自動で使えます。

### ユーザーにとって良いこと
内部参照が簡単になり、SHA pinning を崩さずに同一リポジトリ内の action を再利用できます。メンテナンス負担が減り、参照先のズレも起きにくくなります。

### アクションプラン
- 同一リポジトリ内の `./` 参照や checkout 前提の action 呼び出しを self-repository syntax に置き換えてください。
- enterprise で full-length commit SHA pinning を必須にしている場合は、この構文を使うようワークフローを更新してください。
- runner を 2.336.0 以上に更新してください。

- [Reference same-repository actions with self-repository syntax](https://github.blog/changelog/2026-07-30-reference-same-repository-actions-with-self-repository-syntax)

## Stacked pull requests are now in public preview

**URL:** https://github.blog/changelog/2026-07-30-stacked-pull-requests-are-now-in-public-preview

### 要約
Stacked pull requests が public preview になり、巨大な変更を順序付きの小さな PR に分割してレビューできるようになりました。1 つずつ、またはまとめてマージでき、既存の checks や branch protections もそのまま使えます。

### ユーザーにとって良いこと
レビューしやすい単位で並列に進められるため、大きな変更でも停滞しにくくなります。レビュー品質とスループットの両方を改善できます。

### アクションプラン
- 大きな機能追加やリファクタを stack 化し、1 PR あたりの変更を小さくしてください。
- `gh extension install github/gh-stack` で CLI 拡張を導入し、既存の開発フローに組み込んでください。
- Merge queue を使っている場合は、順次対応が広がるため適用状況を確認してください。

### リファレンス
- [Stacked pull requests are now in public preview](https://github.blog/changelog/2026-07-30-stacked-pull-requests-are-now-in-public-preview)

## Limit remote control to managed devices

**URL:** https://github.blog/changelog/2026-07-30-limit-remote-control-to-managed-devices

### 要約
企業や組織が、Copilot の remote control セッションをホストできるデバイスを制限できるようになりました。SSO 必須、無効化、許可の切り替えを managed settings で細かく制御できます。

### ユーザーにとって良いこと
管理対象デバイスに限定することで、リモート操作の安全性と統制を高められます。組織ポリシーを device 単位まで落とし込めるようになります。

### アクションプラン
- remote control の利用可否を enterprise policy と managed setting の両方で見直してください。
- `copilot-settings.json` または MDM / server-managed 配布で `remoteControl` を設定してください。
- SSO 要件やデバイス単位の制限が必要な場合は `requireSSO` を採用してください。
