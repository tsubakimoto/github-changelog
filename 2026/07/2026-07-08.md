## Innersource security advisories are generally available

**URL:** https://github.blog/changelog/2026-07-08-innersource-security-advisories-are-generally-available

### 要約
GitHub Advanced Security の Enterprise Cloud 利用者向けに、内部向けの security advisory を公開できるようになりました。open source の advisory と同様の流れで扱えますが、可視性は enterprise 所有のリポジトリに限定されます。関連コンポーネントを起点に、REST API で作成・更新・取り下げもできます。

### ユーザーにとって良いこと
社内コンポーネントの脆弱性情報を、外部公開せずに Dependabot や運用フローへつなげられます。内部向けの脆弱性対応を GitHub 上で一元化しやすくなります。

### アクションプラン
- Enterprise Cloud で社内コンポーネントを管理している場合は、Innersource advisory の運用フローを決めてください。これは **enterprise 内部の脆弱性管理機能** です。
- REST API で advisory を作成・更新・取り下げする自動化を、既存の脆弱性管理手順に合わせて実装してください。
- Dependabot 通知の対象になる内部リポジトリを棚卸しし、社内パッケージの影響範囲を確認してください。

### リファレンス
- [Innersource security advisories are generally available](https://github.blog/changelog/2026-07-08-innersource-security-advisories-are-generally-available)

## Enterprise-managed OpenTelemetry export for VS Code and CLI

**URL:** https://github.blog/changelog/2026-07-08-enterprise-managed-opentelemetry-export-for-vs-code-and-cli

### 要約
Copilot の OpenTelemetry データ送信先を enterprise 管理設定で指定できるようになりました。VS Code の Copilot Chat 拡張と Copilot CLI の agent host に適用され、各開発者が `OTEL_*` 環境変数を個別設定する必要がなくなります。OTLP の endpoint と transport も管理できます。

### ユーザーにとって良いこと
テレメトリの送信先を組織で統制でき、監査やデータ保管先の要件に合わせやすくなります。開発者側の手作業設定も減ります。

### アクションプラン
- Enterprise 管理者は telemetry ブロックで OTLP export endpoint と transport を明示してください。これは **管理者が配布する設定** です。
- VS Code と Copilot CLI の両方で、指定先の collector が受けられることを事前に検証してください。
- 各開発者に `OTEL_*` の個別設定を残している場合は、enterprise-managed 設定へ統一してください。

- [Enterprise-managed OpenTelemetry export for VS Code and CLI](https://github.blog/changelog/2026-07-08-enterprise-managed-opentelemetry-export-for-vs-code-and-cli)

## Deploy managed Copilot settings via MDM in VS Code and CLI

**URL:** https://github.blog/changelog/2026-07-08-deploy-managed-copilot-settings-via-mdm-in-vs-code-and-cli

### 要約
GitHub Copilot の managed settings を、server-managed だけでなく MDM やファイルベースの設定でも配布できるようになりました。Intune、Jamf、Group Policy などの既存の端末管理基盤を使って、VS Code と Copilot CLI に統一した設定を届けられます。これは GA です。

### ユーザーにとって良いこと
端末単位で Copilot の運用ルールを強制しやすくなり、組織のガバナンスと端末管理を合わせられます。ローカル設定のばらつきを抑えやすくなります。

### アクションプラン
- 端末管理を使っている管理者は、MDM か file-based config のどちらで配るかを決めてください。これは **既存の管理経路を拡張する設定** です。
- Intune、Jamf、Group Policy の配布内容を、server-managed settings と同じ方針になるよう揃えてください。
- VS Code と Copilot CLI で期待どおりに設定が反映されるか、代表端末で確認してください。

### リファレンス
- [Deploy managed Copilot settings via MDM in VS Code and CLI](https://github.blog/changelog/2026-07-08-deploy-managed-copilot-settings-via-mdm-in-vs-code-and-cli)

## setup-java v5.5.0: signature verification, Kona JDK, and Maven fixes

**URL:** https://github.blog/changelog/2026-07-08-setup-java-v5-5-0-signature-verification-kona-jdk-and-maven-fixes

`actions/setup-java` v5.5.0 で、JDK ダウンロード時の署名検証が追加されました。Temurin と Microsoft distribution では `verify-signature: true` で検証でき、Kona JDK のサポートと Maven 向けの修正も含まれます。

- Temurin または Microsoft を使っているジョブでは `verify-signature: true` を有効化し、署名検証が通ることを確認してください。
- Maven を使うジョブは、既存のキャッシュや依存解決に影響がないかを確認してください。

## npm install-time security and GAT bypass2fa deprecation

**URL:** https://github.blog/changelog/2026-07-08-npm-install-time-security-and-gat-bypass2fa-deprecation

### 要約
npm v12 が generally available になり、install 時のセキュリティ既定値が有効になりました。依存パッケージの lifecycle scripts や install に関する自動動作は、これまでより明示的な opt-in が必要です。同時に、2FA bypass を前提にした granular access token の一部利用は段階的に非推奨になります。

### ユーザーにとって良いこと
インストール時の自動実行リスクを減らしやすくなり、サプライチェーン保護が強化されます。認証まわりの運用もより厳密になります。

### アクションプラン
- npm v12 への更新影響を確認し、`allowScripts` などの install-time 設定を明示してください。これは **既定動作が変わる変更** です。
- lifecycle scripts に依存するパッケージがある場合は、CI とローカルで明示的な許可が必要かを洗い出してください。
- 2FA bypass GAT を使っている運用があれば、今後の非推奨対応に向けて token 方針を見直してください。

### リファレンス
- [npm install-time security and GAT bypass2fa deprecation](https://github.blog/changelog/2026-07-08-npm-install-time-security-and-gat-bypass2fa-deprecation)

## Add review cycles and time to adoption phases in the usage API

**URL:** https://github.blog/changelog/2026-07-08-add-review-cycles-and-time-to-adoption-phases-in-the-usage-api

### 要約
Copilot usage metrics API の adoption phase 集計に、review cycles と time の指標が追加されました。各フェーズごとの merge time や merge counts に加えて、PR が何回レビューされたか、どれくらい速くレビューが進んだかを比較できます。

- 既存のダッシュボードでは、merge time だけでなく review cycle も並べて可視化してください。
- adoption phase ごとの比較基準を更新し、レポートの説明文も新指標に合わせて直してください。
