## Improved accuracy and coverage in Copilot usage metrics reports

**URL:** https://github.blog/changelog/2026-07-02-improved-accuracy-and-coverage-in-copilot-usage-metrics-reports

### 要約
Copilot usage metrics API の精度とカバレッジが改善されました。CLI の suggested lines of code が計上されるようになり、server-side telemetry でしか見えていなかったユーザーの IDE 情報もより多く反映されます。AI credits の attribution も修正され、実利用により近い集計になります。

### ユーザーにとって良いこと
IDE / CLI / server-side の利用実態をまたいで、Copilot の利用状況をより正確に把握できます。レポートの欠損や 0 扱いが減るため、監査・分析・課金把握の信頼性が上がります。

### アクションプラン
- Copilot usage metrics API を使うダッシュボードやレポートの再集計を実施してください。
- CLI 利用分の suggested lines of code と code generation 指標の変化を確認してください。
- 1.0.57 以降の Copilot CLI を使っているか確認し、1.0.64 以降では重複計上が抑制される前提で集計してください。

## Upcoming deprecation of Gemini 2.5 Pro and Gemini 3 Flash

**URL:** https://github.blog/changelog/2026-07-02-upcoming-deprecation-of-gemini-2-5-pro-and-gemini-3-flash

### 要約
Copilot の全体験で Gemini 2.5 Pro と Gemini 3 Flash が 2026-07-31 に非推奨になります。代替として Gemini 3.1 Pro と Gemini 3.5 Flash が案内されています。組織ポリシーで新しいモデルの利用許可が必要な場合があります。

### ユーザーにとって良いこと
サポート終了前に後継モデルへ移行することで、Copilot の各機能を継続して使えます。モデル切り替えを先に済ませると、チャット・エージェント・補完の運用停止を避けられます。

### アクションプラン
- 7/31 までに workflows と統合先のモデル設定を Gemini 3.1 Pro / Gemini 3.5 Flash に切り替えてください。
- Copilot Enterprise 管理者は model policies で代替モデルを有効化してください。
- ⚠️ 期限後は対象モデルが利用できなくなるため、利用中の自動化を事前に棚卸ししてください。

- [Upcoming deprecation of Gemini 2.5 Pro and Gemini 3 Flash](https://github.blog/changelog/2026-07-02-upcoming-deprecation-of-gemini-2-5-pro-and-gemini-3-flash)

## Copilot CLI no longer needs a personal access token in GitHub Actions

**URL:** https://github.blog/changelog/2026-07-02-copilot-cli-no-longer-needs-a-personal-access-token-in-github-actions

### 要約
GitHub Actions で Copilot CLI を `GITHUB_TOKEN` で実行できるようになりました。長期 PAT を保存せずに済むため、運用とセキュリティの負担が減ります。組織所有リポジトリでは利用分の AI credits は組織に直接請求されます。

### ユーザーにとって良いこと
Secrets 管理が簡単になり、漏えいリスクも下がります。ワークフローの認証設定が軽くなり、PAT のローテーションや保管を気にせず自動化できます。

### アクションプラン
- `copilot-requests: write` 権限を付けて、既存の PAT ベースのワークフローを `GITHUB_TOKEN` に置き換えてください。
- 組織ポリシーで「Allow use of Copilot CLI billed to the organization」を有効化してください。
- 必要に応じて `copilot update` か `npm install -g @github/copilot` で CLI を更新してください。

### リファレンス
- [Copilot CLI no longer needs a personal access token in GitHub Actions](https://github.blog/changelog/2026-07-02-copilot-cli-no-longer-needs-a-personal-access-token-in-github-actions)

## Copilot agent session streaming is now in public preview

**URL:** https://github.blog/changelog/2026-07-02-copilot-agent-session-streaming-is-now-in-public-preview

### 要約
Enterprise Managed Users を持つ GitHub Enterprise Cloud で、Copilot agent session データのストリーミングが使えるようになりました。Cloud agents、CLI、VS Code、Visual Studio、JetBrains/Eclipse 系 IDE まで対象です。REST API でも直近 48 時間分を取得できます。

### ユーザーにとって良いこと
エージェントのプロンプト、応答、tool call を横断して可視化できます。SIEM や監査基盤へ流せるため、AI 利用の統制と追跡がしやすくなります。

### アクションプラン
- AI Controls の Copilot サブページで `Copilot Usage Records Streaming` と `Copilot Usage Records API` を有効化してください。
- 監査ログのストリーミング先を SIEM または event collector に設定してください。
- 必要に応じて `GET /enterprises/{enterprise}/copilot/usage-records` を使う取得処理を追加してください。

- [Copilot agent session streaming is now in public preview](https://github.blog/changelog/2026-07-02-copilot-agent-session-streaming-is-now-in-public-preview)

## Cost centers now support AI credit pools

**URL:** https://github.blog/changelog/2026-07-02-cost-centers-now-support-included-usage-caps

### 要約
Cost center ごとに、enterprise の月間 included AI credits の利用上限を設定できるようになりました。REST API で利用可能で、UI 対応は今後予定されています。included usage と metered spend を分けて制御できます。

### ユーザーにとって良いこと
コスト配賦の境界を保ちながら、ある cost center が他の部署分の included credits を使い切る事態を防げます。予算管理と利用上限を分けて運用できるため、より細かい統制が可能です。

### アクションプラン
- REST API から cost center に AI credit pool を設定してください。
- 既存の cost center budget と併用し、included usage と metered spend の両方を管理してください。
- ⚠️ UI での管理はまだ未提供のため、自動化前提で運用設計してください。

## Issue fields are now generally available

**URL:** https://github.blog/changelog/2026-07-02-issue-fields-are-now-generally-available

### 要約
Issue fields が一般提供になりました。優先度、工数、日付などの構造化メタデータを issue に持たせられ、一覧・public projects・MCP server からも扱えます。併せて issue / PR の edit history は 100 件上限に変更されました。

### ユーザーにとって良いこと
issue 管理の一貫性と検索性が上がり、一覧から必要な情報を素早く把握できます。AI ツール経由でも field を読み書きできるため、運用の自動化もしやすくなります。

### アクションプラン
- Organization Settings > Planning > Issue fields で default fields を確認し、必要な field を追加してください。
- public projects で見せる field の可視性を見直してください。
- ⚠️ edit history は 100 件までに制限されるため、長期監査用途の保持要件がある場合は別保存を検討してください。

## Secret scanning public monitoring for enterprises

**URL:** https://github.blog/changelog/2026-07-01-secret-scanning-public-monitoring-for-enterprises

### 要約
Enterprise 向け Secret Protection で、github.com 上の公開領域をリアルタイム監視する public monitoring が public preview になりました。公開 issue、PR コメント、public repo の git content などに漏れた secret を、enterprise に帰属させて検出できます。

### ユーザーにとって良いこと
自社管理外の public surface で漏えいした secret も早く見つけて revoke しやすくなります。personal fork や public issue への貼り付けのような見落としを補えます。

### アクションプラン
- Security tab から public monitoring を有効化してください。
- verified domains と enterprise member ベースの attribution 条件を確認してください。
- 検出後の revoke / rotation 手順を運用に組み込み、対応 SLA を定義してください。

- [Secret scanning public monitoring for enterprises](https://github.blog/changelog/2026-07-01-secret-scanning-public-monitoring-for-enterprises)
