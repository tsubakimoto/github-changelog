## Manage GitHub Copilot app access with a dedicated policy

**URL:** https://github.blog/changelog/2026-07-27-manage-github-copilot-app-access-with-a-dedicated-policy

### 要約
GitHub Copilot app に専用のアクセス ポリシーが追加され、Enterprise / Organization 単位で個別に有効・無効を制御できるようになりました。これまで Copilot CLI の有効化に依存していたため、クライアントごとの管理ができませんでしたが、今回から app と CLI を分けて扱えます。

### ユーザーにとって良いこと
組織ごとに Copilot app の採用可否を柔軟に決められるため、必要なチームだけ段階的に展開できます。Enterprise 管理下でも既存のレビュー、チェック、監査の仕組みを保ったまま利用範囲を調整できます。

### アクションプラン
- Enterprise または Organization の **AI Controls > Copilot Clients** で、Copilot app ポリシーを確認してください。
- 展開方針に応じて `Enabled everywhere` / `Disabled everywhere` / `Let organizations decide` を選択してください。
- 既存の Copilot CLI ポリシーとは独立して管理されるため、必要なら管理方針と周知文を更新してください。

## Enterprise managed settings in the GitHub Copilot app and Copilot cloud agent

**URL:** https://github.blog/changelog/2026-07-27-enterprise-managed-settings-now-apply-to-the-github-copilot-app

### 要約
GitHub Copilot app と Copilot cloud agent が enterprise managed settings の対象になりました。`managed-settings.json` で定義したプラグイン、マーケットプレイス、承認プロンプトの制御などが、Copilot app / CLI / VS Code / cloud agent に横断して適用されます。

### ユーザーにとって良いこと
クライアントごとにガードレールが分かれる穴を減らし、同じポリシーを複数の Copilot 体験に一貫して適用できます。新しい app や cloud agent を導入しても、既存の管理設定をそのまま活用しやすくなります。

### アクションプラン
- すでに `managed-settings.json` を運用している場合は、Copilot app と cloud agent が対象クライアントに含まれているか確認してください。
- 未導入なら Enterprise の `.github-private` リポジトリに `copilot/managed-settings.json` を作成し、必要なポリシーを追加して push してください。
- 反映は再起動や再サインイン後、またはおおむね 1 時間以内に行われるため、展開時はその遅延を見込んでください。
