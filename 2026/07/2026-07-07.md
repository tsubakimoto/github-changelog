## Per-user budgets for cost centers in the billing UI

**URL:** https://github.blog/changelog/2026-07-07-per-user-budgets-for-cost-centers-in-the-billing-ui

### 要約
GitHub Enterprise Cloud の billing UI から、cost center に対するユーザー単位の予算を直接設定できるようになりました。メンバーの追加・変更に応じて予算の適用が自動で追従するため、REST API に頼らずに運用できます。

### ユーザーにとって良いこと
予算設定の手作業が減り、チーム編成の変化があってもコスト管理を維持しやすくなります。AI 利用の上限管理を UI 上で完結できるので、管理者の運用負荷も下がります。

### アクションプラン
- GitHub Enterprise Cloud で cost center を使っている管理者は、billing UI で per-user budget を設定してください。これは **UI で追加された運用機能** です。
- 既存の REST API ベースの設定がある場合は、UI 管理へ寄せるか、両者の役割分担を整理してください。
- cost center のメンバー変更時に予算が自動追従する前提を、財務・管理担当へ共有してください。

## Secret scanning extended metadata and multipart validation

**URL:** https://github.blog/changelog/2026-07-07-secret-scanning-extended-metadata-and-multipart-validation

### 要約
Secret scanning が、検出した secret の所有者や作成日・期限などの補足メタデータをより広く表示するようになりました。さらに、複数要素を組み合わせて判定する multipart validation も拡張され、アラートの精度と文脈が改善されています。

### ユーザーにとって良いこと
漏えいした secret の影響範囲と対応優先度を素早く判断しやすくなります。アラート一覧、詳細、webhook、API まで情報が揃うため、トリアージや自動処理にも使いやすくなります。

### アクションプラン
- セキュリティ運用チームは、アラート一覧・詳細・webhook・REST API の新しいメタデータ項目を取り込むよう、トリアージ手順を更新してください。
- 自動化や SIEM 連携がある場合は、追加フィールドの受け取りと保存を確認してください。これは **既存機能の強化** です。
- multipart validation の対象拡大を前提に、検知結果の解釈ルールを見直してください。

## Restrict who can dismiss reviews in rulesets

**URL:** https://github.blog/changelog/2026-07-07-restrict-who-can-dismiss-reviews-in-rulesets

### 要約
Repository rulesets で、プルリクエストレビューを dismiss できるユーザー・チーム・アプリを細かく制限できるようになりました。UI だけでなく REST API と GraphQL からも設定できます。

### ユーザーにとって良いこと
レビュー承認の解除権限を限定できるため、保護ルールをより厳密に運用できます。誤って承認が外されるリスクを減らし、マージ前の統制を強められます。

### アクションプラン
- 重要なリポジトリの ruleset で `Require a pull request before merging` にこの制限を追加してください。これは **ルールセットで明示的に設定する管理項目** です。
- どのユーザー・チーム・アプリに dismiss 権限を持たせるかを事前に決め、開発責任者へ周知してください。
- API で ruleset を管理している場合は、UI での設定と同等になるよう更新してください。

### リファレンス
- [Restrict who can dismiss reviews in rulesets](https://github.blog/changelog/2026-07-07-restrict-who-can-dismiss-reviews-in-rulesets)

## GitHub Copilot app available to all

**URL:** https://github.blog/changelog/2026-07-07-github-copilot-app-available-to-all

### 要約
GitHub Copilot app がすべての Copilot プランで利用可能になりました。macOS、Windows、Linux に対応し、Copilot Free や GitHub Education でも使えます。さらに、Copilot plan がなくても BYOK でセッションを開始できます。

### ユーザーにとって良いこと
より多くのユーザーがデスクトップから agent-driven development を始めやすくなります。プランに応じて導入障壁が下がり、組織外でも試しやすくなります。

### アクションプラン
- 利用者は GitHub Copilot app をインストールし、既存の Copilot 利用環境と合わせて試してください。
- GitHub Copilot Business / Enterprise の管理者は、アプリ利用の前提として Copilot CLI を policy settings で有効化してください。これは **管理者設定が必要** です。
- Copilot プランがない利用者向けに BYOK を使うかどうか、チームの運用方針を決めてください。

### リファレンス
- [GitHub Copilot app available to all](https://github.blog/changelog/2026-07-07-github-copilot-app-available-to-all)

## Copilot Billing Preview app will be retired on August 3

**URL:** https://github.blog/changelog/2026-07-07-copilot-billing-preview-app-will-be-retired-on-august-3

### 要約
Copilot Billing Preview app は 2026-08-03 に終了します。以後は GitHub の billing settings にある AI usage ページ、予算設定、usage reports、billing API を使って支出を確認・管理します。

### ユーザーにとって良いこと
請求と利用状況の確認先が GitHub 標準の画面に統一され、より正確で包括的な情報を見られます。user-level budgets や cost centers など、アプリより新しい管理機能も使えます。

### アクションプラン
- ⚠️ 2026-08-03 までに、Copilot Billing Preview app 依存の運用を billing settings の AI usage ページへ移行してください。
- 支出確認やレポート取得をアプリに依存している場合は、usage reports と billing API へ切り替えてください。
- 既存のダッシュボードや手順書にアプリ名が残っていないか確認し、参照先を更新してください。

### リファレンス
- [Copilot Billing Preview app will be retired on August 3](https://github.blog/changelog/2026-07-07-copilot-billing-preview-app-will-be-retired-on-august-3)
