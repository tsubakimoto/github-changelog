## GitHub Copilot app usage metrics now expand across report rollups

**URL:** https://github.blog/changelog/2026-07-28-github-copilot-app-usage-metrics-now-expand-across-report-rollups

### 要約
Copilot app の利用状況が、enterprise-user / organization-user レポートや各種 rollup にも反映されるようになりました。ユーザー単位の利用、モデル別・言語別の内訳、DAU への反映まで含めて、Copilot app の活動を既存の指標体系で追えるようになっています。

### ユーザーにとって良いこと
Copilot app を「使われているか」だけでなく、「誰が」「どの機能で」使っているかまで把握しやすくなります。IDE や chat と同じ指標で比較できるため、導入効果の可視化や利用促進の判断がしやすくなります。

### アクションプラン
- Copilot usage metrics policy が有効か確認してください。
- 既存のダッシュボードや集計処理で `copilot_app` の新しい内訳を取り込み、IDE 系メトリクスと並べて比較できるようにしてください。
- enterprise-user / organization-user レポートを使って、Copilot app の利用者と利用量を定期確認してください。

## npm publish-time malware scanning and dual-use metadata

**URL:** https://github.blog/changelog/2026-07-28-npm-publish-time-malware-scanning-and-dual-use-metadata

### 要約
npm は公開時に自動マルウェアスキャンを行うようになり、公開直後に即インストール可能とは限らなくなりました。あわせて、dual-use な内容を持つパッケージ向けに `contentPolicy` と `DISCLOSURE` ファイルの新しい申告要件が導入されます。

### ユーザーにとって良いこと
公開前スキャンにより、悪意あるパッケージが流通する前に止まりやすくなります。dual-use パッケージは意図と用途を明示できるため、正当な公開を維持しながら審査精度も上げられます。

### アクションプラン
- 公開直後にパッケージが見える前提の自動化があれば、数分の遅延を許容するように更新してください。
- dual-use に該当するパッケージは `package.json` の `contentPolicy` と root の `DISCLOSURE` ファイルを追加してください。
- dual-use パッケージの公開経路は、trusted publishing か 2FA 強制の方法に統一してください。

## Dependabot alerts on malicious packages across more ecosystems

**URL:** https://github.blog/changelog/2026-07-28-dependabot-alerts-on-malicious-packages-across-more-ecosystems

### 要約
GitHub Advisory Database が OpenSSF malicious-packages の情報を取り込み、Dependabot の malware alerts が npm 以外の ecosystem にも広がりました。`type:malware` で確認でき、既存の有効化済み環境では追加設定なしで恩恵を受けられます。

### ユーザーにとって良いこと
依存関係のマルウェア検知範囲が広がり、より多くの ecosystem で早期に危険なパッケージを見つけやすくなります。既存の Dependabot 運用を大きく変えずに、検知能力だけを強化できます。

### アクションプラン
- organization または repository の Settings → Code security → Dependabot で Malware alerts を有効化してください。
- 既に有効な場合でも、`type:malware` のアラートを定期確認する運用を追加してください。
- 依存更新のレビュー手順に、悪性パッケージ検知時の差し戻しと調査フローを組み込んでください。

### リファレンス
- [Dependabot alerts on malicious packages across more ecosystems](https://github.blog/changelog/2026-07-28-dependabot-alerts-on-malicious-packages-across-more-ecosystems)

## GitHub Actions holds potentially malicious workflows for approval

**URL:** https://github.blog/changelog/2026-07-28-github-actions-holds-potentially-malicious-workflows-for-approval

### 要約
public repository で危険と判断された GitHub Actions workflow run は、実行前に write 権限のある collaborator の承認を要求されるようになりました。これは GitHub 側で自動適用される保護で、追加設定は不要です。

### ユーザーにとって良いこと
侵害された認証情報を使った workflow 攻撃に対して、公開リポジトリの CI/CD 資格情報が守られやすくなります。怪しい run を人の目で止められるため、被害拡大を防ぎやすくなります。

### アクションプラン
- public repository の workflow 所有者は、承認待ちになる可能性があることをチームに周知してください。
- write 権限のある reviewer が不審な変更を素早く判断できるよう、承認基準を明文化してください。
- この保護は github.com の public repository のみ対象なので、Enterprise Server 利用時は別途対策を維持してください。

## GitHub Copilot for JetBrains adds improved OpenTelemetry configuration and model management

**URL:** https://github.blog/changelog/2026-07-27-github-copilot-for-jetbrains-adds-improvved-opentelemetry-configuration-and-model-management

### 要約
GitHub Copilot for JetBrains に、OpenTelemetry 設定、モデル管理、MCP servers と custom agents の対応強化、さらに CLI セッション機能の拡充が入りました。チャットや model picker の UX、診断、パス処理も改善されています。

### ユーザーにとって良いこと
IDE 内での可観測性、コスト制御、モデル統制がしやすくなります。Copilot CLI や JetBrains をまたぐ体験も少しずつ揃い、チームでの運用と個人利用の両方で扱いやすくなります。

### アクションプラン
- JetBrains 利用チームは、`Settings > Tools > GitHub Copilot > Chat` で OpenTelemetry export を必要に応じて設定してください。
- BYOK / custom endpoint を使う場合は、token 上限とモデルの有効・無効を見直してください。
- Claude agent flows で MCP servers や custom agents を使うなら、共有設定とリポジトリ固有設定の両方を確認してください。
