## Copilot cloud agent for Linear is now generally available

**URL:** https://github.blog/changelog/2026-07-23-copilot-cloud-agent-for-linear-is-now-generally-available

### 要約
Linear の issue を Copilot cloud agent に割り当てられるようになり、非同期で下書き PR の作成まで進められるようになりました。実行は GitHub Actions ベースの一時環境で行われ、進捗は Linear のタイムラインに返り、完了時にレビュー依頼も送られます。

### ユーザーにとって良いこと
Linear 上の作業を GitHub 側の実装フローに自然につなげられるため、仕様→実装→レビューの往復が短くなります。チームごとの運用に合わせてモデル、カスタムエージェント、ブランチ設定まで調整できます。

### アクションプラン
- GitHub Marketplace から GitHub Copilot for Linear アプリをインストールしてください。
- GitHub では organization owner、Linear では workspace admin 権限があることを確認してください。
- チーム運用に合わせて、モデル選択・カスタム agent・base branch / working branch・コメントでの指示追加を設定してください。

- [Copilot cloud agent for Linear is now generally available](https://github.blog/changelog/2026-07-23-copilot-cloud-agent-for-linear-is-now-generally-available)

## GitHub MCP Server supports the next MCP specification

**URL:** https://github.blog/changelog/2026-07-23-github-mcp-server-supports-the-next-mcp-specification

### 要約
GitHub MCP Server が、7 月 28 日に stateless 化される次期 MCP 仕様に先行対応しました。Redis セッションの削除、リクエスト payload の deep packet inspection 廃止、elicitation 実装の更新により、スケール性と互換性が改善されています。

### ユーザーにとって良いこと
MCP サーバーの運用が軽くなり、接続や拡張の扱いがシンプルになります。公式 SDK との互換性を保ったまま、新しい仕様や conformance test を使って実装を検証しやすくなります。

### アクションプラン
- GitHub MCP Server を利用している場合は、最新仕様対応版へ更新してください。
- 独自 MCP クライアント / サーバーを運用している場合は、stateless 前提と extension 対応を確認してください。
- 新しい仕様での互換性確認に conformance test を組み込み、SDK や実装差分を早めに検出してください。

### リファレンス
- [GitHub MCP Server supports the next MCP specification](https://github.blog/changelog/2026-07-23-github-mcp-server-supports-the-next-mcp-specification)

## GitHub Mobile: Fix failing Actions checks with Copilot cloud agent

**URL:** https://github.blog/changelog/2026-07-23-github-mobile-fix-failing-actions-checks-with-copilot-cloud-agent

### 要約
GitHub Mobile から、失敗した GitHub Actions check を Copilot coding agent に直接修正させられるようになりました。Failed check 画面の「Fix with Copilot」から開始でき、Copilot は既存 PR の上に新しい PR を作って修正案を出します。

### ユーザーにとって良いこと
外出先でも CI 失敗への初動をすばやく取れるため、PR の停滞を減らせます。修正は自動で提案され、最後は人間がレビューして判断できるので、モバイルでも安心して使えます。

### アクションプラン
- GitHub Mobile を最新の production build に更新してください（iOS / Android）。
- Actions check 失敗時は、failed check から「Fix with Copilot」を使って修正フローを開始してください。
- 生成された PR を確認し、必要に応じて追加の checks を実行してからマージしてください。

## Multi-select fields for Projects and Issues in public preview

**URL:** https://github.blog/changelog/2026-07-23-multi-select-fields-for-projects-and-issues-in-public-preview

### 要約
Projects と Issue fields に、1 つの項目へ複数の値を持てる multi-select field が追加されました。チーム、モジュール、カテゴリなどを 1 つのフィールドで同時に扱え、sidebar から複数値の設定や view での絞り込みができます。

### ユーザーにとって良いこと
「どれか 1 つ」ではなく「関連するものを全部」表現できるため、プロジェクトの分類と検索精度が上がります。単一選択フィールドの運用で無理に分割していたタグ付けを減らせます。

### アクションプラン
- 必要な Projects / Issue fields を multi-select に変更するか、新規作成してください。
- 保存済みビューやフィルターが単一選択前提になっていないか確認してください。
- 運用ルールや入力ガイドを更新し、どの値を複数選択にするかをチームでそろえてください。

### リファレンス
- [Multi-select fields for Projects and Issues in public preview](https://github.blog/changelog/2026-07-23-multi-select-fields-for-projects-and-issues-in-public-preview)

## Agent automation controls in GitHub Issues in public preview

**URL:** https://github.blog/changelog/2026-07-23-agent-automation-controls-in-github-issues-in-public-preview

### 要約
GitHub Issues の agent automation に、approvals・confidence・rationale が追加されました。低/中 confidence の変更はレビュー待ちにでき、各アクションの理由も確認できるため、label、field、type、close、assignee の変更をより細かく制御できます。

### ユーザーにとって良いこと
自動化を止めるのではなく、信頼度に応じて段階的に適用できるため、運用のスピードと安全性を両立しやすくなります。なぜその変更が提案されたのかも見えるので、レビュー判断がしやすくなります。

### アクションプラン
- GitHub Agentic Workflows を使っている場合は、issue intent support を追加するようワークフローを更新してください。
- 必要に応じて `issue-intents: true` を設定し、明示的に対象 safe output を有効化してください。不要なら `false` で明示的にオプトアウトできます。
- Repository admin は automation level を見直し、confidence threshold をチーム方針に合わせて調整してください。

### リファレンス
- [Agent automation controls in GitHub Issues in public preview](https://github.blog/changelog/2026-07-23-agent-automation-controls-in-github-issues-in-public-preview)
