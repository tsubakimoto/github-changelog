## CodeQL 2.26.0 adds Kotlin 2.4.0 support and AI prompt injection detection

**URL:** https://github.blog/changelog/2026-07-10-codeql-2-26-0-adds-kotlin-2-4-0-support-and-ai-prompt-injection-detection

### 要約
CodeQL 2.26.0 で Kotlin 2.4.0 対応が追加され、JavaScript / TypeScript では system prompt injection を検出する新しいクエリが入ります。あわせて Go、Python、Swift、GitHub Actions でも精度改善や誤検知低減が行われました。コードスキャンの検出範囲と品質が広がる更新です。

### ユーザーにとって良いこと
新しい言語版や AI 関連の攻撃パターンをより早く検出しやすくなります。既存のルールを大きく変えずに、実運用で役立つアラートの質が改善されます。

### アクションプラン
- CodeQL 依存のコードスキャン運用では、`js/system-prompt-injection` と `javascript/ssrf-ipv6-transition-incomplete-guard` を確認し、対象リポジトリのセキュリティレビュー項目に追加してください。
- GHES を使っている場合は、**旧バージョンでは手動アップグレードが必要** なので、CodeQL の更新計画を確認してください。
- 既存のアラート調整では、Go / Python / Swift / Actions の誤検知変化を見てルールや通知を再評価してください。

### リファレンス
- [CodeQL 2.26.0 adds Kotlin 2.4.0 support and AI prompt injection detection](https://github.blog/changelog/2026-07-10-codeql-2-26-0-adds-kotlin-2-4-0-support-and-ai-prompt-injection-detection)

## Clearer names for secret scanning detector types

**URL:** https://github.blog/changelog/2026-07-10-clearer-names-for-secret-scanning-detector-types

### 要約
Secret scanning の detector type 名称が、実際の検出方法に合わせてより分かりやすい名前に変わります。検出挙動そのものは変わらず、Webhook、audit log、REST API にも変更はありません。ドキュメントと用語だけが整理される更新です。

### ユーザーにとって良いこと
「何で検出されたのか」が読みやすくなり、運用者や開発者が結果を理解しやすくなります。名称の整理により、ドキュメント検索や社内説明も簡単になります。

### アクションプラン
- 社内ドキュメント、運用手順、検知一覧の表示名を新しい用語に合わせて更新してください。これは **名称変更のみで、検出ロジックの変更ではありません**。
- Webhook、audit log、REST API の受信側コードは変更不要ですが、表示ラベルをハードコードしている場合は置き換えてください。
- 旧名称のまま説明しているヘルプページや FAQ があれば、用語統一のために更新してください。

### リファレンス
- [Clearer names for secret scanning detector types](https://github.blog/changelog/2026-07-10-clearer-names-for-secret-scanning-detector-types)

## Per-user states for multi-user budgets in the REST API

**URL:** https://github.blog/changelog/2026-07-10-per-user-states-for-multi-user-budgets-in-the-rest-api

### 要約
REST API で multi-user budget に対する各ユーザーの消費状況を 1 つのエンドポイントから取得できるようになりました。ページング、しきい値でのフィルタ、ユーザー単位の絞り込みや並び替え、個別上限の上書き確認が可能です。大規模 enterprise での予算監視がかなり扱いやすくなります。

### ユーザーにとって良いこと
ユーザーごとに API を何度も叩かなくてよくなり、消費率の高い人をすばやく見つけられます。予算の見回りやアラートの自動化が、より少ないリクエストで実装できます。

### アクションプラン
- Enterprise の請求・予算監視スクリプトを、ユーザーごとの個別呼び出しからこの新しい一覧 API に置き換えてください。
- 消費率のしきい値でフィルタして、上限に近いユーザーだけを定期監視するようにしてください。これは **Enterprise owners / billing managers 向けの機能** です。
- 既存の集計処理でページング前提の実装がある場合は、ソート条件と個別上限 override の扱いを見直してください。

- [Per-user states for multi-user budgets in the REST API](https://github.blog/changelog/2026-07-10-per-user-states-for-multi-user-budgets-in-the-rest-api)

## GitHub Mobile: Improved filters and sorting for Copilot sessions

**URL:** https://github.blog/changelog/2026-07-10-github-mobile-improved-filters-and-sorting-for-copilot-sessions

### 要約
GitHub Mobile で Copilot sessions の絞り込みと並び替えが強化されました。Active、Status、Repository、Type、Agent でセッションを探しやすくなり、最近のものや要対応のものをすぐ見つけられます。iOS と Android の最新 production build で利用できます。

### ユーザーにとって良いこと
モバイルからでも必要な Copilot session を素早く見つけられ、対応漏れを減らせます。セッション数が増えても、状態別に整理して追いやすくなります。

### アクションプラン
- GitHub Mobile を使うメンバーへ、最新版へ更新して新しいフィルタと sort を使うよう案内してください。これは **モバイルアプリ側で有効になる機能** です。
- セッション管理の運用メモに、Active / Status / Repository / Type / Agent の絞り込み条件を追記してください。
- サポート担当やレビュー担当がいる場合は、needs-attention の見つけ方を共有してください。
