## 重要アップデート

- **Breaking Change / Improvement / GA** [Customize code scanning default setup at scale](https://github.blog/changelog/2026-08-04-customize-code-scanning-default-setup-at-scale): code scanning の default setup を `github-codeql-config-file` で組織横断的にカスタマイズ可能に。既定設定の利便性を保ちながら、クエリ追加や除外パス、threat model を制御できる。

- **Improvement** [Code coverage automatic enablement in Code Quality settings](https://github.blog/changelog/2026-08-04-code-coverage-automatic-enablement-in-code-quality-settings): Code Quality 設定から coverage workflow を AI 生成できる public preview。PR を自動作成してレビュー後に導入できる。

### 2026-08-05 | <a href="https://github.blog/changelog/2026-08-04-customize-code-scanning-default-setup-at-scale">Customize code scanning default setup at scale</a>

<span style="display:inline-block;padding:2px 8px;border-radius:999px;background:#7d2e1e;color:#ffe9e4;font-size:12px;">Breaking Change</span>
<span style="display:inline-block;padding:2px 8px;border-radius:999px;background:#244b7a;color:#e7f0ff;font-size:12px;">Improvement</span>
<span style="display:inline-block;padding:2px 8px;border-radius:999px;background:#8a5a12;color:#fff2d9;font-size:12px;">GA</span>

`github-codeql-config-file` repository property を使って、code scanning default setup に独自の CodeQL 設定を適用できます。クエリ追加や除外パス設定を一元管理でき、リポジトリごとの workflow file を増やさずに運用しやすくなります。

### ユーザーにとって良いこと

大規模な組織でも、標準設定を保ちながら必要なスキャン調整を配れます。

### アクションプラン

- default setup を使っている repository では、`github-codeql-config-file` の導入可否を確認してください。
- 組織共通の CodeQL 設定を集中管理する場合は、参照先ファイルの配置を決めてください。
- private repository を参照するなら、Git Source private registry の設定も確認してください。

### リファレンス
- [Customize code scanning default setup at scale](https://github.blog/changelog/2026-08-04-customize-code-scanning-default-setup-at-scale)

### 2026-08-05 | <a href="https://github.blog/changelog/2026-08-04-codeql-2-26-2-adds-swift-6-3-3-and-kotlin-2-4-10-support">CodeQL 2.26.2 adds Swift 6.3.3 and Kotlin 2.4.10 support</a>

<span style="display:inline-block;padding:2px 8px;border-radius:999px;background:#244b7a;color:#e7f0ff;font-size:12px;">Improvement</span>
<span style="display:inline-block;padding:2px 8px;border-radius:999px;background:#7d2e1e;color:#ffe9e4;font-size:12px;">Breaking Change</span>

CodeQL 2.26.2 が追加され、Swift 6.3.3 と Kotlin 2.4.10 に対応しました。あわせて path injection、URL redirection、GitHub Actions 関連クエリの精度が改善され、`[[` スタイルの legacy link 記法は使えなくなります。

### ユーザーにとって良いこと

新しい言語バージョンの解析精度が上がり、誤検出や見逃しが減ります。

### アクションプラン

- Swift / Kotlin を使う code scanning 環境では CodeQL 更新を確認してください。
- alert メッセージ内の `[[` 形式の legacy link を使っているクエリは `$@` へ移行してください。

### リファレンス
- [CodeQL 2.26.2 adds Swift 6.3.3 and Kotlin 2.4.10 support](https://github.blog/changelog/2026-08-04-codeql-2-26-2-adds-swift-6-3-3-and-kotlin-2-4-10-support)

### 2026-08-05 | <a href="https://github.blog/changelog/2026-08-04-upcoming-deprecation-of-github-spark-on-github-com">Upcoming deprecation of GitHub Spark on github.com</a>

<span style="display:inline-block;padding:2px 8px;border-radius:999px;background:#8a5a12;color:#fff2d9;font-size:12px;">Deprecated</span>
<span style="display:inline-block;padding:2px 8px;border-radius:999px;background:#7d2e1e;color:#ffe9e4;font-size:12px;">Retirement</span>

GitHub Spark on github.com は新規ユーザー受付と新規アプリ作成を停止しました。既存ユーザーは 2026-08-31 までエクスポート可能で、`llm()` を使うアプリは別の inference provider へ置き換える必要があります。

### ユーザーにとって良いこと

既存アプリの扱いと移行期限が明確になりました。

### アクションプラン

- 既存の Spark アプリがある場合は 2026-08-31 までに repository へ書き出してください。
- `llm()` 利用の有無を確認し、必要なら代替 inference provider に差し替えてください。

### リファレンス
- [Upcoming deprecation of GitHub Spark on github.com](https://github.blog/changelog/2026-08-04-upcoming-deprecation-of-github-spark-on-github-com)
