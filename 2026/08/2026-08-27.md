## Better label management on issues is generally available

**URL:** https://github.blog/changelog/2026-08-27-label-archiving-is-generally-available

### 要約
Issue のラベル管理が改善され、最近使ったラベルの候補表示と、未使用ラベルのアーカイブができるようになりました。既存の issue に付いている履歴は保持したまま、ラベル一覧を整理できます。

### ユーザーにとって良いこと
ラベル数が増えたリポジトリでも、目的のラベルを見つけやすくなります。頻繁に使うラベルに絞り込めるため、ラベル付けの手間と探す時間を減らせます。

### アクションプラン
- ラベル数が多いリポジトリで、長期間使っていないラベルをアーカイブしてください。
- 運用上よく使うラベルが候補に出るか、実際の issue 作成フローで確認してください。
- アーカイブしても履歴は残るため、削除ではなく整理手段として使う方針をチーム内で共有してください。

### リファレンス
- [Better label management on issues is generally available](https://github.blog/changelog/2026-08-27-label-archiving-is-generally-available)

## Copilot code review: Resolution reasons and expanded capabilities

**URL:** https://github.blog/changelog/2026-08-27-copilot-code-review-resolution-reasons-and-expanded-capabilities

### 要約
Copilot code review が、bot 作成の pull request と非常に大きな pull request も扱えるようになりました。あわせて、レビューコメントを解決する際に「Addressed」「Won't fix」「Incorrect」の理由を選べるようになっています。

### ユーザーにとって良いこと
自動生成や大規模な変更でも Copilot code review の対象を広げられるため、レビューの抜けを減らせます。解決理由の記録でフィードバックが蓄積され、レビュー品質の改善にもつながります。

### アクションプラン
- bot や Copilot cloud agent が作成する PR を自動レビュー対象にしている場合は、Copilot ライセンス不要でレビューできるポリシー設定を確認してください。
- レビュアーに対して、コメントを解決する際は適切な理由を選ぶ運用を周知してください。
- 大規模 PR でも Copilot code review を使う前提で、既存のサイズ制限を前提にした手順が残っていないか見直してください。

### リファレンス
- [Copilot code review: Resolution reasons and expanded capabilities](https://github.blog/changelog/2026-08-27-copilot-code-review-resolution-reasons-and-expanded-capabilities)

## Actions retention will cover checks, workflow runs, and statuses

**URL:** https://github.blog/changelog/2026-08-27-actions-retention-will-cover-checks-workflow-runs-and-statuses

### 要約
2026-10-01 から、checks / workflow runs / statuses が Actions の保持設定に従うようになります。これまでは 400 日超保持されていたデータも、アーティファクトやログと同じ保持期間で自動削除されます。

### ユーザーにとって良いこと
保持ポリシーが一本化されるため、運用ルールが分かりやすくなります。不要な古いデータが減ることで、Actions のストレージ負荷や管理コストの見直しにもつながります。

### アクションプラン
- 2026-10-01 までに、リポジトリ / 組織 / Enterprise の Actions retention 設定を確認してください。
- 必要な履歴が 90 日を超える場合は、上限を踏まえて保持期間を延ばせるか検討してください。
- 古い checks / workflow runs / statuses を後から復元できないため、必要なものは事前にエクスポートまたはアーカイブしてください。

### リファレンス
- [Actions retention will cover checks, workflow runs, and statuses](https://github.blog/changelog/2026-08-27-actions-retention-will-cover-checks-workflow-runs-and-statuses)

## Close all open contributions authored by a blocked user

**URL:** https://github.blog/changelog/2026-08-27-close-all-open-contributions-authored-by-a-blocked-user

### 要約
ユーザーをブロックする際に、そのユーザーが作成した open な issues、discussions、pull requests をまとめて閉じられるようになりました。ブロックダイアログや設定画面から、該当コンテンツを一括で閉じる操作ができます。

### ユーザーにとって良いこと
モデレーション時の後処理が減り、不要な投稿を素早く整理できます。個人アカウントでも組織でも使えるため、コミュニティ運営の負担を下げられます。

### アクションプラン
- 既存のブロック運用で、投稿の整理を手作業で行っている場合はこのオプションを使うように切り替えてください。
- issue / PR コメントからブロックする運用でも同じ操作が出るため、モデレーション手順を更新してください。
- 組織管理者向けに、どのケースで「Close content authored by this user」を選ぶかを明文化してください。

### リファレンス
- [Close all open contributions authored by a blocked user](https://github.blog/changelog/2026-08-27-close-all-open-contributions-authored-by-a-blocked-user)

## Enterprise-managed settings now support autoUpdate for plugin marketplaces

**URL:** https://github.blog/changelog/2026-08-27-enterprise-managed-settings-now-support-autoupdate-for-plugin-marketplaces

### 要約
Enterprise managed settings で、個別の plugin marketplace に対して `autoUpdate: true` を設定できるようになりました。許可済みの marketplace から入ったプラグインを、対応クライアントが自動更新します。

### ユーザーにとって良いこと
承認済み marketplace のプラグイン更新を自動化できるため、手動メンテナンスの手間を減らせます。Copilot Business / Enterprise、Copilot CLI、Visual Studio Code で一貫した管理がしやすくなります。

### アクションプラン
- 管理している marketplace のうち、自動更新してよいものにだけ `autoUpdate: true` を設定してください。
- その marketplace が `strictKnownMarketplaces` の allowlist に含まれているか確認してください。
- 対応クライアントが Copilot app、Copilot CLI、VS Code のどれかを使っているか確認し、更新方針を合わせてください。

### リファレンス
- [Enterprise-managed settings now support autoUpdate for plugin marketplaces](https://github.blog/changelog/2026-08-27-enterprise-managed-settings-now-support-autoupdate-for-plugin-marketplaces)
