## Enterprise managed settings in GitHub Copilot for JetBrains

**URL:** https://github.blog/changelog/2026-08-18-enterprise-managed-settings-in-github-copilot-for-jetbrains

### 要約
GitHub Copilot for JetBrains に、企業向けの管理設定が追加されました。プラグイン許可、MCP サーバーの allowlist/denylist、OpenTelemetry 設定、権限モードを管理者が一元制御できます。

### ユーザーにとって良いこと
企業全体で Copilot の利用方針を統一でき、開発者ごとの設定差を減らせます。監査や運用ルールに合わせて、IDE 内の接続先やテレメトリ送信も管理しやすくなります。

### アクションプラン
- JetBrains 向け Copilot プラグインを最新版へ更新する。
- `enabledPlugins` / `extraKnownMarketplaces` / `strictKnownMarketplaces` を使って、許可するプラグイン配布元を整理する。
- `allowedMcpServers` と `deniedMcpServers` を設定し、接続可能な MCP サーバーを企業標準に合わせて制限する。
- `permissions.disableBypassPermissionsMode` の適用可否を確認し、Agent の権限モードを運用ポリシーに合わせる。

## Credential revocation and deauthorization by token type

**URL:** https://github.blog/changelog/2026-08-18-credential-revocation-and-deauthorization-by-token-type

### 要約
資格情報の失効・取り消しを、トークン種別ごとに実行できるようになりました。従来はユーザーの全資格情報が一括対象でしたが、PAT、SSH key、OAuth app token、GitHub App user access token などを個別に止められます。

### ユーザーにとって良いこと
インシデント時に、信頼できる資格情報まで巻き込まずに被害範囲を絞れます。組織レベルでも同等の操作ができ、監査ログと通知で追跡もしやすくなります。

### アクションプラン
- 企業・組織のインシデント対応手順を、トークン種別単位の失効・取り消しに更新する。
- REST API と UI の両方で、enterprise / organization の credential revocation 手順を確認する。
- 監査ログで deauthorization / revocation の記録と通知フローを確認し、運用担当へ周知する。
- ⚠️ 既存の「全資格情報一括」手順に依存している場合は、トークン種別ごとの対応へ移行する。
