## GitHub Copilot weekly releases — August 3

**URL:** https://github.blog/changelog/2026-08-07-github-copilot-weekly-releases-august-3

Copilot のデスクトップアプリ、CLI、VS Code にまたがる週次更新です。セッションの再開や並列作業、コードレビュー、モデル表示など、作業の流れを切らさずに進める機能が強化されました。

## Enterprises can now install third-party GitHub Apps

**URL:** https://github.blog/changelog/2026-08-07-enterprises-can-now-install-third-party-github-apps

### 要約
Enterprise オーナーが、組織外で作成された public GitHub App を enterprise アカウントへ直接インストールできるようになりました。あわせて、enterprise 権限を持つ GitHub App を全ユーザー・全組織で作成できるようになっています。

### ユーザーにとって良いこと
サードパーティの統合を enterprise 単位で導入しやすくなり、管理系の自動化や可視化を広く展開できます。Enterprise 全体を対象にした連携を、より現実的に構築できます。

### アクションプラン
- enterprise 管理向けの連携を開発している場合は、enterprise 権限対応の GitHub App を検討してください。
- 既存アプリで enterprise 権限を使う場合は、cross-enterprise インストール可否の制約を確認してください。
- ⚠️ enterprise をまたぐインストールは、Enterprise organization installations 系の権限では不可です。

## Copilot impact dashboard adds a return on investment section

**URL:** https://github.blog/changelog/2026-08-07-copilot-impact-dashboard-adds-a-return-on-investment-section

### 要約
Copilot impact dashboard に「Potential return on investment」セクションが追加されました。Copilot 利用コストと pull request 産出を並べ、導入段階ごとの価値を比較できます。

### ユーザーにとって良いこと
Copilot の投資対効果を、感覚ではなく実データベースで説明しやすくなります。管理者は導入促進や予算説明、対象チームの優先順位付けをしやすくなります。

### アクションプラン
- Copilot 予算の説明資料に、impact dashboard の ROI 指標を追加してください。
- Copilot usage metrics policy を有効化し、enterprise/organization での可視化を確認してください。
- ⚠️ 表示されるコストは推定値であり、給与セレクターはモデリング入力です。実給与データとして扱わないでください。

## Copilot code review effort levels are generally available

**URL:** https://github.blog/changelog/2026-08-07-copilot-code-review-effort-levels-are-generally-available

### 要約
Copilot code review の Lite と Balanced が一般提供になりました。Pull request の複雑さに応じてレビュー深度を選べ、組織既定値も設定できます。

### ユーザーにとって良いこと
軽微な変更には速いレビュー、重要な変更には深いレビューを当てやすくなります。レビュー品質と所要時間のバランスを、チームごとに調整できます。

### アクションプラン
- 小さな修正やドキュメント更新には Lite、複雑な変更には Balanced を使い分けてください。
- 必要に応じて組織レベルの既定値を設定し、リポジトリへ継承させてください。
- ⚠️ Low / Medium は Lite / Balanced に名称変更されていますが、既存設定は自動で引き継がれます。

## Copilot usage metrics API adds agent app activity

**URL:** https://github.blog/changelog/2026-08-07-copilot-usage-metrics-api-adds-agent-app-activity

### 要約
Copilot usage metrics API が、サードパーティの agent app 活動を agent ごとに集計して返すようになりました。enterprise、organization、user 単位の 1 日・28 日レポートで利用できます。

### ユーザーにとって良いこと
どの agent が実際に使われているかを、単一のバケットではなく個別に把握できます。導入比較やライセンス判断、展開効果の追跡がしやすくなります。

### アクションプラン
- ダッシュボードや集計処理で `totals_by_3rd_party_agent` を取り込み、agent_id で集計してください。
- agent 名ではなく、変更に強い agent_id をキーにして保存してください。
- ⚠️ 既存フィールドの形は維持されます。データがない期間は新配列は返りません。

### リファレンス
- [Copilot usage metrics API adds agent app activity](https://github.blog/changelog/2026-08-07-copilot-usage-metrics-api-adds-agent-app-activity)

## Secret scanning coverage updates

**URL:** https://github.blog/changelog/2026-08-07-secret-scanning-coverage-updates

### 要約
Secret scanning の検出対象が拡大し、新しい partner、push protection の既定拡張、extended metadata 対応が追加されました。より多くの秘密情報を、漏洩前後の両面で検知しやすくなっています。

### ユーザーにとって良いこと
漏洩リスクを減らしつつ、検出後の調査も速くなります。アラートに所有者や有効期限などの文脈が出るため、修正判断がしやすくなります。

### アクションプラン
- secret scanning を有効にしているリポジトリでは、新しい検出対象が自動的に push protection に入る前提で運用してください。
- アラート対応手順に extended metadata の確認を組み込み、所有者特定を迅速化してください。
- ⚠️ public repository で検出された Lovable Labs secret は partner に転送されます。

## GitHub Code Quality no longer adds Copilot as a reviewer

**URL:** https://github.blog/changelog/2026-08-07-github-code-quality-no-longer-adds-copilot-as-a-reviewer

### 要約
GitHub Code Quality を有効化しても、Copilot review を自動追加する ruleset はもう作成されません。既存の自動設定も、GitHub が作成したものに限って無効化されています。

### ユーザーにとって良いこと
自動で reviewer が付くことを望まないチームの意図が尊重されます。必要な場合だけ、自分たちで Copilot review を明示的に有効化できます。

### アクションプラン
- Code Quality 導入済みのリポジトリでは、不要なら ruleset を削除してください。
- 自動 Copilot review を継続したい場合は、対象ブランチの ruleset を手動で設定してください。
- ⚠️ 既存の自動レビュー設定は、GitHub が作成した ruleset に限りオフになっています。

### リファレンス
- [GitHub Code Quality no longer adds Copilot as a reviewer](https://github.blog/changelog/2026-08-07-github-code-quality-no-longer-adds-copilot-as-a-reviewer)

## MCP allowlists in enterprise managed settings

**URL:** https://github.blog/changelog/2026-08-06-mcp-allowlists-in-enterprise-managed-settings

### 要約
Enterprise managed settings で、Copilot クライアントが実行できる MCP server を allowlist / denylist で制御できるようになりました。URL、コマンド、名前を使ってサーバーを識別できます。

### ユーザーにとって良いこと
企業全体で、信頼できる MCP server だけを許可しやすくなります。コンプライアンスや運用統制を保ちながら、Copilot の拡張性を活かせます。

### アクションプラン
- `.github-private/copilot/managed-settings.json` に allowedMcpServers もしくは deniedMcpServers を追加してください。
- enterprise 配下の各チームで、必要な MCP server がブロックされないか確認してください。
- ⚠️ ポリシーは fail closed です。設定不備があると許可されず、サーバーは実行されません。

### リファレンス
- [MCP allowlists in enterprise managed settings](https://github.blog/changelog/2026-08-06-mcp-allowlists-in-enterprise-managed-settings)
