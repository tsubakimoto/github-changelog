### 2026-08-03 | <a href="https://github.blog/changelog/2026-08-03-customize-the-reasoning-level-for-copilot-cloud-agent">Customize the reasoning level for Copilot cloud agent</a>

<span style="display:inline-block;padding:2px 8px;border-radius:999px;background:#244b7a;color:#e7f0ff;font-size:12px;">Improvement</span>

Copilot cloud agent に、タスクごとの推論レベル指定が追加されました。難しい問題では深く考えさせ、軽い処理ではトークン消費を抑える使い分けができます。対象は Copilot Pro / Pro+ / Business / Enterprise / Max など、cloud agent を含む有料プランです。

### ユーザーにとって良いこと

複雑な依頼の成功率を上げつつ、簡単な作業ではクレジット消費を抑えられます。

### アクションプラン

- cloud agent の実行時に、タスクの難易度に応じて推論レベルを選んでください。
- 複雑な調査やリファクタリングは高め、定型作業は低めで使い分けてください。
- 有料プランで cloud agent が有効かを確認してください。

### 2026-08-03 | <a href="https://github.blog/changelog/2026-08-03-enterprise-team-specialization-for-managed-settings">Enterprise team specialization for managed settings</a>

<span style="display:inline-block;padding:2px 8px;border-radius:999px;background:#244b7a;color:#e7f0ff;font-size:12px;">Improvement</span>

Copilot の managed settings を、エンタープライズ全体ではなくチーム単位で上書きできるようになりました。`overridable` を付けたキーだけがチーム設定で差し替え可能で、`team-mappings.json` で複数チームへ割り当てられます。運用統制を保ったまま、チームごとのワークフローに合わせた設定を配れます。

### ユーザーにとって良いこと

大規模組織でも、中央管理を崩さずにチームごとの最適化がしやすくなります。

### アクションプラン

- `copilot/managed-settings.json` のうち、チーム差分を許すキーを `overridable` に設定してください。
- チーム別設定ファイルを `copilot/teams/` に追加してください。
- `team-mappings.json` で各設定ファイルを対象チームへ割り当ててください。

### リファレンス
- [Enterprise team specialization for managed settings](https://github.blog/changelog/2026-08-03-enterprise-team-specialization-for-managed-settings)

### 2026-08-03 | <a href="https://github.blog/changelog/2026-08-03-trigger-copilot-automations-with-comments">Trigger Copilot automations with comments</a>

<span style="display:inline-block;padding:2px 8px;border-radius:999px;background:#244b7a;color:#e7f0ff;font-size:12px;">Improvement</span>

Issue コメントや PR コメントをトリガーにして、Copilot cloud agent の自動化を起動できるようになりました。コメント内容を条件に、ドキュメント生成、エラー調査、フォローアップ issue 作成などを自動化できます。既存の Copilot 利用者向けで、Business / Enterprise では管理者による cloud agent policy 有効化が必要です。

### ユーザーにとって良いこと

レビューやトリアージの流れの中で、手動作業を減らしやすくなります。

### アクションプラン

- repository の Agents タブから Automations を開き、コメント文字列で起動するルールを設定してください。
- 自動化対象を issue / PR のどちらにするか決めてください。
- Business / Enterprise では cloud agent policy を管理者が有効化してください。

### リファレンス
- [Trigger Copilot automations with comments](https://github.blog/changelog/2026-08-03-trigger-copilot-automations-with-comments)

### 2026-08-03 | <a href="https://github.blog/changelog/2026-08-03-triage-role-can-bypass-issue-creation-restrictions">Triage role can bypass issue creation restrictions</a>

<span style="display:inline-block;padding:2px 8px;border-radius:999px;background:#244b7a;color:#e7f0ff;font-size:12px;">Improvement</span>

issue 作成を collaborator のみに制限している repository でも、triage ロールのユーザーが issue を作成できるようになりました。これにより、書き込み権限は与えずに、トリアージ担当へ受付・整理の役割を持たせやすくなります。

### ユーザーにとって良いこと

権限設計を細かく保ちながら、運用担当の作業範囲を広げられます。

### アクションプラン

- issue 作成制限を使っている repository では、triage ロールの運用を見直してください。
- 受付担当に write 権限を与えたくない場合は、この変更を活用してください。

### 2026-08-03 | <a href="https://github.blog/changelog/2026-08-03-migrate-from-gitlab-to-github-with-github-enterprise-importer">Migrate from GitLab to GitHub with GitHub Enterprise Importer</a>

<span style="display:inline-block;padding:2px 8px;border-radius:999px;background:#7d2e1e;color:#ffe9e4;font-size:12px;">Breaking Change</span>
<span style="display:inline-block;padding:2px 8px;border-radius:999px;background:#244b7a;color:#e7f0ff;font-size:12px;">Improvement</span>
<span style="display:inline-block;padding:2px 8px;border-radius:999px;background:#8a5a12;color:#fff2d9;font-size:12px;">GA</span>

GitLab.com と GitLab Self-Managed から GitHub Enterprise Cloud への移行が GA になりました。`gh gl2gh` 拡張で単一リポジトリ移行も一括移行もでき、`--use-github-storage` で GitHub 管理ストレージを使うか、S3 / Azure Blob を使うこともできます。GitHub Enterprise Server への移行は対象外です。

### ユーザーにとって良いこと

GitLab からの移行を、手作業ではなく標準化された手順で進めやすくなります。

### アクションプラン

- GitLab から移行する場合は、`gh gl2gh` の利用手順を確認してください。
- 移行先が GitHub Enterprise Cloud かを確認してください。
- ⚠️ GitHub Enterprise Server は対象外なので、GEI の対応範囲を前提に計画してください。

### リファレンス
- [Migrate from GitLab to GitHub with GitHub Enterprise Importer](https://github.blog/changelog/2026-08-03-migrate-from-gitlab-to-github-with-github-enterprise-importer)
