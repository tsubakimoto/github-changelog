## Pinning saved views to the repository issues sidebar is generally available and more

**URL:** https://github.blog/changelog/2026-08-20-pin-projects-views-and-milestones-to-the-repository-sidebar

### 要約
Repository の Issues サイドバーに saved views をピン留めできるようになりました。よく使うビューへ、サイドバーを折りたたんだ状態でもすぐアクセスできます。

### ユーザーにとって良いこと
Issue の確認やトリアージが速くなり、作業導線が短くなります。加えて、反応アバターや一覧の密度調整、依存関係 API のスコープ反映など、日常運用の使い勝手も改善されています。

### アクションプラン
- Repository ごとに、頻繁に使う saved views を Issues サイドバーへピン留めする。
- Issue の依存関係 API を使う自動化がある場合は、トークンの granted scope で結果が絞られる前提に合わせて確認する。
- ⚠️ 既存の依存関係取得ロジックが全件取得前提なら、スコープ不足時の空結果を扱うように修正する。

### リファレンス
- [Pinning saved views to the repository issues sidebar is generally available and more](https://github.blog/changelog/2026-08-20-pin-projects-views-and-milestones-to-the-repository-sidebar)

## Windows 11 arm64 VS2026 image generally available

**URL:** https://github.blog/changelog/2026-08-20-windows-11-arm64-vs2026-image-generally-available

### 要約
GitHub-hosted runner で Windows 11 arm64 + Visual Studio 2026 イメージが一般提供されました。既定の windows-11-arm イメージも 2026-09 下旬に VS2026 へ段階的に移行します。

### ユーザーにとって良いこと
arm64 の Windows ビルドを新しい開発環境で試せます。事前に更新しておくと、既定イメージの切り替え時に CI が止まりにくくなります。

### アクションプラン
- arm64 のワークフローで `runs-on: windows-11-vs2026-arm` を指定して先行検証する。
- Visual Studio 2022 依存があるビルドは、VS2026 での互換性を確認する。
- ⚠️ 2026-09-21 以降の自動移行で壊れる可能性があるため、依存ビルドは早めに分岐テストする。

### リファレンス
- [Windows 11 arm64 VS2026 image generally available](https://github.blog/changelog/2026-08-20-windows-11-arm64-vs2026-image-generally-available)

## Code scanning adds a mitigated alert dismissal reason

**URL:** https://github.blog/changelog/2026-08-20-code-scanning-adds-a-mitigated-alert-dismissal-reason

### 要約
Code scanning の alert を、新しい dismissal reason `Mitigated` で閉じられるようになりました。アプリ自体には脆弱性が残っていても、WAF やネットワークポリシーなど外部対策でリスクを下げている場合に使えます。

### ユーザーにとって良いこと
「修正済み」ではなく「対策済み」として記録でき、リスク受容や例外管理の実態に合わせた運用がしやすくなります。監査や説明責任にも使いやすいです。

### アクションプラン
- 例外管理フローで、`Won't fix` の代わりに `Mitigated` を使う基準を定義する。
- 監査ログやレポートで dismissal reason の分類を更新する。
- ⚠️ 既存の自動処理が dismissal reason の列挙を固定している場合は、新値を追加する。

### リファレンス
- [Code scanning adds a mitigated alert dismissal reason](https://github.blog/changelog/2026-08-20-code-scanning-adds-a-mitigated-alert-dismissal-reason)

## Separate GitHub Actions path for GitHub Code Quality

**URL:** https://github.blog/changelog/2026-08-20-separate-github-actions-path-for-github-code-quality

### 要約
GitHub Code Quality の Actions 実行が、code scanning とは別の workflow path と actor を持つようになりました。実行履歴や usage レポートで、Code Quality と code scanning を区別しやすくなります。

### ユーザーにとって良いこと
利用状況や請求の集計が正確になり、Code Quality 導入の把握がしやすくなります。自動化やダッシュボードでも、分析対象を分けて扱えます。

### アクションプラン
- `dynamic/github-code-scanning/codeql` に依存する usage / billing 集計を `dynamic/github-code-quality/codeql` も含むよう更新する。
- workflow run のフィルタやスクリプトで `github-advanced-security` actor を前提にしている箇所を見直す。
- ⚠️ 既存レポートが Code Quality を取りこぼすため、集計ロジックの更新は必須。

### リファレンス
- [Separate GitHub Actions path for GitHub Code Quality](https://github.blog/changelog/2026-08-20-separate-github-actions-path-for-github-code-quality)

## Track GitHub Code Quality enablement changes in the audit log

**URL:** https://github.blog/changelog/2026-08-20-track-github-code-quality-enablement-changes-in-the-audit-log

### 要約
GitHub Code Quality の有効化・無効化・設定変更が audit log に記録されるようになりました。`repo.code_quality_enabled`、`repo.code_quality_disabled`、`repo.code_quality_updated` の 3 つのイベントで追跡できます。

### ユーザーにとって良いこと
誰がいつ Code Quality を変更したかを監査しやすくなります。請求やアクティブ committer の範囲変化を説明する際の証跡にも使えます。

### アクションプラン
- organization / enterprise の audit log で新しい Code Quality イベントを監視対象に追加する。
- Audit Log API を使うレポートやアラートに `repo.code_quality_enabled` などを追加する。
- ⚠️ 変更履歴を手作業で追っていた運用は、新しい audit log イベントへ移行する。

### リファレンス
- [Track GitHub Code Quality enablement changes in the audit log](https://github.blog/changelog/2026-08-20-track-github-code-quality-enablement-changes-in-the-audit-log)
