## GitHub Enterprise Server 3.22 release candidate

**URL:** https://github.blog/changelog/2026-08-11-github-enterprise-server-3-22-release-candidate

### 要約
GHES 3.22 のリリース候補が公開されました。Copilot CLI を GHES の切断環境で使えるようにする機能、Enterprise Teams の GA、rulesets 強化、Issue 側バーでの release 状態表示などが含まれます。

### ユーザーにとって良いこと
企業内の権限管理やレビュー統制、運用確認がしやすくなります。特に GHES を使う組織では、Copilot CLI の接続やルール管理の選択肢が広がります。

### アクションプラン
- ⚠️ GHES 3.22 RC の評価環境で、Copilot CLI 連携と rulesets の動作を確認してください。
- Enterprise Teams を使う場合は、既存の権限設計を中央集約型に移せるか検討してください。
- secret scanning の保護解除要求や alert dismissal 要求の運用を、日付ソート前提で見直してください。

### リファレンス
- [GitHub Enterprise Server 3.22 release candidate](https://github.blog/changelog/2026-08-11-github-enterprise-server-3-22-release-candidate)

## Copilot memory and Ollama in GitHub Copilot for JetBrains

**URL:** https://github.blog/changelog/2026-08-11-copilot-memory-and-ollama-in-github-copilot-for-jetbrains

### 要約
JetBrains 向け Copilot に、セッションをまたいだ memory、Ollama の BYOK 対応、Codex ワークフロー改善、CLI の自動導入などが追加されました。あわせて MCP、ターミナル、カスタマイズ、cloud agent 周りの信頼性も改善されています。

### ユーザーにとって良いこと
会話の前提を毎回入力し直す手間が減り、ローカルや企業内のモデル選択肢も増えます。IDE 内の導線が改善され、セットアップと日常利用の摩擦も下がります。

### アクションプラン
- Copilot Memory を使うかどうかを設定ポータルで確認し、チーム方針に合わせて有効化してください。
- Ollama を使う場合は、JetBrains 側で provider と model selection を設定してください。
- Copilot CLI の自動インストールを使う前提で、社内端末の権限や配布ポリシーを確認してください。

## Automatically migrate branch protection rules to repository rulesets

**URL:** https://github.blog/changelog/2026-08-11-automatically-migrate-branch-protection-rules-to-repository-rulesets

### 要約
既存の branch protection rules を repository rulesets に直接変換できるようになりました。レビュー、ステータスチェック、push 制限をより柔軟なポリシーへ移行しやすくなります。

### ユーザーにとって良いこと
従来の保護ルールを手作業で再作成せずに、rulesets へ移行できます。複数ブランチや組織・enterprise 単位の統制も扱いやすくなります。

### アクションプラン
- 既存リポジトリで `Settings → Branches` の `Convert to ruleset` を試してください。
- 移行後は required reviews、status checks、push restrictions が同等に再現されているか確認してください。
- ⚠️ バイパス権限の設計が変わるため、ユーザー・チーム・アプリの許可範囲を見直してください。

### リファレンス
- [Automatically migrate branch protection rules to repository rulesets](https://github.blog/changelog/2026-08-11-automatically-migrate-branch-protection-rules-to-repository-rulesets)

## Upcoming deprecation of MAI-Code-1-Flash

**URL:** https://github.blog/changelog/2026-08-11-upcoming-deprecation-of-mai-code-1-flash

### 要約
MAI-Code-1-Flash は 2026-09-10 に全 Copilot 体験で非推奨になります。代替は MAI-Code-1.1-Flash です。

### ユーザーにとって良いこと
事前に移行先が示されたため、ワークフローやポリシーを計画的に更新できます。管理者は利用可能モデルの切り替えを前もって調整できます。

### アクションプラン
- ⚠️ 2026-09-10 までに、利用中のモデル指定を MAI-Code-1.1-Flash に更新してください。
- Copilot Enterprise / Business 管理者は、モデルポリシーで新モデルの利用を有効化してください。
- VS Code と github.com の Copilot Chat で新モデルが選択できるか確認してください。

### リファレンス
- [Upcoming deprecation of MAI-Code-1-Flash](https://github.blog/changelog/2026-08-11-upcoming-deprecation-of-mai-code-1-flash)

## Per-model token breakdown in the usage report

**URL:** https://github.blog/changelog/2026-08-11-per-model-token-breakdown-in-the-usage-report

### 要約
AI usage report で、モデルごとの input / output / cache read / cache write token 内訳を見られるようになりました。これにより、AI credits の消費理由をより詳しく追跡できます。

### ユーザーにとって良いこと
コストの説明責任が高まり、どのモデルがどの token を使っているかを把握しやすくなります。予算管理や最適化の材料として使えます。

### アクションプラン
- Copilot Business / Enterprise の管理者は、billing settings の AI usage page から usage report をダウンロードしてください。
- Copilot for individuals でも同様に内訳を確認し、コスト最適化に活用してください。
- ステークホルダー向けの課金説明資料に token 内訳を反映してください。

### リファレンス
- [Per-model token breakdown in the usage report](https://github.blog/changelog/2026-08-11-per-model-token-breakdown-in-the-usage-report)
