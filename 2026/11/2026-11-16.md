## GitHub Copilot weekly releases — November 9

**URL:** https://github.blog/changelog/2026-11-16-github-copilot-weekly-releases-november-9

### 要約
GitHub Copilot アプリで GitHub Enterprise Server のリポジトリを扱えるようになり、スマートフォンからクラウド／Codespace セッションを再開する QR コード機能なども追加されました。VS Code 1.146 ではエージェントセッションの受信トレイ、チャットの別ウィンドウ表示、拡張機能管理などが加わり、Claude Fable 5.2 と Gemini 4 Carbon も利用可能になりました。

### ユーザーにとって良いこと
Copilot を使った作業をデバイスやワークスペース間で続けやすくなり、注意が必要なエージェントセッションを優先して確認できます。プロジェクトのスケジュールや音声入力、アクセシビリティ設定など、アプリやエディター以外の操作性も向上します。

### アクションプラン
- Copilot アプリで GHES リポジトリを扱う場合は、GitHub.com または GHE.com アカウントでサインインしてください。GHES リポジトリのクラウドセッションは利用できません。
- 新しい Claude Fable 5.2 を使う場合、Copilot Pro+、Max、Business、Enterprise が対象です。データ保持がデフォルトで必要で、Business／Enterprise では管理者がポリシーを有効にする必要があります。Gemini 4 Carbon も対象プランを確認して利用してください。
- VS Code の実験的なモデル比較・Inbox・拡張機能管理やプレビュー中のチャット別ウィンドウ表示を試す場合は、該当機能を有効にし、チームのワークフローへの影響を確認してください。
- VS Code の Local harness は 2027 年 2 月に削除予定です。まだ利用している場合は Copilot harness へ移行し、既存のカスタマイズとワークフローを事前に確認してください。

## Budget limit increased to 40,000 budgets per account

**URL:** https://github.blog/changelog/2026-11-16-budget-limit-increased-to-40000-budgets-per-account

### 要約
GitHub Enterprise Cloud のアカウントごとの予算上限が、10,000 件から 40,000 件に引き上げられました。個人ユーザー、コストセンター、組織ごとに多数の予算を管理する大規模な企業でも、より細かく予算を設定できます。

### ユーザーにとって良いこと
企業アカウントの成長に合わせ、個別の利用者やコストセンター単位で予算管理を拡張できます。github.com と GHE.com で自動適用されるため、設定変更は不要です。

### アクションプラン
- GitHub Enterprise Cloud の既存の予算運用を継続してください。上限の引き上げは自動適用され、追加設定は不要です。
- 予算を 10,000 件近くまで利用している場合は、必要に応じて新しい予算を追加し、既存の予算・アラート運用を整理してください。

## GitHub Copilot models deprecated on November 16, 2026

**URL:** https://github.blog/changelog/2026-11-16-github-copilot-models-deprecated-on-november-16-2026

### 要約
2026 年 11 月 16 日付で、Claude Opus 4.8、Claude Opus 5、GPT-5.6 Terra が、Copilot Chat、インライン編集、Ask／Agent モード、コード補完など大半の Copilot 機能で非推奨になりました。代替モデルは順に Claude Opus 5.5、Claude Opus 5.5、GPT-6.1 Sol または GPT-6 Luna です。Claude Opus 4.8 は個人向け Copilot 年間プランでは引き続き利用できます。

### ユーザーにとって良いこと
推奨モデルへの切り替えにより、Copilot の各機能でサポート対象のモデルを継続して利用できます。代替モデルは既定のモデル有効化ポリシーが適用される Business／Enterprise では自動的に有効になる場合があります。

### アクションプラン
- 既存のワークフローや連携で非推奨モデルを指定している場合は、Claude Opus 5.5、GPT-6.1 Sol、または GPT-6 Luna へ更新してください。
- Copilot Business／Enterprise 管理者は、代替モデルの利用ポリシーを確認してください。グローバル既定を無効にしている場合は、Copilot 設定のモデルポリシーから必要なモデルを有効にしてください。
- 非推奨モデルを削除するための操作は不要です。Claude Opus 5 はモデル選択欄から削除されていますが、既存の許可済みアクセスを通じたランタイム拒否フォールバックでは引き続き利用されます。

## Control where GitHub Copilot customizations come from

**URL:** https://github.blog/changelog/2026-11-16-control-where-github-copilot-customizations-come-from

### 要約
GitHub Enterprise Cloud の管理者は、Copilot の選択したカスタマイズについて、ユーザーやプロジェクトの単独設定ではなく、プラグインまたは管理設定から提供するよう必須化できます。対象は skills、custom agents、hooks、MCP servers、実行可能な Copilot extensions で、全カテゴリまたは個別に制限できます。

### ユーザーにとって良いこと
組織は承認済みのプラグインや管理設定を通じて Copilot のツールや機能を配布しながら、必要なカスタマイズ機能を利用者に提供できます。マーケットプレイス制限と組み合わせることで、利用可能な配布元も制御できます。

### アクションプラン
- Copilot Business／Enterprise のライセンスを組織が発行している場合、管理者は `strictPluginOnlyCustomization` を設定し、プラグイン提供を必須にするカスタマイズカテゴリを選択してください。
- プラグインの配布元も制限する場合は、`strictKnownMarketplaces` および管理設定のマーケットプレイス定義と組み合わせてください。プラグイン限定設定だけでは、Enterprise 管理のプラグインだけに制限されません。
- 拡張機能の制御範囲には実行可能な canvas provider が含まれますが、VS Code Marketplace 拡張機能は含まれない点を確認してください。

## VS Code retires the Local harness in February 2027

**URL:** https://github.blog/changelog/2026-11-16-vs-code-retires-the-local-harness-in-february-2027

### 要約
VS Code 1.146 で Local harness が非推奨になり、2027 年 2 月に削除される予定です。後継の Copilot harness は VS Code 1.143 以降、新しいセッションの既定であり、ファイルをクラウドへ移動せずにローカルでエージェントコマンドを実行できます。

### ユーザーにとって良いこと
Copilot harness は Copilot CLI や Copilot アプリと共通のエージェントランタイムを利用し、VS Code のエージェント機能やセッション継続を利用できます。管理者は Local harness では適用できないランタイム権限やサンドボックス制限も管理できます（別途設定が必要です）。

### アクションプラン
- Local harness を利用している場合は、新しい VS Code セッションの Session Target で Copilot を選び、カスタマイズの互換性を確認してください。
- 管理者は `vscode.temporaryDefaultToLocalHarness` の例外設定、必要なワークフロー、権限制御、サンドボックス設定を確認し、2027 年 2 月までに Copilot harness で検証してください。
- Copilot harness を選んだだけではサンドボックスは有効になりません。必要な場合は権限設定とサンドボックス設定を別途構成してください。
- **⚠️ Local harness は 2027 年 2 月に削除されます。** 一時的な Enterprise 管理設定を残しても削除後の利用は継続できないため、期限までに移行してください。

## Bulk start AI Scan for repositories

**URL:** https://github.blog/changelog/2026-11-16-bulk-start-ai-scan-for-repositories

### 要約
AI Scan for repositories を最大 20 リポジトリに対して一括で開始できるようになりました。スキャン結果は CodeQL が未対応の言語や既存の解析対象言語の追加の問題を検出し、CodeQL アラートと同じ code scanning backlog に表示されます。

### ユーザーにとって良いこと
組織は複数のリポジトリで AI Scan をまとめて開始でき、リポジトリごとの操作を減らしながら脆弱性検出の対象を広げられます。Copilot ライセンスは不要です。

### アクションプラン
- 対象リポジトリをまとめてスキャンする場合は、組織レベル設定を有効にしたうえで対象を選択するか、code scanning の組織アラートページから最大 20 件を選んで開始してください。
- 機能はパブリックプレビューです。github.com またはデータレジデンシー対応の GitHub Enterprise Cloud で、プレビューとして評価してください。
