## Copilot impact dashboard adds chat and VS Code agent usage

**URL:** https://github.blog/changelog/2026-11-06-copilot-impact-dashboard-adds-chat-and-vs-code-agent-usage

### 要約
Copilot impact dashboard の機能別利用状況に Copilot Chat と VS Code Agents ウィンドウが加わり、対象は合計9機能になりました。「Passive users」コホートは「Chat-first users」に名称変更されますが、Chat と VS Code Agents は引き続き導入フェーズの判定には使われず、API 上のコホート値やコホート人数も変わりません。

### ユーザーにとって良いこと
Chat を中心に使う開発者の利用状況をより正確に把握でき、エンタープライズ・組織向けの28日間レポートでも Chat と VS Code Agents の利用状況を確認できます。

### アクションプラン
- エンタープライズまたは組織の Copilot 28日間レポートで `chat` と `vscode_agent` の利用状況を確認し、既存の機能別分析に加えてください。
- Chat と VS Code Agents の利用数は機能エンゲージメントとして扱い、導入フェーズの判定には使わないでください。利用状況データには Copilot usage metrics policy の有効化と、必要な閲覧権限が必要です。

## GitHub Copilot weekly releases — November 2

**URL:** https://github.blog/changelog/2026-11-06-github-copilot-weekly-releases-november-2

### 要約
Copilot アプリでは、Pull Request からの Agent Merge、セッション管理、CSV/TSV の表表示、コンテキスト上限への対応などが改善されました。Copilot CLI に統合設定画面が追加され、JetBrains Air と Xcode にも Copilot が登場します。VS Code 1.145 ではチャット表示、リモートアプリ、定期実行の自動化などが更新され、一部はプレビューまたは実験的機能です。

### ユーザーにとって良いこと

### アクションプラン

- ローカルセッションの assisted approval 向け個人指示はオプトインです。内容を確認してから有効化してください。VS Code のクラウドセッションでは追加コンテキストとして画像のみがサポートされます。

## @GitHub in Slack and Teams is generally available and more

**URL:** https://github.blog/changelog/2026-11-06-github-copilot-in-slack-and-teams-is-generally-available

### 要約
Slack と Teams の `@GitHub` が一般提供となり、会話からバグ調査、Issue 作成、変更の実装、Pull Request の作成を行えるようになりました。Teams の Canvas では実装計画やコード変更、プレビューを会話と並べて確認し、チームで共同レビューできます。リポジトリの自動判定やフォローアップへの応答も改善され、作成された Issue と Pull Request には Slack/Teams の会話に由来することが記載されます。

### ユーザーにとって良いこと
Slack や Teams を離れずに、会話から実装・レビューまで進められます。Canvas と作成元の明示により、チームでのフィードバックや変更の経緯も追いやすくなります。

### アクションプラン
- Slack または Teams に `@GitHub` を導入し、アプリのアクセス権と既定リポジトリを確認したうえで、Issue 作成や PR 作成を試してください。
- Teams では Canvas を使って実装計画や変更内容を共同レビューする運用を検討してください。会話から作成した Issue/PR の説明に作成元が記載されることをチームに共有してください。

## Usage metrics API adds code review details and addressed rate

**URL:** https://github.blog/changelog/2026-11-05-usage-metrics-api-adds-code-review-details-and-addressed-rate

### 要約
Copilot usage metrics API のエンタープライズ・組織向けリポジトリ別日次レポートに `copilot_code_review` が追加され、Copilot のレビューコメント数、開発者が対応したコメント数、レビュー後に人から変更要求されずにマージされた PR 数などを取得できるようになりました。コメントの対応率は `total_comments_addressed` を `total_comments_evaluated` で割って算出でき、重要度、レビュー tier、コメント種別、カスタマイズ別の内訳も確認できます。

### ユーザーにとって良いこと
提案の適用ボタンが押された回数だけでなく、編集や Copilot への修正依頼なども含めて、レビューコメントが実際に活用された状況をリポジトリ単位で分析できます。カスタム指示や Skills、MCP サーバーの利用状況とレビュー結果の関係も把握しやすくなります。

### アクションプラン
- API クライアントや分析基盤で `copilot_code_review` の新しいフィールドを取り込み、`total_comments_evaluated` が0の場合を考慮して対応率を算出してください。
- コメントは PR のレビュー日ではなくマージ日に集計される点をレポートに反映してください。Bot が作成した PR のレビューコメントは通常評価されませんが、変更要求なしでマージされた PR の数には含まれる場合があります。
- レポートはエンタープライズ・組織の `repos-1-day` データが対象です。閲覧には Copilot usage metrics policy の有効化と適切な権限が必要です。

## Usage metrics API flags telemetry and version gaps

**URL:** https://github.blog/changelog/2026-11-05-usage-metrics-api-flags-telemetry-and-version-gaps

### 要約
Copilot usage metrics API に、ユーザーごとのクライアントテレメトリ受信状況と、IDE・Copilot 拡張機能の利用要件を満たしているかを示す項目が追加されました。日次レポートでは、テレメトリがないユーザー数と、最低バージョンを満たさないユーザー数も確認できます。

### ユーザーにとって良いこと
利用者としては記録されていても、エディター由来の詳細な利用データが欠けているユーザーや、古い IDE・拡張機能を使っているユーザーを特定できます。バージョン更新やテレメトリ設定、ネットワーク制限の確認を対象者に案内しやすくなります。

### アクションプラン
- `client_telemetry_present` が `false` のユーザーには IDE のテレメトリ設定やプロキシ・ファイアウォールを確認してもらい、`usage_metrics_requirements` が `unmet` の IDE/拡張機能は必要なバージョンへ更新してください。
- `missing_client_telemetry_user_count` と `below_usage_metrics_minimum_user_count` は重複する場合があるため合算しないでください。また、日次の件数を日をまたいで合算してユニークユーザー数として扱わないでください。
- `null` または欠落値は `false` や0ではなくデータ未提供を意味します。リリース前の日付には値がない点も分析に反映してください。レポートの利用には Copilot usage metrics policy の有効化と適切な権限が必要です。
