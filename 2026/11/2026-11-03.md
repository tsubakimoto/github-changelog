## Dependabot version updates support Agent Package Manager

**URL:** https://github.blog/changelog/2026-11-03-dependabot-version-updates-support-agent-package-manager

### 要約
Dependabot version updates が Agent Package Manager (APM) に対応し、`apm.yml` に宣言されたサポート対象の Git 依存関係を更新するプルリクエストを作成できるようになりました。`apm.lock.yaml` がある場合は更新時に再生成されますが、今回の対応はバージョン更新のみで、セキュリティ更新は対象外です。

### ユーザーにとって良いこと
AI エージェント用のスキル、プロンプト、指示ファイルなどの依存関係を、自動のプルリクエストで最新に保ちやすくなります。

### アクションプラン
- APM 依存関係を自動更新する場合は、`.github/dependabot.yml` に `apm` のエントリを追加し、`apm.yml` があるディレクトリと更新スケジュールを指定してください。
- 自動適用ではなく、Dependabot が作成するプルリクエストを確認してマージしてください。セキュリティ更新はこの機能の対象外です。
- GitHub.com の全プランで一般提供されています。GitHub Enterprise Server では 3.24 で利用可能になる予定です。

### リファレンス
- [Dependabot version updates support Agent Package Manager](https://github.blog/changelog/2026-11-03-dependabot-version-updates-support-agent-package-manager)

## Look up a resource’s cost center with the GitHub REST API

**URL:** https://github.blog/changelog/2026-11-03-look-up-a-resources-cost-center-with-the-github-rest-api

### 要約
新しい REST API エンドポイントを使い、ユーザー、Organization、リポジトリ、Enterprise チームが所属するコストセンターをリソース名から検索できるようになりました。該当する所属がなければ `memberships` は空になり、参照できる範囲は Enterprise billing へのアクセス権とユーザーのロールによって異なります。

### ユーザーにとって良いこと
すべてのコストセンターを取得して対象リソースを照合する必要がなくなり、請求情報を利用した管理や自動化を効率化できます。

### アクションプラン
- リソースごとのコストセンターを取得する連携を作る場合は、新しい「Get cost center membership for a resource」エンドポイントを利用してください。
- 呼び出し元に Enterprise billing の読み取り権限があることを確認してください。Enterprise owner、billing manager、該当権限を持つ GitHub App は Enterprise 内の任意のリソースを検索できます。Organization owner やカスタムロールは、閲覧可能なリソースとコストセンターに限定されます。

### リファレンス
- [Look up a resource’s cost center with the GitHub REST API](https://github.blog/changelog/2026-11-03-look-up-a-resources-cost-center-with-the-github-rest-api)

## GitHub Copilot is now available in JetBrains Air

**URL:** https://github.blog/changelog/2026-11-03-github-copilot-is-now-available-in-jetbrains-air

### 要約
JetBrains Air から GitHub Copilot にコーディングタスクを委任し、IDE やクラウドで実行結果を確認できるようになりました。クラウドタスクは新しい仮想マシン上の Docker コンテナで実行され、Copilot プランを使用します。タスク間で状態は引き継がれません。

### ユーザーにとって良いこと
IDE のプロジェクトコンテキストやツールを使って複数のエージェント作業を並行管理でき、クラウド実行ではローカル環境を変更せずにビルドやテストを実行できます。

### アクションプラン
- IDE でローカルタスクを使うには、JetBrains IDE に Air をインストールし、GitHub Copilot を選択して GitHub アカウントに接続してください。
- クラウドタスクには、Air Teams が有効なビジネス Organization の JetBrains アカウント、Copilot サブスクリプション、および管理者による Copilot の有効化が必要です。
- Cloud 利用前に、タスクが個人プランか Organization プランかを選択できないこと、Air のガバナンス・分析に Copilot 利用状況が含まれないことを管理者と確認してください。

### リファレンス
- [GitHub Copilot is now available in JetBrains Air](https://github.blog/changelog/2026-11-03-github-copilot-is-now-available-in-jetbrains-air)

## CodeQL 2.27.3 adds Python 3.15 features and JSON data extensions

**URL:** https://github.blog/changelog/2026-11-03-codeql-2-27-3-adds-python-3-15-features-and-json-data-extensions

### 要約
CodeQL 2.27.3 は Python 3.15 の構文・組み込み型、C23 の `_BitInt(N)`、JSON 形式のデータ拡張などに対応し、複数言語の解析精度も改善しました。カスタム CodeQL クエリ向けには、GitHub Actions の制御フローグラフが共通ライブラリに切り替わり、旧 `Completion` クラスが削除される破壊的変更があります。

### ユーザーにとって良いこと
新しい言語機能を使うコードの解析や、データ拡張による脅威モデルのカスタマイズが可能になり、誤検知の削減や脆弱性検出の改善も期待できます。

### アクションプラン
- GitHub.com の CodeQL code scanning には新バージョンが自動展開されます。古い GitHub Enterprise Server を利用している場合は、必要に応じて CodeQL を手動でアップグレードしてください。GHES 3.24 にも含まれる予定です。
- カスタムクエリが GitHub Actions の CFG ノード、エッジ、基本ブロック境界、または `Completion` クラスに依存している場合は、2.27.3 への更新前にクエリを確認し、必要に応じて `DirectSuccessor`、`BooleanSuccessor`、`ReturnSuccessor` などの CFG エッジラベルへ移行してください。
- JSON 形式のデータ拡張を使う場合は `.json` ファイルを用意してください。LLM 生成データ向けの `ai` 脅威モデルはオプトインで、組み込みソースモデルを含まないため、必要なソースをデータ拡張で定義してください。

### リファレンス
- [CodeQL 2.27.3 adds Python 3.15 features and JSON data extensions](https://github.blog/changelog/2026-11-03-codeql-2-27-3-adds-python-3-15-features-and-json-data-extensions)

## Dependabot now supports Python 3.15

**URL:** https://github.blog/changelog/2026-11-03-dependabot-now-supports-python-3-15

### 要約
Dependabot が Python 3.15 に対応し、Python 3.15 を使うプロジェクトでも Dependabot の更新を受け取れるようになりました。GitHub.com の全ユーザーが利用でき、GitHub Enterprise Server 3.24 にも含まれる予定です。

### ユーザーにとって良いこと
Python 3.15 へのアップグレード後も依存関係を継続的に更新でき、Dependabot による依存管理を維持できます。

### アクションプラン
- Python 3.15 へ移行するリポジトリは、Dependabot の設定と利用中の依存関係がサポート対象か確認してください。
- GitHub Enterprise Server を利用している場合は、3.24 の提供後に利用可能になります。

### リファレンス
- [Dependabot now supports Python 3.15](https://github.blog/changelog/2026-11-03-dependabot-now-supports-python-3-15)

## GitHub Desktop adds short-lived authentication tokens

**URL:** https://github.blog/changelog/2026-11-02-github-desktop-adds-short-lived-authentication-tokens

### 要約
GitHub Desktop 3.6.10 以降で、対象アカウントはサインイン時に有効期間の短い認証トークンを利用できるようになりました。トークンは API リクエストや Git 操作のために Desktop が自動更新しますが、機能は段階的に展開中で、既存セッションやトークンはアップグレードだけでは移行されません。

### ユーザーにとって良いこと
トークンが漏えいした場合に悪用される期間を短縮しつつ、日常の操作で手動更新する手間を避けられます。

### アクションプラン
- 対象アカウントで利用するには GitHub Desktop 3.6.10 以降に更新し、サインインしてください。段階的な展開のため、更新後すぐに全ユーザーが利用できるわけではありません。
- GitHub.com と GitHub Enterprise Cloud が対象です。GitHub Enterprise Server は対象外です。
- 既存セッションはサインイン状態を維持し、既存トークンも自動移行されません。新しいトークンを利用するには、対象環境への展開後にサインインしてください。

### リファレンス
- [GitHub Desktop adds short-lived authentication tokens](https://github.blog/changelog/2026-11-02-github-desktop-adds-short-lived-authentication-tokens)
