## OpenAI’s GPT-6.2 Astra and GPT-6.2 Sol now available

**URL:** https://github.blog/changelog/2026-11-17-openais-gpt-6-2-astra-and-gpt-6-2-sol-now-available

### 要約
GPT-6.2 Astra と GPT-6.2 Sol が GitHub Copilot で一般提供されました。Astra はエージェント型コーディングやターミナル作業向け、Sol は複雑なエージェント作業や詳細なコードレビュー向けで、どちらも従来モデルより少ないトークンで高いレビュー性能を目指しています。

### ユーザーにとって良いこと
複雑さに応じてモデルを選び、コードレビューやエージェント型開発の精度と利用効率を高められます。利用料金はプロバイダーのリスト価格に基づく従量課金です。

### アクションプラン
- Copilot Pro+、Max、Business、Enterprise の対象ユーザーは、段階的なロールアウト後にモデルピッカーから利用できます。表示されない場合は後日再確認してください。
- Copilot Business／Enterprise 管理者はモデルポリシーを確認してください。既定のモデル有効化が無効、または対象モデルを個別に無効化している場合は、必要に応じて許可してください。
- 利用前に従量課金の適用条件とモデル価格を確認してください。

## GitHub Copilot Fusion updates: more availability, benchmarks, and models

**URL:** https://github.blog/changelog/2026-11-17-github-copilot-fusion-updates-more-availability-benchmarks-and-models

### 要約
Copilot Fusion が最新の github.com、Visual Studio、GitHub Mobile ベータ版でも利用可能になり、Terminal-Bench 4.1 の公開リーダーボードにも掲載されました。Fusion Max は同ベンチマークで 71.2% の解決率を記録し、Fusion Max／High／Standard にそれぞれ新しい対応モデルが追加されました。

### ユーザーにとって良いこと

### アクションプラン
- 対応する最新バージョンの github.com、Visual Studio、または GitHub Mobile ベータ版で、モデルピッカーから Copilot Fusion を選択してください。通常版 GitHub Mobile への対応は後日提供予定です。
- 新モデルは Fusion Max に Claude Sonnet 5.5、High に GPT-6.1 Terra、Standard に MAI-Code-2 が追加されています。利用可能なティアとモデルを確認してください。

## GitHub Copilot app, Microsoft Ignite releases

**URL:** https://github.blog/changelog/2026-11-17-github-copilot-app-microsoft-ignite-releases

### 要約
GitHub Copilot アプリで Azure DevOps リポジトリの操作がパブリックプレビューになり、GitHub Enterprise Server（GHES）対応は一般提供になりました。また、Chrome／Edge のブラウザー操作機能もプレビューとして追加され、Webページの参照やフォーム操作を Copilot に依頼できます。

### ユーザーにとって良いこと
GitHub、Azure DevOps、GHES の作業やブラウザー上のタスクを Copilot アプリから進めやすくなります。Azure DevOps のプルリクエスト対応やレビュー指摘への修正もアプリ内で行えます。

### アクションプラン
- Azure DevOps 連携を試す場合は、アプリの Settings > Experimental で連携を有効にし、Accounts > Add account から Azure DevOps 用 Microsoft アカウントでサインインしてください。パブリックプレビューで、クラウドセッションには対応していません。
- ブラウザー操作は Chrome 拡張機能をインストールし、Settings > Computer Use で Enable Computer Use と Enable Browser Use を有効にしてください。既定ではオフで、権限レベルを拡張機能の設定から管理できます。
- GHES を使う場合は Copilot アプリを 1.2.0 以降に更新してアカウントを追加してください。GHES リポジトリのクラウドセッションには対応していません。

## Copilot code review: Adaptive effort, secret detection, and more

**URL:** https://github.blog/changelog/2026-11-17-copilot-code-review-adaptive-effort-secret-detection-and-more

### 要約
Copilot code review に、プルリクエストの複雑さやリスクに合わせて Lite／Balanced／Max を選ぶ Adaptive、関連する公開リポジトリを参照する機能、レビュー中のシークレット検出がパブリックプレビューとして追加されました。Repository insights でレビュー結果を確認できるほか、Azure Repos 向けコードレビューは一般提供になりました。

### ユーザーにとって良いこと
変更のリスクに応じたレビューの深さを自動化し、関連コードを踏まえた指摘や、漏えいした認証情報の早期発見に役立てられます。Azure DevOps 上のチームも Copilot によるレビューや提案を通常提供として利用できます。

### アクションプラン
- Adaptive、クロスリポジトリコンテキスト、シークレット検出はパブリックプレビューです。対象プラン（Pro、Pro+、Max、Business、Enterprise）で、レビュー担当者欄または設定から有効化を検討してください。
- Adaptive はリポジトリ／組織／Enterprise で設定した最大レビュー強度を超えません。許容する最大レベルを管理者と確認してください。
- シークレット検出を有効にする場合は、リポジトリまたは組織の Settings > Copilot > Code review を設定してください。
- Azure Repos で使う場合は、組織・プロジェクト・リポジトリの設定とブランチポリシーを構成し、必要なレビュー強度やカスタム指示を設定してください。利用料は Azure DevOps 組織に紐づく Azure サブスクリプションの GitHub AI クレジットに請求されます。

- [Copilot code review: Adaptive effort, secret detection, and more](https://github.blog/changelog/2026-11-17-copilot-code-review-adaptive-effort-secret-detection-and-more)

## Monitor GitHub Copilot activity through Microsoft Agent 365

**URL:** https://github.blog/changelog/2026-11-17-monitor-github-copilot-activity-through-microsoft-agent-365

### 要約
GitHub Enterprise Cloud の Enterprise Managed Users（EMU）を利用する企業は、Copilot のエージェント活動を Microsoft Agent 365 にストリーミングできるようになりました。複数の Copilot クライアントのセッション、プロンプト、応答、ツール呼び出しや利用傾向を確認し、Microsoft Purview と Defender のリスク情報も活用できます。

### ユーザーにとって良いこと
企業は GitHub Copilot の監査情報を他の AI ワークロードと一元的に確認し、利用状況の把握やリスク調査に役立てられます。

### アクションプラン
- 対象の GitHub Enterprise Cloud／EMU 環境では、Enterprise の監査ログストリーミング設定から Microsoft Agent 365 への連携を構成してください。
- Copilot クライアント全体の活動を確認する運用担当者と、Purview／Defender での調査手順を決めてください。

## GitHub Copilot CLI adds Microsoft Entra sign-in as a preview

**URL:** https://github.blog/changelog/2026-11-17-github-copilot-cli-adds-microsoft-entra-sign-in-as-a-preview

### 要約
GitHub Copilot CLI に Microsoft Entra 認証がパブリックプレビューとして追加されました。EMU のサイレント SSO、または Frontier 環境での Microsoft 365 Copilot ライセンスによるモデル利用が可能で、両方の方式は現時点で Windows と macOS に対応し、Linux 対応は今後予定されています。

### ユーザーにとって良いこと
組織の Microsoft Entra ID で認証し、対象の GitHub Enterprise アカウントや Microsoft 365 Copilot の権利を CLI から利用できます。Microsoft 365 経由の場合、モデル利用と上限は Microsoft 365 側で管理されます。

### アクションプラン
- Copilot CLI を 1.0.113 以降に更新してください（`copilot update`）。
- EMU で利用する場合は、組織が OIDC を使用していること、Copilot Business／Enterprise ライセンスが割り当てられていること、Copilot CLI ポリシーが有効であることを確認してください。
- Microsoft 365 Copilot 経由で利用する場合は、組織が Frontier に参加し、従量課金付きの Microsoft 365 Copilot ライセンスを有効にしていることを確認してください。利用条件と制限は Microsoft 365 管理者に確認してください。
- **Linux は未対応です。** 対応する OS でプレビューを評価してください。

## Track Copilot code review outcomes in Repository insights

**URL:** https://github.blog/changelog/2026-11-17-track-copilot-code-review-outcomes-in-repository-insights

### 要約
リポジトリの Insights タブに Repository insights ページが追加され、Copilot code review のコメント対応状況や高重要度コメントの対応状況などを確認できるようになりました。対応率の推移やコメント分類も確認でき、同じ指標は Copilot usage metrics API の組織・Enterprise 向け 1 日レポートでも利用できます。

### ユーザーにとって良いこと
チームは Copilot のレビュー指摘が活用されているか、人間のレビュー依頼が後から発生しているか、レビューが抜けているマージ済み PR があるかを把握し、改善箇所を特定できます。

### アクションプラン
- リポジトリの読み取り権限があれば Insights > Repository insights を開いて指標を確認してください。
- API の 1 日レポートを使う場合は Copilot usage metrics ポリシーを有効にし、必要な View Copilot Metrics 権限を持つ担当者にアクセスを付与してください。
- 対応率やレビュー対象の抜けを定期的に確認し、必要に応じてチームのレビュー運用を調整してください。

## GitHub Copilot Evals is now in public preview

**URL:** https://github.blog/changelog/2026-11-17-github-copilot-evals-is-now-in-public-preview

### 要約
GitHub Copilot Evals が Copilot Individual、Business、Enterprise 向けにパブリックプレビューになりました。skills、custom agents、MCP ツール向けに再現可能な評価を作成・実行し、合否や失敗理由を確認して、設定変更の前後で挙動を比較できます。

### ユーザーにとって良いこと
プロンプトやモデル、スキル、ツールを変更した際に、Copilot の動作が期待どおりか、変更で回帰が起きていないかを継続的に検証できます。各評価の実行前に承認できるため、実行を管理できます。

### アクションプラン
- 利用する環境（VS Code、Copilot CLI、Copilot アプリ）に対応する GitHub Copilot Evals 拡張機能またはプラグインをインストールしてください。
- 重要な skill、custom agent、MCP ツールに対して代表的なタスクと期待結果を定義し、カスタマイズ変更の前後で同じ評価を実行してください。
- プレビューとして結果を検証し、評価実行前の承認をチームの運用に組み込んでください。
