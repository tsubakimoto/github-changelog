## Enterprise Live Migrations from Azure DevOps generally available

**URL:** https://github.blog/changelog/2026-11-19-enterprise-live-migrations-from-azure-devops-generally-available

### 要約
Azure DevOps Services からデータレジデンシー対応の GitHub Enterprise Cloud への Enterprise Live Migrations が一般提供になりました。Git の履歴、ブランチ、タグ、プルリクエストとブランチポリシーを移行でき、移行中も同期を続けてチームの作業を止めずに切り替えられます。Azure Boards との接続や Azure Pipelines のリポジトリ切り替えも支援します。

### ユーザーにとって良いこと
移行前の検証や進捗追跡で問題を把握し、チームの作業を継続したまま都合のよいタイミングで切り替えられます。履歴や既存の開発ワークフローを引き継ぎやすくなります。

### アクションプラン
- Azure DevOps からの移行を計画している組織は、Microsoft の ELM ドキュメントで前提条件を確認し、Azure DevOps ポータルまたは CLI で移行を開始してください。
- データレジデンシー要件と切り替え時の運用を確認し、事前検証後にチームの予定に合わせてカットオーバーしてください。
- 一般提供の機能ですが、移行には組織側での計画・実行が必要です。

## Red Hat Enterprise Linux runner images now generally available

**URL:** https://github.blog/changelog/2026-11-19-red-hat-enterprise-linux-runner-images-now-generally-available

### 要約
GitHub-hosted larger runners 向けの Red Hat Enterprise Linux 9 および 10 イメージが一般提供になりました。GitHub Actions の本番ワークフローで利用でき、これらのイメージを基に必要なツールや設定を含むカスタムイメージも作成できます。

### ユーザーにとって良いこと
本番環境と同じ RHEL バージョンで CI を実行できるため、環境差異による問題を減らせます。プレビュー版を利用中の既存ランナーとワークフローは、そのまま継続して利用できます。

### アクションプラン
- 利用する場合は、GitHub Team または GitHub Enterprise Cloud の対象組織で Linux x64 larger runner を作成し、partner images から RHEL 9 または RHEL 10 を選択してください。
- プレビュー利用者は移行作業不要です。独自ツールや設定が必要な場合は、RHEL イメージを基にカスタムイメージを構成してください。

### リファレンス
- [Red Hat Enterprise Linux runner images now generally available](https://github.blog/changelog/2026-11-19-red-hat-enterprise-linux-runner-images-now-generally-available)

## S3 audit log streaming with OpenID Connect expands to GHE.com

**URL:** https://github.blog/changelog/2026-11-19-s3-audit-log-streaming-with-openid-connect-expands-to-ghe-com

### 要約
データレジデンシー対応の GitHub Enterprise Cloud（GHE.com）でも、OpenID Connect（OIDC）を使って監査ログを Amazon S3 にストリーミングできるようになりました。既存の GitHub.com での機能が GHE.com に拡張されます。

### ユーザーにとって良いこと
GitHub に長期有効な AWS 認証情報を保存せずに S3 への認証を構成でき、監査ログの外部保管をより安全に運用できます。

### アクションプラン
- GHE.com の監査ログを S3 に転送する組織は、OIDC による監査ログストリーミングの設定手順に沿って AWS 側と GitHub 側を構成してください。
- これは利用組織が設定して有効化する機能です。既存の GitHub.com 設定への変更は、GHE.com を利用する場合に必要に応じて行ってください。

### リファレンス
- [S3 audit log streaming with OpenID Connect expands to GHE.com](https://github.blog/changelog/2026-11-19-s3-audit-log-streaming-with-openid-connect-expands-to-ghe-com)

## Wait for pull request events with GitHub CLI

**URL:** https://github.blog/changelog/2026-11-18-wait-for-pull-request-events-with-github-cli

### 要約
GitHub CLI v2.105.0 以降で GitHub Event Streams に対応し、`gh event listen` を使ってプルリクエストのレビュー、状態や head の変更、マージ競合、チェック完了などのイベントを待てるようになりました。`--count`、`--follow`、`--timeout`、`--jq`、`--template` で待機方法や出力を制御でき、サブスクリプションの作成・一覧・確認・削除も CLI から行えます。

### ユーザーにとって良いこと
スクリプトやエージェントが一定間隔で状態を確認する代わりに、イベント発生を待って処理を進められます。不要なポーリングを減らし、イベントを受け取った後の処理も組み込みやすくなります。

### アクションプラン
- 試す場合は GitHub CLI を v2.105.0 以降に更新し、GitHub.com の Event Streams へのアクセスを確認して `gh event listen <プルリクエストURL>` を実行してください。
- Event Streams と `gh event` コマンドはプレビュー中で、利用には waitlist への登録が必要です。自動化に組み込む前にプレビューの制約と変更可能性を考慮してください。
- 利用は任意です。既存のポーリング処理は、アクセスが利用可能になり、イベント待機に置き換える価値がある場合に更新してください。

### リファレンス
- [Wait for pull request events with GitHub CLI](https://github.blog/changelog/2026-11-18-wait-for-pull-request-events-with-github-cli)
