## Security advisory permissions are now generally available

**URL:** https://github.blog/changelog/2026-11-20-security-advisory-permissions-are-now-generally-available

### 要約
カスタムリポジトリロールに、セキュリティアドバイザリの閲覧、作成・編集・管理、非公開の脆弱性レポートの受け入れ、アドバイザリの公開やCVEの申請に関する権限が追加され、一般提供されました。対象リポジトリ単位で担当者やチームに権限を付与でき、リポジトリ管理者や組織全体のSecurity Managerロールを付与せずに作業を任せられます。

### ユーザーにとって良いこと
アドバイザリを担当する人に必要最小限のアクセスを与えられるため、組織内の他のリポジトリの情報を不必要に公開せず、セキュリティ対応を分担できます。

### アクションプラン
- カスタムリポジトリロールに対応するプランを利用している組織は、対象リポジトリで担当者・チームに必要なSecurity権限だけを設定してください。
- 権限設計時は、臨時の非公開フォークからの変更のマージには引き続きリポジトリ管理者またはSecurity Managerが必要なこと、機密コメントには「Create, Edit, and Manage」とリポジトリへの書き込み権限の両方が必要なことを確認してください。
- これらの権限を持つユーザーは臨時の非公開フォークを削除できません。権限を割り当てる前に、リポジトリのセキュリティアドバイザリに関するドキュメントで各権限の詳細を確認してください。

## GitHub Enterprise Server 3.23 release candidate

**URL:** https://github.blog/changelog/2026-11-20-github-enterprise-server-3-23-release-candidate

### 要約
GitHub Enterprise Server（GHES）3.23のリリース候補版が公開されました。Projectsの高度なフィルター、ネットワーク内で動作するAIシークレット検出、npm以外のエコシステムへの悪意あるパッケージ情報の拡大、Dependabotの更新クールダウン、OAuthトークン有効期限などが含まれます。AIシークレット検出とOAuthトークン有効期限はパブリックプレビューです。

### ユーザーにとって良いこと
新機能を一般提供前に検証し、フィードバックを届けられます。とくにAIシークレット検出はエアギャップ環境でも利用でき、Dependabotの3日間のクールダウンは侵害された、または問題のある新バージョンをすぐに取り込むリスクを抑えます。

### アクションプラン
- GHES 3.23 RCを本番環境ではなく検証環境に導入し、公式のリリースノートとアップグレード手順を確認して、利用中の機能との互換性を評価してください。
- Secret Protectionを利用している場合は、AIシークレット検出のプレビュー機能とCPU要件を検証してください。外部接続やGPUは不要ですが、プレビュー機能の仕様は変更される可能性があります。
- OAuthアプリでトークン有効期限を必須化する前に、すべてのクライアントで8時間のアクセストークンとリフレッシュトークンを要求・保存・使用できることを確認してください。既存アプリではオプトインで、新規アプリではデフォルトです。
- RCへのフィードバックや質問はGitHub Supportに連絡してください。

## Pin your favorite repositories to your dashboard

**URL:** https://github.blog/changelog/2026-11-20-pin-your-favorite-repositories-to-your-dashboard

### 要約
新しいダッシュボード体験に「Favorite repositories」セクションが追加され、表示するリポジトリを選択できるようになりました。お気に入りはGitHub Mobileのピン留めリポジトリと同期し、両方の体験を合わせて最大25件まで登録できます。

### ユーザーにとって良いこと
よく使うリポジトリをWebとモバイルの両方で見つけやすくなり、検索や作業開始までの手間を減らせます。

### アクションプラン
- 新しいダッシュボードを利用している場合は、ダッシュボードの「Edit」または「Add repositories」からお気に入りを選び、「Save」で反映してください。変更を取り消す場合は「Cancel」を選択します。
- GitHub Mobileと合わせて25件を超えないように管理してください。上限を超える保存はエラーとなり、リストは変更されません。
- 新しいダッシュボード体験を有効にしていない場合、「Top repositories」は従来どおり表示されます。

## GitHub Desktop now supports multiple accounts per host

**URL:** https://github.blog/changelog/2026-11-19-github-desktop-now-supports-multiple-accounts-per-host

### 要約
GitHub Desktop 3.7.0で、GitHub.com、GitHub Enterprise Server、GHE.comの各ホストに複数アカウントでサインインできるようになりました。リポジトリごとに使用アカウントを関連付けられ、クローン、公開、Git操作で適切な認証情報を使えます。既存のリポジトリは現在使用中のアカウントに自動移行されます。

### ユーザーにとって良いこと
個人用と仕事用など複数のアカウントを同じホストで使い分けても、リポジトリごとに認証情報を手動で切り替える手間や誤操作を減らせます。

### アクションプラン
- 複数アカウントを使う場合はGitHub Desktop 3.7.0以降に更新し、「Settings/Options」>「Accounts」からアカウントを追加してください。
- クローンまたは公開時にアカウントを選択し、既存リポジトリの関連付けはリポジトリ設定またはリポジトリ一覧のコンテキストメニューで確認してください。
- ホストごとに1アカウントのみ利用している場合、既存リポジトリは自動移行されるため、通常は追加設定は不要です。

## Improvements on the pull request overview in public preview

**URL:** https://github.blog/changelog/2026-11-19-improvements-on-the-pull-request-overview-in-public-preview

### 要約
パブリックプレビュー中の新しいPull Request Overviewページが改善され、マージ可否や次の対応がより分かりやすくなりました。レビュー操作、解決済みスレッドの表示、force-pushやコミットのアクティビティ情報、画面サイズに応じたレイアウトなども改善されています。

### ユーザーにとって良いこと
レビュー担当者や閲覧者が必要な対応を把握しやすくなり、チェック、承認、変更履歴、関連操作をページ上で確認しやすくなります。

### アクションプラン
- プレビューを試す場合はPull Requestのヘッダーにある「Try the Overview page」を選択してください。プレビューへの参加は任意で、同じメニューから従来のOverviewに戻せます。
- マージ要件の表示、レビューやコメントの操作、モバイルでのレイアウトを実際のPull Requestで確認し、問題やフィードバックを公式のプレビュー用ディスカッションで共有してください。

### リファレンス
- [Improvements on the pull request overview in public preview](https://github.blog/changelog/2026-11-19-improvements-on-the-pull-request-overview-in-public-preview)
