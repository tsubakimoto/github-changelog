## Security risk assessments include repository protection status

**URL:** https://github.blog/changelog/2026-11-02-security-risk-assessments-include-repository-protection-status

### 要約
GitHub code security risk assessment と secret risk assessment に、検出結果が保護済み・未保護のどちらのリポジトリにあるかが表示されるようになりました。GitHub Team と GitHub Enterprise Cloud で利用でき、secret risk assessment の機能は GitHub Enterprise Server 3.24 でも利用可能になる予定です。

### ユーザーにとって良いこと
組織内でセキュリティ対策が不足しているリポジトリを特定しやすくなり、保護対象の拡大や優先順位付けに役立ちます。

### アクションプラン
- 組織の管理者またはセキュリティマネージャーは、組織の **Security** タブにある **Assessments** から評価を開始し、未保護リポジトリを確認してください。
- 未保護のリポジトリがあれば、組織のセキュリティ要件に沿って保護設定の適用を検討してください。この機能は GitHub Team と GitHub Enterprise Cloud で利用できます。
- GitHub Enterprise Server を利用している場合は、secret risk assessment の対応予定バージョン 3.24 を確認してください。

## pull_request_target blocked by default December 2

**URL:** https://github.blog/changelog/2026-11-02-pull_request_target-blocked-by-default-december-2

### 要約
公開リポジトリでは、2026年12月2日から `pull_request_target` イベントがデフォルトでブロックされます。従来の適用予定日（2026年11月2日）から延期されており、それまでは評価モードで影響するワークフローを確認できます。適用前に、11月9日と16日の各16:00〜18:00 UTCには一時的なブロック（brownout）が実施されます。

### ユーザーにとって良いこと
フォーク由来の信頼できないコードを、リポジトリのシークレットへアクセス可能な `pull_request_target` の実行環境に持ち込むリスクを抑えられます。事前の評価モードと brownout により、恒久適用前に影響を確認して対処できます。

### アクションプラン
- 公開リポジトリの管理者は、最初の brownout（2026年11月9日 16:00〜18:00 UTC）より前に Insights でブロック対象となるワークフローを確認してください。11月16日 16:00〜18:00 UTCにも brownout が予定されています。
- `pull_request_target` が必要なワークフローだけ、Actions event policy で明示的に許可してください。可能なら workflow file targeting で対象ファイルを限定し、不要なワークフローはデフォルトのブロックを維持してください。
- ⚠️ brownout 中、対象ワークフローは実行されず、失敗した run とエラー注釈が記録されます。恒久適用は2026年12月2日です。
- 変更対象は GitHub Free、GitHub Team、GitHub Enterprise Cloud の公開リポジトリです。非公開・内部リポジトリと GitHub Enterprise Server は対象外です。
