## Claude Sonnet 5 is generally available for GitHub Copilot

**URL:** https://github.blog/changelog/2026-06-30-claude-sonnet-5-is-generally-available-for-github-copilot

### 要約
Claude Sonnet 5 が GitHub Copilot で一般提供されました。IDE、Copilot CLI、cloud agent など幅広い経路で選べる Sonnet クラスの新しいモデルで、日常的な開発からエージェント的な作業まで対応します。

### ユーザーにとって良いこと
CLI やエージェント実行での応答性とコーディング性能の両方を改善しやすくなります。用途に応じてモデルを選べるため、速度重視・品質重視の切り替えもしやすくなります。

### アクションプラン
- Copilot Pro / Pro+ / Max / Business / Enterprise の利用者は、モデルピッカーで Claude Sonnet 5 を選んで既存モデルと比較してください。

- 料金は Usage Based Billing の provider list pricing が適用されるため、利用量の把握方法をチームで確認してください。

## GitHub code coverage merge protection for pull requests

**URL:** https://github.blog/changelog/2026-06-30-github-code-coverage-merge-protection-for-pull-requests

### 要約
branch rulesets で、プルリクエストのマージ時にコードカバレッジが下がった場合にブロックできるようになりました。最小カバレッジ率や default branch からの許容低下幅を条件にでき、まず evaluate mode で影響確認も可能です。

### ユーザーにとって良いこと
テスト品質の低下をマージ前に防ぎやすくなります。カバレッジを運用ルールとして固定できるため、偶発的な回帰を減らしやすくなります。

### アクションプラン
- GitHub Code Quality を使っているリポジトリで、branch rulesets に `Require code coverage merge protection` 相当の条件を追加してください。これは **ルールセットによる手動設定** です。
- まず evaluate mode にして、既存 PR にどれだけ影響するか確認してから active mode に切り替えてください。
- 最小カバレッジ率と許容低下幅のどちらを基準にするか、チームのテスト方針に合わせて決めてください。

## Releases: Sidebar navigation and per-asset download counts

## Open source license compliance is in public preview

**URL:** https://github.blog/changelog/2026-06-30-open-source-license-compliance-is-in-public-preview

### 要約
enterprise-wide な license policy に基づいて、依存関係のライセンス適合性を PR 時にチェックできる機能が public preview になりました。ruleset で有効化し、非準拠の依存関係はマージ前に検出・注釈されます。

- まず許容ライセンスの方針を定義し、必要なら package exceptions や closure request の承認フローを整えてください。
- 違反が出た場合の対応手順（削除、置換、ポリシー更新）を開発チームへ共有してください。

## Dependabot no longer infers .npmrc

**URL:** https://github.blog/changelog/2026-06-30-dependabot-no-longer-infers-npmrc

### 要約
Dependabot が `.npmrc` を推測して再構成する挙動が廃止されました。今後は `dependabot.yml` の registries に `scope` を定義すると、その情報を使って正しい `.npmrc` が生成されます。

### ユーザーにとって良いこと
private npm registry の認証失敗を減らし、Dependabot の設定をより明確な単一ソースにできます。ロックファイル差異や推測ロジックに依存しないため、更新の安定性が上がります。

### アクションプラン
- `.npmrc` を checked-in していないリポジトリでは、`dependabot.yml` の npm registry に `scope` を追加してください。これは **Dependabot 設定の更新** です。
- すでに checked-in `.npmrc` がある場合は、既存設定が優先されるため、そのままでも動作するか確認してください。
- private registry を使うリポジトリで、認証失敗が出ていないか Dependabot の PR 履歴を確認してください。

### リファレンス
- [Dependabot no longer infers .npmrc](https://github.blog/changelog/2026-06-30-dependabot-no-longer-infers-npmrc)

## Upcoming cloud data retention policy for closed security alerts

**URL:** https://github.blog/changelog/2026-06-30-cloud-data-retention-policy-for-closed-security-alerts

### 要約
2026-08-25 から、閉じられた Dependabot security alerts にデータ保持ポリシーが適用されます。2 年以上前に閉じたアラートは UI / API から外れ、必要に応じて CSV のアーカイブから取得する形になります。

### ユーザーにとって良いこと
保持期間と取得先が明確になり、監査やコンプライアンス対応の見通しを立てやすくなります。古いアラートはアーカイブで長期保管されるため、履歴管理もしやすくなります。

### アクションプラン
- 2026-08-25 までに REST API で閉じた Dependabot alerts を必要分取得し、2 年超のクエリに依存していないか確認してください。
- Enterprise / org / repo の管理者と security managers は、必要に応じて CSV アーカイブの取得手順を整備してください。
- この変更はまず Dependabot に適用されるため、今後の alert type 拡張の告知も追跡してください。⚠️ 2 年超の閉鎖アラートは UI / API から消えます。

## Per-user AI credit budgets available for cost centers

**URL:** https://github.blog/changelog/2026-06-30-per-user-ai-credit-budgets-available-for-cost-centers

### 要約
cost center に対して、個々のユーザー単位で AI credit budget を設定できるようになりました。ユーザーの追加・削除に応じて自動で追従し、個別予算・cost center 予算・universal 予算の優先順位も明確になっています。

### ユーザーにとって良いこと
チーム単位で AI 利用コストを細かく制御でき、人数の増減に合わせて手動再設定する手間を減らせます。Copilot 利用の多い部門だけ予算を厚くする、といった運用がしやすくなります。

### アクションプラン
- Enterprise 管理者は、REST API で cost center user-level budget を作成し、対象チームに紐づく予算を設定してください。現時点では **API でのみ作成可能** です。
- どの cost center にどの per-user budget を適用するかを整理し、universal budget との優先順位を確認してください。
- 支出上限として included usage も数える点を踏まえ、早期停止の挙動を財務・運用担当に共有してください。

### リファレンス
- [Per-user AI credit budgets available for cost centers](https://github.blog/changelog/2026-06-30-per-user-ai-credit-budgets-available-for-cost-centers)
