## Secret scanning adds extended metadata for Replicate secrets

**URL:** https://github.blog/changelog/2026-06-23-secret-scanning-adds-extended-metadata-for-replicate-secrets

### 要約
GitHub Secret Scanning が Replicate のシークレット検出に拡張メタデータを追加しました。漏えいした資格情報について、単なる検出だけでなく、より文脈のある情報を得られるようになります。

### ユーザーにとって良いこと
検出結果の意味が分かりやすくなり、対応優先度を判断しやすくなります。セキュリティチームは、誤検知の切り分けや修正対象の特定をより速く進められます。

### アクションプラン
- Secret scanning を利用しているリポジトリで、Replicate 関連のアラート表示を確認してください。
- 既存の漏えい対応フローに、拡張メタデータの確認手順を追加してください。
- 自動適用ではないため、通知・トリアージ運用は各組織で維持してください。

- [Secret scanning adds extended metadata for Replicate secrets](https://github.blog/changelog/2026-06-23-secret-scanning-adds-extended-metadata-for-replicate-secrets)

## Fetch Code Quality findings via REST API

**URL:** https://github.blog/changelog/2026-06-23-fetch-code-quality-findings-via-rest-api

### 要約
Code Quality の findings を取得するためのリポジトリ単位 REST API が public preview で利用可能になりました。単一 finding の取得と一覧取得の 2 つの read-only エンドポイントが追加されています。

### ユーザーにとって良いこと
UI だけでなく API からも CodeQL の結果を扱えるため、分析や自動化の幅が広がります。修正支援ツールやエージェントによる自動 remediation ワークフローに組み込みやすくなります。

### アクションプラン
- Code Quality の結果を外部ツールに取り込みたい場合は、`GET /repos/{owner}/{repo}/code-quality/findings` を試してください。
- 個別調査では `GET /repos/{owner}/{repo}/code-quality/findings/{finding_number}` を使って詳細を取得してください。
- ⚠️ public preview のため、プロダクション依存の前にエンドポイント仕様変更の可能性を考慮してください。

### リファレンス
- [Fetch Code Quality findings via REST API](https://github.blog/changelog/2026-06-23-fetch-code-quality-findings-via-rest-api)

## Automatic Dependabot access to GitHub-hosted registries

**URL:** https://github.blog/changelog/2026-06-23-automatic-dependabot-access-to-github-hosted-registries

### 要約
Dependabot が、PAT なしで private GitHub Packages registry を読めるようになりました。パッケージ側で Actions access を付与していれば、Dependabot はその権限を再利用して取得します。

### ユーザーにとって良いこと
Dependabot の認証設定が簡素化され、機密性の高い PAT 管理を減らせます。更新ジョブの失敗要因が減るため、依存更新の安定性も上がります。

### アクションプラン
- Dependabot が参照する各パッケージで、`Manage Actions access` に対象リポジトリを Read で追加してください。
- 既存の PAT ベースの registry 設定は、不要なら `dependabot.yml` から削除してください。
- GitHub-hosted registries を使う依存関係の更新結果を、初回適用後に確認してください。

### リファレンス
- [Automatic Dependabot access to GitHub-hosted registries](https://github.blog/changelog/2026-06-23-automatic-dependabot-access-to-github-hosted-registries)

## Deprecation of Python 3.9 for Dependabot

**URL:** https://github.blog/changelog/2026-06-23-deprecation-of-python-3-9-for-dependabot

### 要約
Dependabot が Python 3.9 のサポートを終了しました。Python 3.9 を使い続けると、依存関係更新の PR が作成されない可能性があります。

### ユーザーにとって良いこと
サポート対象の Python に揃えることで、Dependabot の更新ワークフローが継続して安定します。古いランタイムの維持による更新停止リスクを避けられます。

### アクションプラン
- `dependabot.yml` や関連設定で Python 3.9 を使っていないか確認してください。
- 使っている場合は、サポート対象の Python 3.14 などへ更新してください。
- ⚠️ 旧バージョン継続時は更新停止の可能性があるため、早めの移行が必要です。

### リファレンス
- [Deprecation of Python 3.9 for Dependabot](https://github.blog/changelog/2026-06-23-deprecation-of-python-3-9-for-dependabot)

## GitHub Copilot app support for BYOK

**URL:** https://github.blog/changelog/2026-06-23-github-copilot-app-support-for-byok

### 要約
GitHub Copilot app が BYOK (bring your own key) に対応し、独自のモデルプロバイダを接続できるようになりました。OpenAI、Azure OpenAI、Anthropic、Ollama、LM Studio などのプロバイダをセッション単位で選べます。

### ユーザーにとって良いこと
既存の契約やデータ境界を活かしながら、用途に応じてモデルを切り替えられます。企業や規制要件の厳しい環境でも、推論先を自社管理の範囲に寄せやすくなります。

### アクションプラン
- Settings → Model Providers から利用したいプロバイダと API key を追加してください。
- セッションごとに使うモデルを見直し、重い推論は frontier model、定型処理は local/self-hosted model に振り分けてください。
- ⚠️ Copilot Business / Enterprise では、組織または enterprise 管理者が Copilot CLI を policy で有効化している必要があります。

### リファレンス
- [GitHub Copilot app support for BYOK](https://github.blog/changelog/2026-06-23-github-copilot-app-support-for-byok)
