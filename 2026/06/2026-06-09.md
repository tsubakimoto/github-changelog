## Upcoming breaking changes for npm v12

**URL:** https://github.blog/changelog/2026-06-09-upcoming-breaking-changes-for-npm-v12

### 要約
npm v12 では、`npm install` の既定動作がセキュリティ重視に変わります。依存パッケージの install 系スクリプト、Git 依存、リモート URL 依存が明示許可なしでは実行・解決されなくなります。

### ユーザーにとって良いこと
サプライチェーン攻撃や意図しないコード実行のリスクを下げられます。インストール時の振る舞いがより明示的になり、どの依存に実行権限を与えるかをチームで管理しやすくなります。

### アクションプラン
- ⚠️ `npm 11.16.0+` に上げて通常の `npm install` を実行し、警告対象のスクリプトを洗い出してください。
- `npm approve-scripts --allow-scripts-pending` で信頼するパッケージを承認し、生成された `package.json` の変更をコミットしてください。
- Git 依存や HTTPS tarball 依存を使っている場合は、v12 移行前に許可設定・固定化・代替手段の確認を行ってください。

## Claude Fable 5 is generally available for GitHub Copilot

**URL:** https://github.blog/changelog/2026-06-09-claude-fable-5-is-generally-available-for-github-copilot

### 要約
Claude Fable 5 が GitHub Copilot で一般提供されました。長時間の自律的なコーディングや知識作業向けに設計され、Copilot の各種クライアントから選択できます。

### ユーザーにとって良いこと
より少ないツール呼び出しとトークン消費で複雑な作業を進めやすくなります。Copilot の利用環境に応じて新しい高性能モデルを選べるため、作業効率の改善が期待できます。

### アクションプラン
- Copilot Pro+ / Max / Business / Enterprise の対象環境で、モデルピッカーから Claude Fable 5 を選べるか確認してください。
- Copilot Business / Enterprise では、必要に応じて管理者が Copilot 設定で Claude Fable 5 ポリシーを有効化してください。
- ⚠️ このモデルはデータ保持が必要なため、組織のデータ保持ポリシーと利用可否を事前に確認してください。

## Periodic code scanning of inactive repositories

**URL:** https://github.blog/changelog/2026-06-09-periodic-code-scanning-of-inactive-repositories

### 要約
最終 push や pull request から 6 か月以上動きのないリポジトリに対して、30 日ごとの定期 code scanning が可能になりました。code scanning default setup を使う組織で、休眠リポジトリにも継続的なセキュリティカバレッジを適用できます。

### ユーザーにとって良いこと
放置されたリポジトリでも脆弱性検出を継続できるため、見落としを減らせます。アクティブ開発中だけでなく、保守停止に近いコードベースの安全性も維持しやすくなります。

### アクションプラン
- 組織の `Settings > Advanced Security > Global Settings` で、休眠リポジトリ向けの 30 日スキャンを有効化するか決めてください。
- 対象が `code scanning default setup` のリポジトリに限定される点を確認し、範囲外のリポジトリがないか把握してください。
- 休眠リポジトリから出る新規アラートの担当者と対応フローを決めてください。

## Security validation for third-party coding agents

**URL:** https://github.blog/changelog/2026-06-09-security-validation-for-third-party-coding-agents

### 要約
第三者の coding agent が生成したコードに対しても、GitHub が自動でセキュリティ検証を行うようになりました。CodeQL、GitHub Advisory Database、secret scanning を使って問題を検出し、必要なら agent が PR 完了前に修正を試みます。

### ユーザーにとって良いこと
Copilot cloud agent 以外の agent を使っても、同じセキュリティ基準を適用しやすくなります。agent 由来のコードの脆弱性や秘密情報漏えいを早い段階で抑えられます。

### アクションプラン
- 第三者 agent を使うリポジトリでは、Copilot 設定で有効にする検証ツールを確認してください。
- agent が作成した PR に未解決の警告や修正漏れがないか、マージ前の確認手順に組み込んでください。
- ⚠️ 追加ライセンスは不要ですが、検証は既存の Copilot 設定に従うため、組織標準を明文化してください。
