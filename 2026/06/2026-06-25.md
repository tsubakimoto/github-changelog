## Copilot code review: Analysis depth and efficiency updates

**URL:** https://github.blog/changelog/2026-06-25-copilot-code-review-analysis-depth-and-efficiency-updates

### 要約
Copilot code review が、Copilot CLI / SDK のファイル探索ツールを使う実装に切り替わり、既存のワークフローを変えずにコスト効率が改善されました。Medium analysis depth の public preview では、PR コメントへの深さ表示と、組織単位の既定レビュー深さ設定も追加されています。

### ユーザーにとって良いこと
レビュー品質を維持したまま、より少ないコストでコードレビューを回せます。Medium 深さの利用状況も見えやすくなり、組織標準の設定を揃えやすくなります。

### アクションプラン
- Medium analysis depth を使っている組織は、PR コメントで深さラベルが表示されることを確認してください。
- 組織の既定 review level を設定し、未設定リポジトリの挙動を統一してください。
- ⚠️ 変更は既存ワークフローに自動反映されるため、利用側の操作は不要です。

## Enterprise-managed settings now support strictKnownMarketplaces in VS Code and GitHub Copilot CLI

**URL:** https://github.blog/changelog/2026-06-25-enterprise-managed-settings-now-support-strictknownmarketplaces-in-vs-code-and-the-cli

### 要約
Enterprise-managed settings で `strictKnownMarketplaces` が使えるようになり、Copilot CLI と VS Code でインストール可能なプラグインの市場を制限できるようになりました。Copilot Business / Enterprise の管理設定を通じて、許可された marketplace だけからの導入を強制できます。

### ユーザーにとって良いこと
未承認のプラグイン導入を抑えられ、クライアント側のガバナンスを強化できます。管理者は利用許可の範囲を明示しやすくなります。

### アクションプラン
- enterprise-managed `settings.json` に `strictKnownMarketplaces` を追加してください。
- 許可する marketplace の一覧を見直し、社内ポリシーに合わせて明示してください。
- ⚠️ これは管理設定に基づいて自動適用されるため、ユーザー個別の設定変更は不要です。

- [Enterprise-managed settings now support strictKnownMarketplaces in VS Code and GitHub Copilot CLI](https://github.blog/changelog/2026-06-25-enterprise-managed-settings-now-support-strictknownmarketplaces-in-vs-code-and-the-cli)

## Saved views for repository issues – Public Preview and adjustable row heights in projects

**URL:** https://github.blog/changelog/2026-06-25-saved-views-for-repository-issues-and-adjustable-row-heights-in-projects

### 要約
Repository Issues に saved views が追加され、よく使う絞り込み条件を共有しやすくなりました。あわせて、Projects の table layout では row height を Single / Medium / Tall / Extra Tall から選べるようになっています。

### ユーザーにとって良いこと
よく見る issue の視点をチームで共有でき、triage の導線が短くなります。Projects では情報量に応じて表示密度を調整でき、一覧の見やすさを保てます。

### アクションプラン
- 「Unassigned bugs」「Needs triage」など、チーム共通の saved view を作成してください。
- Projects の table layout で、必要に応じて row height を調整してください。
- リポジトリの Issues sidebar にある新しい導線を前提に、運用ドキュメントを更新してください。

## More control over your GitHub-hosted runners

**URL:** https://github.blog/changelog/2026-06-25-more-control-over-your-github-hosted-runners

### 要約
Organizations が GitHub-hosted runners の利用制御をより細かく行えるようになりました。標準ラベルの無効化や、macOS runners を runner groups に追加して、権限・同時実行数・経路制御をまとめて管理できます。

### ユーザーにとって良いこと
どのワークフローがどの runner を使えるかを明確にでき、セキュリティとコスト管理を両立しやすくなります。macOS 実行基盤の制御もしやすくなります。

### アクションプラン
- 既存 workflow が `ubuntu-latest` などの標準ラベルに依存していないか確認してください。
- runner group の権限と concurrency 制限を見直してください。
- ⚠️ 標準 hosted runner を無効化する場合は、すべての workflow が runner group 経由で動くように移行してください。

### リファレンス
- [More control over your GitHub-hosted runners](https://github.blog/changelog/2026-06-25-more-control-over-your-github-hosted-runners)

## Actions steps can now be run in parallel

**URL:** https://github.blog/changelog/2026-06-25-actions-steps-can-now-be-run-in-parallel

### 要約
GitHub Actions で step の並列実行が正式にサポートされ、`background`、`wait` / `wait-all`、`cancel`、`parallel` の 4 つの新しいキーワードが導入されました。従来のシェル背景実行よりも、ログを分離したまま並列処理やバックグラウンドサービス起動を扱いやすくなっています。

### ユーザーにとって良いこと
独立した処理を同時に走らせやすくなり、ジョブ全体の待ち時間を減らせます。ログも整理されるため、実行状況の把握がしやすくなります。

### アクションプラン
- 独立している build / test / upload 処理を並列化できる workflow を洗い出してください。
- バックグラウンドサービスを使うジョブは `background` と `cancel` の組み合わせに置き換えてください。
- 新しい syntax を使う workflow は、実行順序と終了条件を明示して検証してください。

### リファレンス
- [Actions steps can now be run in parallel](https://github.blog/changelog/2026-06-25-actions-steps-can-now-be-run-in-parallel)

## npm adds preventive account protection for high-impact accounts

**URL:** https://github.blog/changelog/2026-06-25-npm-adds-preventive-account-protection-for-high-impact-accounts

### 要約
npm の high-impact account に対して、メール変更や 2FA recovery code 使用などの敏感な変更を検出すると、72 時間の read-only state に入る予防措置が導入されました。アカウント乗っ取りを使ったサプライチェーン攻撃を抑えるための保護です。

### ユーザーにとって良いこと
重要なパッケージを管理するアカウントが、侵害直後に悪用されるリスクを下げられます。利用者側のインストールやダウンロードは継続できます。

### アクションプラン
- npm で重要パッケージを管理する担当者は、72 時間の read-only 期間を前提に incident response を見直してください。
- アカウントのメール変更や 2FA recovery の手順を、セキュリティ運用に合わせて再確認してください。
- ⚠️ publish や token 管理などの操作は一時停止されるため、リリース計画に猶予を持たせてください。

### リファレンス
- [npm adds preventive account protection for high-impact accounts](https://github.blog/changelog/2026-06-25-npm-adds-preventive-account-protection-for-high-impact-accounts)

## GitHub Copilot for Jira is now generally available

**URL:** https://github.blog/changelog/2026-06-25-github-copilot-for-jira-is-now-generally-available

### 要約
GitHub Copilot for Jira が一般提供になりました。Jira issue への進捗ストリーミング、セッション完了後の Jira チャットからの追加指示、より簡単なオンボーディングが追加されています。

### ユーザーにとって良いこと
Jira から離れずに agent の進捗を追え、完了後も同じ pull request に対して指示を継続できます。作業の分断が減り、レビューの流れを保ちやすくなります。

### アクションプラン
- Jira 連携を使う組織は、GitHub organization と repository の接続設定を見直して GA 前提に更新してください。
- 既存の public preview 利用者は、オンボーディング手順と運用説明を最新版に差し替えてください。
- Jira での progress 表示を前提に、社内の確認フローを更新してください。

## Cost centers now support enterprise teams

**URL:** https://github.blog/changelog/2026-06-25-assign-enterprise-teams-to-cost-centers

### 要約
Enterprise teams を cost center の resource として追加できるようになり、チームメンバーの利用量をその cost center に自動で割り当てられるようになりました。手動更新だけでなく SCIM による membership 変更にも追従します。

### ユーザーにとって良いこと
組織構造に沿ったコスト配賦がしやすくなり、予算管理と責任の所在を揃えられます。チーム単位での spend cap 設定の土台にもなります。

### アクションプラン
- enterprise teams を cost center の resource に追加してください。
- 予算と cap の設定主体を cost center に寄せ、チーム membership の更新方法を SCIM 前提で整理してください。
- ⚠️ 課金配賦のルール変更になるため、財務・管理者・チームリーダーへ事前共有してください。

### リファレンス
- [Cost centers now support enterprise teams](https://github.blog/changelog/2026-06-25-assign-enterprise-teams-to-cost-centers)
