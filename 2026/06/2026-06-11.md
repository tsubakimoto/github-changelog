## GitHub Enterprise Server 3.21 is now generally available

**URL:** https://github.blog/changelog/2026-06-11-github-enterprise-server-3-21-is-now-generally-available

### 要約
GitHub Enterprise Server 3.21 が一般提供され、運用効率、監視、コードセキュリティ、ポリシー管理が強化されました。organization custom properties と Projects の hierarchy view が GA になり、Actions の大規模ワークフロー表示や secret scanning 権限管理も改善されています。REST API version 2026-03-10 は破壊的変更を含むため、既存連携には注意が必要です。

### ユーザーにとって良いこと
組織メタデータや issue 階層を活用した可視化がしやすくなり、大規模運用の管理負担が下がります。Actions や secret scanning の改善で、CI とセキュリティ運用の安定性も上がります。

### アクションプラン
- GHES 3.21 のリリースノートを確認し、アップグレード計画を立ててください。
- REST API version 2026-03-10 を使う連携があれば、破壊的変更の影響を事前に検証してください。⚠️
- organization custom properties、Projects の hierarchy view、secret scanning 権限の運用手順を更新してください。

## Bot-created pull requests can run workflows if approved

**URL:** https://github.blog/changelog/2026-06-11-bot-created-pull-requests-can-run-workflows-if-approved

### 要約
`github-actions[bot]` が作成した pull request でも、ユーザー承認があれば CI/CD ワークフローを実行できるようになりました。Copilot 生成 PR と同じ承認モデルに揃えられ、ボット由来の変更でも適切に検証しやすくなっています。

### ユーザーにとって良いこと
ボットが作った PR でも CI を通せるため、誤って未検証のままマージするリスクを減らせます。自動更新や自動修正の運用でも、既存のレビュー手順を保ったまま品質確認を回せます。

### アクションプラン
- `github-actions[bot]` が作る PR のレビュー手順に、ワークフロー承認の確認を追加してください。
- bot 生成 PR を自動マージしている場合は、CI 実行前提の運用に見直してください。
- write 権限を持つレビュアーが承認するフローをチームで共有してください。

## AI usage report updates

**URL:** https://github.blog/changelog/2026-06-11-ai-usage-report-updates

### 要約
AI usage report が、GitHub AI Credits の使用量を標準のレポート項目で反映するようになりました。今後は `quantity` と `gross_amount` を参照し、プレビュー期間に使われていた `aic_quantity` と `aic_gross_amount` は実質的に不要になります。

### ユーザーにとって良いこと
レポート項目が billing model と一致するため、集計やダッシュボードの解釈が分かりやすくなります。6 月 1 日以降の AI credit 利用を正しく追跡しやすくなり、運用の混乱を減らせます。

### アクションプラン
- AI usage report を参照しているダッシュボードや ETL で、`quantity` と `gross_amount` を使うよう更新してください。
- `aic_quantity` / `aic_gross_amount` に依存した分析ロジックを見直してください。
- 6 月 1 日以降の履歴を再集計し、レポートの表示が期待通りか確認してください。

### リファレンス
- [AI usage report updates](https://github.blog/changelog/2026-06-11-ai-usage-report-updates)

## Copilot CLI: Configure everything from one place with /settings

**URL:** https://github.blog/changelog/2026-06-11-copilot-cli-configure-everything-from-one-place-with-settings

### 要約
Copilot CLI に、設定を一元管理する `/settings` が追加されました。従来の `/theme` や `/experimental` などを統合し、対話 UI、インライン指定、`reset` を一つの入口で扱えます。

### ユーザーにとって良いこと
設定キーを探し回らずに、CLI 上で安全に編集できます。スキーマ検証つきで保存されるため、設定ミスで次回セッションが壊れるリスクも下がります。

### アクションプラン
- Copilot CLI を更新し、`/settings` で主要設定を確認してください。
- 既存の手順書やスクリプトに `/theme` など旧コマンドを使っている箇所があれば、`/settings` に統一してください。
- 設定変更が即時反映される項目を把握し、運用手順に追記してください。

### リファレンス
- [Copilot CLI: Configure everything from one place with /settings](https://github.blog/changelog/2026-06-11-copilot-cli-configure-everything-from-one-place-with-settings)

## New runner images in public preview

**URL:** https://github.blog/changelog/2026-06-11-new-runner-images-in-public-preview

### 要約
GitHub Actions に Ubuntu 26.04 と Windows 11 arm64 + Visual Studio 2026 の新しい runner image が public preview で追加されました。現行イメージとはツール構成が異なるため、事前検証に使うのが目的です。

- ⚠️ `windows-11-arm` ラベルはプレビュー終了後に移行予定なので、9 月までに互換性確認を終えてください。

## GitHub Agentic Workflows is now in public preview

**URL:** https://github.blog/changelog/2026-06-11-github-agentic-workflows-is-now-in-public-preview

### 要約
GitHub Agentic Workflows が public preview になり、issue triage や CI failure analysis、ドキュメント更新のような推論ベースの作業を Actions 内で自動化できるようになりました。自然言語の Markdown から standard Actions YAML に変換し、既存の runner group とポリシーをそのまま使えます。

### ユーザーにとって良いこと
反復作業を agent に任せられるため、運用や保守にかかる時間を減らせます。GitHub 内の制御と組み合わせて、自律処理をチームの標準フローに組み込みやすくなります。

### アクションプラン
- Quickstart に従って CLI extension を導入し、まずは小さな workflow で試してください。
- issue triage や失敗解析など、繰り返し発生する作業を Markdown workflow に切り出してください。
- read-only 権限、sandbox、safe outputs の前提を確認し、既存の権限設計に合わせてください。

## Agentic workflows no longer need a personal access token

**URL:** https://github.blog/changelog/2026-06-11-agentic-workflows-no-longer-need-a-personal-access-token

### 要約
GitHub Agentic Workflows で、personal access token の代わりに Actions の `GITHUB_TOKEN` を使えるようになりました。組織所有リポジトリでは、Copilot CLI の課金を組織に直接付ける運用も可能です。

### ユーザーにとって良いこと
長期保存が必要な PAT を減らせるため、運用とセキュリティの負担が下がります。組織課金に寄せることで、agent 実行コストの集約と管理もしやすくなります。

### アクションプラン
- Agentic Workflows CLI を最新に更新し、`gh extension upgrade aw` を実行してください。
- 組織課金に切り替える場合は、Copilot policy の `Allow use of Copilot CLI billed to the organization` を有効化してください。
- workflow frontmatter に `copilot-requests: write` を追加し、必要なコスト管理設定を確認してください。

### リファレンス
- [Agentic workflows no longer need a personal access token](https://github.blog/changelog/2026-06-11-agentic-workflows-no-longer-need-a-personal-access-token)
