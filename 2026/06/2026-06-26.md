## Track total merges by adoption phase in enterprise and organization reports

**URL:** https://github.blog/changelog/2026-06-26-track-total-merges-by-adoption-phase-in-enterprise-and-organization-reports

### 要約
Copilot usage metrics API の adoption phase ごとの集計に、pull request の merged 総数が追加されました。これまでの平均値に加えて、1 日・28 日レポートで phase ごとの絶対的な貢献量を確認できます。

### ユーザーにとって良いこと
各 adoption phase が実際にどれだけ成果に寄与しているかを把握しやすくなります。平均だけでは見えなかった、組織全体への影響度や導入の進み具合を比較しやすくなります。

### アクションプラン
- Copilot usage metrics API の `totals_by_ai_adoption_phase` を参照する分析処理に `total_pull_requests_merged` を追加する
- 既存のダッシュボードで平均値中心の表示になっている場合は、総数も併記して解釈しやすくする
- この指標は REST API 経由で Copilot usage metrics にアクセスできる enterprise admin / organization owner にのみ有効な点を周知する

- [Track total merges by adoption phase in enterprise and organization reports](https://github.blog/changelog/2026-06-26-track-total-merges-by-adoption-phase-in-enterprise-and-organization-reports)

## MAI-Code-1-Flash for Copilot Business and Copilot Enterprise

**URL:** https://github.blog/changelog/2026-06-26-mai-code-1-flash-for-copilot-business-and-copilot-enterprise

### 要約
MAI-Code-1-Flash が Copilot Business / Enterprise で一般提供になりました。高速・低遅延のモデルで、反復的な agentic coding に向いた選択肢です。

### ユーザーにとって良いこと
Copilot でより素早い応答が得られ、日常的なコーディング作業の待ち時間を減らせます。モデル選択肢が増えることで、用途に応じて速度重視の運用がしやすくなります。

### アクションプラン
- Copilot Enterprise / Business の管理者は、Copilot settings で `MAI-Code-1-Flash` policy を有効化する
- 使用中の Copilot ポリシーと課金設定を確認し、usage-based billing の provider list pricing を前提に社内案内を更新する
- モデル利用可否に依存する社内ドキュメントや運用手順を、対応モデル一覧に合わせて更新する

### リファレンス
- [MAI-Code-1-Flash for Copilot Business and Copilot Enterprise](https://github.blog/changelog/2026-06-26-mai-code-1-flash-for-copilot-business-and-copilot-enterprise)

## GitHub Desktop 3.6: Worktrees and deeper Copilot integration

**URL:** https://github.blog/changelog/2026-06-26-github-desktop-3-6-worktrees-and-deeper-copilot-integration

### 要約
GitHub Desktop 3.6 で、Copilot による commit authoring と merge conflict resolution が強化され、Git worktree にも対応しました。さらに、モデル picker と BYOK により、Desktop 内の Copilot 利用がより柔軟になっています。

### ユーザーにとって良いこと
コミットメッセージ生成やコンフリクト解消が楽になり、Git 作業の負担が下がります。worktree 対応により、複数ブランチを並行して扱う作業もやりやすくなります。

### アクションプラン
- GitHub Desktop を利用しているチームは 3.6.0 への更新方針を決める
- `./github/copilot-instructions.md` や `AGENTS.md` を整備し、Desktop の commit message 生成がリポジトリ標準に沿うようにする
- 複数ブランチを扱う作業手順を worktree 前提に見直し、stashing / clone の運用を減らす
- Copilot 利用には GitHub Copilot のアクセス権が必要なため、対象ユーザーのライセンス状況を確認する

- [GitHub Desktop 3.6: Worktrees and deeper Copilot integration](https://github.blog/changelog/2026-06-26-github-desktop-3-6-worktrees-and-deeper-copilot-integration)
