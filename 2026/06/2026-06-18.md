## Upcoming deprecation of Opus 4.6 (fast)

**URL:** https://github.blog/changelog/2026-06-18-upcoming-deprecation-of-opus-4-6-fast

### 要約
Copilot の各体験で使われている Opus 4.6 (fast) が 2026-06-29 に非推奨になります。代替は Opus 4.8 (fast) です。

### ユーザーにとって良いこと
サポート終了後の予期しない失敗を避けやすくなり、より新しいモデルへ計画的に移行できます。

### アクションプラン
- Copilot Chat、inline edits、ask/agent mode、code completions で使うモデル設定を Opus 4.8 (fast) に切り替えてください。
- Copilot Enterprise 管理者は、モデルポリシーで代替モデルを有効化してください。
- ⚠️ 6/29 以降は古いモデル前提の運用を続けないでください。

### リファレンス
- [Upcoming deprecation of Opus 4.6 (fast)](https://github.blog/changelog/2026-06-18-upcoming-deprecation-of-opus-4-6-fast)

## Detecting Duplicate Issues – Public Preview and issue fields MCP support for GitHub Issues

**URL:** https://github.blog/changelog/2026-06-18-duplicate-detection-and-issue-fields-mcp-support-for-github-issues

### 要約
Issue 作成時に既存 issue との重複候補を提案する機能が public preview で追加されました。GitHub MCP server の issue fields も読み書き可能になっています。

### ユーザーにとって良いこと
重複 issue の乱立を減らし、メンテナーの triage 時間を削減できます。AI エージェントで triage 済み issue を自動作成しやすくなります。

### アクションプラン
- Issue 作成フローで候補表示を確認し、重複削減の運用を試してください。
- MCP server を使うエージェントに issue fields の設定・検索を組み込んでください。
- ⚠️ public preview のため、運用に入れる前にフィードバック前提で評価してください。

### リファレンス
- [Detecting Duplicate Issues – Public Preview and issue fields MCP support for GitHub Issues](https://github.blog/changelog/2026-06-18-duplicate-detection-and-issue-fields-mcp-support-for-github-issues)

## Safer pull_request_target defaults for GitHub Actions checkout

**URL:** https://github.blog/changelog/2026-06-18-safer-pull_request_target-defaults-for-github-actions-checkout

### 要約
`actions/checkout v7` が `pull_request_target` の危険な checkout パターンを既定で拒否するようになりました。既存の floating major tag は 2026-07-16 にバックポートで強制されます。

### ユーザーにとって良いこと
fork 由来の unreviewed code を privileged workflow で実行してしまう事故を減らせます。

### アクションプラン
- `pull_request_target` を使う workflow で、fork PR の checkout パターンを棚卸ししてください。
- `actions/checkout@v4` のような floating tag 利用箇所は、7/16 の挙動変更に備えて点検してください。
- ⚠️ どうしても必要な場合のみ `allow-unsafe-pr-checkout` を明示し、理由をレビュー可能にしてください。

### リファレンス
- [Safer pull_request_target defaults for GitHub Actions checkout](https://github.blog/changelog/2026-06-18-safer-pull_request_target-defaults-for-github-actions-checkout)

## Control who and what triggers GitHub Actions workflows

**URL:** https://github.blog/changelog/2026-06-18-control-who-and-what-triggers-github-actions-workflows

### 要約
Workflow execution protections が public preview になり、誰がどのイベントで workflow を起動できるかを ruleset ベースで制御できるようになりました。actor と event の 2 種類のルールから始まります。

### ユーザーにとって良いこと
CI の起動主体を中央管理できるため、攻撃者や低信頼ユーザーによる不正実行を抑えやすくなります。

### アクションプラン
- organization または repository の Actions > Policies で、許可する actor / event を定義してください。
- まず evaluate mode で影響を確認し、その後 enforce に切り替えてください。
- ⚠️ public preview なので、既存 workflow が止まらないか shadow 運用で確認してください。

### リファレンス
- [Control who and what triggers GitHub Actions workflows](https://github.blog/changelog/2026-06-18-control-who-and-what-triggers-github-actions-workflows)
