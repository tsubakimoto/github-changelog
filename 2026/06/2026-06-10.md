## List, view, and create discussions in GitHub CLI

**URL:** https://github.blog/changelog/2026-06-10-list-view-and-create-discussions-in-github-cli

### 要約
GitHub CLI に `gh discussion` が追加され、Discussions の一覧表示、閲覧、作成、更新、コメントをターミナルから直接扱えるようになりました。これまで `gh api` に頼っていた作業を、より自然な CLI ワークフローで実行できます。

### ユーザーにとって良いこと
Discussions をブラウザに切り替えずに操作できるため、コミュニティ対応や社内 QA の流れが速くなります。CLI で完結することで、自動化やスクリプトへの組み込みもしやすくなります。

### アクションプラン
- GitHub CLI を v2.94.0 以降に更新してください。
- Discussions が有効なリポジトリで `gh discussion list` と `gh discussion view` を試し、既存の `gh api` 置き換え余地を確認してください。
- CLI ベースの運用をしているチームでは、`gh discussion create` / `edit` / `comment` を作業手順に追加してください。

### リファレンス
- [List, view, and create discussions in GitHub CLI](https://github.blog/changelog/2026-06-10-list-view-and-create-discussions-in-github-cli)

## Manage sub-issues, types, and dependencies from GitHub CLI

**URL:** https://github.blog/changelog/2026-06-10-manage-sub-issues-types-and-dependencies-from-github-cli

### 要約
GitHub CLI で issue の種類、親子 issue 関係、依存関係を直接扱えるようになりました。`gh issue` の JSON 出力にもこれらの情報が追加され、タスク構造を CLI から安定して読み書きできます。

### ユーザーにとって良いこと
作業の分解、依存関係の管理、進捗の追跡をブラウザなしで行えます。自動化や agent 連携でも issue の階層構造をそのまま利用しやすくなります。

### アクションプラン
- GitHub CLI を v2.94.0 以降に更新してください。
- `gh issue create` / `edit` で `--parent` や `--blocking` 系フラグを使い、既存の運用に issue 階層を反映してください。
- 依存関係や sub-issue を読み取る自動化がある場合は、新しい JSON フィールドを使うよう更新してください。

### リファレンス
- [Manage sub-issues, types, and dependencies from GitHub CLI](https://github.blog/changelog/2026-06-10-manage-sub-issues-types-and-dependencies-from-github-cli)

## Copilot Chat now sees your agent sessions

**URL:** https://github.blog/changelog/2026-06-10-copilot-chat-now-sees-your-agent-sessions

### 要約
Copilot Chat が Copilot cloud agent のセッション状況を把握し、実行中・完了済みのセッションを会話内で追跡できるようになりました。過去の agent セッション検索とログ取得もチャット内から使えます。

### ユーザーにとって良いこと
作業の引き継ぎや後追い確認がしやすくなり、何を agent が行ったかをすぐに把握できます。過去セッションを再利用しやすくなるため、同じ調査や実装を繰り返す手間が減ります。

### アクションプラン
- Copilot Chat で agent セッションの状態表示が出るか確認してください。
- 重要な agent 作業では、完了後にログと結果を会話から参照してレビュー手順に組み込んでください。
- セッション検索を使うチームでは、命名規則やタイトル付けを統一して見つけやすくしてください。

### リファレンス
- [Copilot Chat now sees your agent sessions](https://github.blog/changelog/2026-06-10-copilot-chat-now-sees-your-agent-sessions)

## Enterprises can now create up to 500 cost centers

**URL:** https://github.blog/changelog/2026-06-10-enterprises-can-now-create-up-to-500-cost-centers

### 要約
Enterprise あたりの cost center 上限が 250 から 500 に引き上げられました。大規模組織でも、部門や事業単位に合わせてより細かく費用を割り当てられます。

### ユーザーにとって良いこと
コスト管理の粒度が上がり、利用状況や支出の可視化がしやすくなります。既存の運用を変えずに、より多くの組織単位をそのまま管理できます。

### アクションプラン
- 追加設定が不要な自動適用の変更として扱ってください。
- 250 件制限を理由に分割していた cost center があれば、統合できるか見直してください。
- 財務・管理部門に、新しい上限と現状の登録数を共有してください。

### リファレンス
- [Enterprises can now create up to 500 cost centers](https://github.blog/changelog/2026-06-10-enterprises-can-now-create-up-to-500-cost-centers)

## Incremental analysis for Go, C/C++, and CodeQL CLI

**URL:** https://github.blog/changelog/2026-06-10-incremental-analysis-for-go-c-c-and-codeql-cli

### 要約
CodeQL の増分解析が Go と C/C++ の pull request スキャンで利用できるようになり、CodeQL CLI にも同機能が追加されました。既に対象だった言語群と同様に、解析時間の短縮が期待できます。

### ユーザーにとって良いこと
スキャン時間が短くなることで、PR の待ち時間やフィードバック遅延を減らせます。CI の回転が良くなり、CodeQL をより継続的に回しやすくなります。

### アクションプラン
- `code scanning` のデフォルトクエリスイートを使っている Go / C/C++ リポジトリで、増分解析が有効か確認してください。
- 3rd party CI の CodeQL CLI を使っている場合は、CLI を 2.25.5 以降に上げてください。
- 解析時間が長いリポジトリでは、変更前後の所要時間を比較して CI 設計を見直してください。

### リファレンス
- [Incremental analysis for Go, C/C++, and CodeQL CLI](https://github.blog/changelog/2026-06-10-incremental-analysis-for-go-c-c-and-codeql-cli)

## Dedicated security review command now available in Copilot CLI

**URL:** https://github.blog/changelog/2026-06-10-dedicated-security-review-command-now-available-in-copilot-cli

### 要約
Copilot CLI に実験的な `/security-review` コマンドが追加され、ローカルの変更差分に対するセキュリティレビューをターミナルで実行できるようになりました。高信頼度の指摘と修正提案を返し、典型的な脆弱性クラスを重点的に確認します。

### ユーザーにとって良いこと
コミット前に軽量なセキュリティ確認を挟めるため、初期段階で問題を見つけやすくなります。既存の code scanning や secret scanning を補完する、手元での即時レビュー手段になります。

### アクションプラン
- Copilot CLI の experimental mode を有効化してください。
- 変更を加えたローカルリポジトリで `/security-review` を実行し、指摘をコミット前レビューに組み込んでください。
- これは public preview の実験機能なので、重要なマージ前チェックとしては既存のセキュリティツールも併用してください。

### リファレンス
- [Dedicated security review command now available in Copilot CLI](https://github.blog/changelog/2026-06-10-dedicated-security-review-command-now-available-in-copilot-cli)

## Dependabot version updates now support the Deno ecosystem

**URL:** https://github.blog/changelog/2026-06-09-dependabot-version-updates-now-support-the-deno-ecosystem

### 要約
Dependabot の version updates が Deno に対応しました。`.github/dependabot.yml` に Deno エントリを追加すると、通常のスケジュールで更新 PR を作成できます。

### ユーザーにとって良いこと
Deno を使うリポジトリでも、依存更新の自動化を GitHub 上でまとめて管理できます。手動更新の負担を減らしつつ、更新漏れも抑えやすくなります。

### アクションプラン
- Deno を使っているリポジトリの `.github/dependabot.yml` に Deno 設定を追加してください。
- これは version updates のみの対応なので、security updates とは別に運用してください。
- 更新 PR のレビュー担当とマージ方針を決めて、既存の Dependabot 運用に組み込んでください。

### リファレンス
- [Dependabot version updates now support the Deno ecosystem](https://github.blog/changelog/2026-06-09-dependabot-version-updates-now-support-the-deno-ecosystem)
