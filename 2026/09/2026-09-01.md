## Enterprise Live Migrations from GHES to ghe.com generally available

**URL:** https://github.blog/changelog/2026-09-01-enterprise-live-migrations-from-ghes-to-ghe-com-generally-available

### 要約
Enterprise Live Migrations (ELM) が一般提供になり、GHES から GHEC with Data Residency へほぼ無停止でリポジトリ移行できるようになりました。移行中も継続同期が走るため、開発を止めずに切り替えを進められます。

### ユーザーにとって良いこと
大規模リポジトリや活発な開発中でも、ダウンタイムを最小化しながら移行できます。GEI と使い分けることで、移行対象の規模や停止許容度に応じた戦略を取りやすくなります。

### アクションプラン
- GHES 3.17.18+ / 3.18.12+ / 3.19.9+ / 3.20.3+ / 3.21.3+ / 3.22.0+ のどれを使っているか確認し、ELM 対応範囲に入る移行計画だけを対象にしてください。
- 大規模モノレポや常時更新されるリポジトリは ELM、短時間の停止が許容できる移行は GEI を使うように運用を分けてください。
- gh elm 拡張を導入し、移行作成・監視・cutover の手順を運用手順書に追加してください。

### リファレンス
- [Enterprise Live Migrations from GHES to ghe.com generally available](https://github.blog/changelog/2026-09-01-enterprise-live-migrations-from-ghes-to-ghe-com-generally-available)

## Set an expiration date for individual user budgets

**URL:** https://github.blog/changelog/2026-09-01-set-an-expiration-date-for-individual-user-budgets

### 要約
個別ユーザーバジェットに有効期限を設定できるようになりました。期限到来時に GitHub が自動でバジェットを削除し、次の適用対象バジェットへフォールバックします。

### ユーザーにとって良いこと
一時的な予算上書きの手動削除が不要になり、運用負荷と設定忘れのリスクを減らせます。期限付きの割り当てを安全に使えるため、キャンペーンや短期プロジェクト向けの管理がしやすくなります。

### アクションプラン
- 個別ユーザーバジェットを使っている Enterprise では、期限なしの常設設定と一時設定を分けて運用してください。
- 一時的な割り当てには「次の請求サイクル開始時」または特定日での expiration を設定し、不要な手動削除をやめてください。
- Budgets REST API を使っている場合は `expires_at` の保存・更新ロジックを追加してください。

## Copilot code review can now approve pull requests

**URL:** https://github.blog/changelog/2026-09-01-copilot-code-review-can-now-approve-pull-requests

### 要約
Copilot code review が、PR を承認可能かどうかの評価を示し、管理者が承認アクションを有効化できるようになりました。承認はデフォルトで無効で、enterprise / organization / repository の各レベルで制御できます。

### ユーザーにとって良いこと
レビューの一次判断から承認までを Copilot に任せられるため、レビュー待ち時間を短縮しやすくなります。承認可否の評価がコメントに残るので、人間のレビュアーは判断の根拠を素早く確認できます。

### アクションプラン
- ⚠️ Copilot に PR 承認をさせる前に、どのリポジトリで自動承認を許可するかを明確にしてください。
- Enterprise / organization / repository のどの階層で許可を持たせるかを決め、必要最小限の範囲だけ有効化してください。
- required-approvals ルールに Copilot の承認を含める場合は、承認後に新しいコミットが来たときの再レビュー運用を定義してください。

### リファレンス
- [Copilot code review can now approve pull requests](https://github.blog/changelog/2026-09-01-copilot-code-review-can-now-approve-pull-requests)

## Block users from discussion comments in personal repositories

**URL:** https://github.blog/changelog/2026-09-01-block-users-from-discussion-comments-in-personal-repositories

### 要約
個人所有リポジトリの discussion コメントでも、コメントから直接ユーザーを block / unblock できるようになりました。issue と PR コメントで使えていたインラインのブロック操作が discussion にも広がっています。

### ユーザーにとって良いこと
不適切なコメントへの対応をその場で完結でき、モデレーションの手間が減ります。Issue / PR / Discussion で操作がそろうため、コミュニティ運営の一貫性も高まります。

### アクションプラン
- 個人リポジトリで discussion を運営している場合は、モデレーション手順を issue / PR と同じ運用に統一してください。
- ブロック時に private note を残すルールを決め、対応履歴を後から追えるようにしてください。
- 複数人で運営しているなら、誰が block / unblock を実行できるかを明文化してください。

### リファレンス
- [Block users from discussion comments in personal repositories](https://github.blog/changelog/2026-09-01-block-users-from-discussion-comments-in-personal-repositories)

## Claude Fable 5.1 is generally available in GitHub Copilot

**URL:** https://github.blog/changelog/2026-09-01-claude-fable-5-1-generally-available-in-github-copilot

### 要約
Claude Fable 5.1 が GitHub Copilot で一般提供になりました。長時間の自律的なコーディングや大きなコードベースの調査に向いたモデルとして提供されます。

### ユーザーにとって良いこと

### アクションプラン

- ⚠️ このモデルはデフォルトで data retention が必要なので、ZDR 前提の組織では利用可否と契約条件を先に確認してください。

## GitHub CLI: Media in issues, pull requests, and comments

**URL:** https://github.blog/changelog/2026-09-01-github-cli-media-in-issues-pull-requests-and-comments

### 要約
GitHub CLI の `--attach` で、issue / pull request / comment に画像や動画を直接添付できるようになりました。Markdown 内で参照したローカルファイルも、そのままアップロード済みメディアに置き換えられます。

### ユーザーにとって良いこと
ブラウザを開かずにスクリーンショットや録画をその場で共有でき、バグ報告や PR 説明が速くなります。Coding agent や CLI ベースの運用でも、結果をテキストではなく実物で見せやすくなります。

### アクションプラン
- gh を v2.99.0 以上へ更新し、`gh issue comment --attach` と `gh pr comment --attach` の使い方をチームに共有してください。
- UI バグ報告のテンプレートに、スクリーンショットを `--attach` で付ける手順を追加してください。
- ⚠️ リポジトリへの書き込み権限が必要なので、権限のないメンバー向けには既存の添付フローを残してください。

### リファレンス
- [GitHub CLI: Media in issues, pull requests, and comments](https://github.blog/changelog/2026-09-01-github-cli-media-in-issues-pull-requests-and-comments)
