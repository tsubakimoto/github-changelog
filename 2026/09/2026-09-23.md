## More ways to request and configure Copilot code reviews

**URL:** https://github.blog/changelog/2026-09-23-copilot-code-review-more-ways-to-request-and-configure-reviews

### 要約
GitHub Copilot code review に、個人向けの専用設定ページと、より細かな自動レビュー設定が追加され、Copilot Business と Enterprise を含む全プランで利用できるようになりました。プルリクエスト作成時・共同作成時・draft 解除時や新しい push 時の自動レビュー、レビューの標準 effort（Lite / Balanced）を個人で設定できます。さらに、Enterprise 管理者は組織所有リポジトリに継承される既定の review effort を設定できます。

### ユーザーにとって良いこと
レビューを依頼する操作を減らし、チームの開発フローに合わせて Copilot のレビュータイミングと深度を統一できます。個人設定と Enterprise の既定値を使い分けられるため、開発者の利便性と組織の運用標準を両立できます。

### アクションプラン
- 開発者は `Profile -> Copilot settings -> Code review` を開き、自動レビューの対象（新規 push や draft pull request を含む）と既定の effort を設定してください。
- Enterprise 管理者は Enterprise 設定で Lite、Balanced、または GitHub の既定値から組織所有リポジトリ向けの既定 effort を選び、必要に応じて組織・リポジトリ単位の上書きを確認してください。
- チームは自動レビューの実行頻度と使用量への影響を確認し、既存のレビューポリシーやブランチ保護ルールと重複しないよう運用を調整してください。
- 個別にレビューを依頼する場合は、依頼時に既定値とは異なる review effort を選択できます。

## Node 20 is no longer available in GitHub Actions

**URL:** https://github.blog/changelog/2026-09-23-node-20-is-no-longer-available-in-github-actions

### 要約
GitHub Actions の runner で JavaScript action が Node 20 では実行されなくなり、Node 24 が標準になりました。`ACTIONS_ALLOW_USE_UNSECURE_NODE_VERSION` による一時的な opt-out も廃止されたため、独自の JavaScript action は `runs.using` を `node24` に変更して新しいリリースを公開する必要があります。

### ユーザーにとって良いこと
サポート対象の新しい Node.js ランタイムへ移行することで、Actions のセキュリティと保守性が向上します。公式 action の最新版を使うワークフローでは、必要な対応がすでに反映されています。

### アクションプラン
- JavaScript action を保守しているチームは、`action.yml` または `action.yaml` の `runs.using` を `node24` に変更し、新しい action リリースを公開してください。
- ワークフロー管理者は、利用中の JavaScript action を Node 24 対応の最新版へ更新し、主要なイベントで実行結果を確認してください。
- self-hosted runner の OS とアーキテクチャを確認してください。⚠️ Node 24 は macOS 13.4 以前および ARM32 と互換性がなく、これらの runner はサポート対象外です。
- ⚠️ 既存の `ACTIONS_ALLOW_USE_UNSECURE_NODE_VERSION` に依存する回避策は利用できないため、直ちに移行してください。

## Local sandboxing in the GitHub Copilot app

**URL:** https://github.blog/changelog/2026-09-23-local-sandboxing-in-the-github-copilot-app

### 要約
GitHub Copilot app で、プロジェクト単位にローカルセッションのサンドボックスを設定できるようになりました。ファイルシステムの読み書き・拒否パス、外部/ローカルネットワーク、Git および GitHub CLI の認証情報へのアクセスを制御でき、OS がポリシーを適用できない場合はサンドボックスなしで実行せずエラーになります。機能はデフォルトで無効で、現在は public preview です。

### ユーザーにとって良いこと
意図しないコマンドがローカルファイル、ネットワーク、認証情報へ与える影響を抑えられます。プロジェクトごとに権限を絞れるため、リポジトリの性質に応じた安全なエージェント利用が可能になります。

### アクションプラン
- ローカルリポジトリを開き、Copilot app のプロジェクト設定で `Sandbox new sessions` を有効にしてください。これは新規セッションに適用されます。
- 追加の read/write、read-only、拒否フォルダーと、外部/ローカルネットワーク、GitHub CLI・Git 認証情報の要否をプロジェクトごとに最小権限で設定してください。
- 実行中のセッションだけ有効化する場合は `/sandbox on` を使い、設定変更後は新規セッション開始または既存セッションの再起動で反映を確認してください。
- ⚠️ Copilot app と Copilot CLI のサンドボックス設定は別管理です。また、cloud sandbox やリモートホストのセッションには適用されません。

## OpenTelemetry in the GitHub Copilot app

**URL:** https://github.blog/changelog/2026-09-22-opentelemetry-in-the-github-copilot-app

### 要約
GitHub Copilot app が OpenTelemetry（OTel）に対応し、Enterprise の managed settings からエージェントの活動データを組織の監視基盤へ送信できるようになりました。セッションの流れ、モデルへのリクエスト、利用ツールのトレースを集中管理して、予期しない挙動の調査や運用分析に利用できます。プロンプトと応答本文はデフォルトでは含まれません。

### ユーザーにとって良いこと
既存の監視ツールで Copilot エージェントの実行状況を可視化でき、障害や不審な動作を段階的なトレースで調査できます。個々の開発者が設定するのではなく、Enterprise 全体へ一元的に適用できる点も運用上の利点です。

### アクションプラン
- Enterprise 管理者は `managed-settings.json` の `telemetry` プロパティに、互換性のある監視エンドポイントへの export 設定を追加してください。
- セキュリティ・プライバシー担当と、送信する属性、保持期間、アクセス権、監視基盤側の認証を確認してから有効化してください。
- ⚠️ コンテンツ取得設定を変更する前に、プロンプトや応答本文を収集する必要性とデータ取り扱い要件を確認してください。本文はデフォルトで除外されています。

## New features and improvements in Copilot for JetBrains

**URL:** https://github.blog/changelog/2026-09-22-new-features-and-improvements-in-copilot-for-jetbrains

### 要約
Copilot for JetBrains 1.18.0 で、低リスク操作を自動承認する assisted approvals、過去メッセージの再編集、組織共有の skills と custom instructions、Codex agent の plan mode が追加されました。組み込み GitHub MCP Server の有効/無効化やツール単位の永続的な制御、サイドバイサイドのチャットなど、エージェント操作と設定の管理性も向上しています。JetBrains Gateway とリモート開発環境では inline chat が非表示になり、JetBrains 2025.1 には将来のアップグレード案内が表示されます。

### ユーザーにとって良いこと
低リスクな承認の中断を減らしつつ高リスク操作の判断は利用者に残せるため、エージェント作業を効率化できます。計画を確認してから実装したり、組織の指示を共有したり、MCP ツールを細かく制御したりできるため、チーム開発での安全性と一貫性も高まります。

### アクションプラン
- JetBrains IDE の GitHub Copilot プラグインを 1.18.0 以降へ更新し、既存セッションと inline chat、Codex agent の動作を確認してください。
- assisted approvals は public preview であることを踏まえ、低リスク操作の自動承認範囲をチームの安全基準に照らして評価してください。
- 組織管理者は共有 skills・custom instructions を整備し、利用者は Codex の plan mode とメッセージ再編集を使って実装前に方針を確認してください。
- 組み込み GitHub MCP Server と個別ツールの権限を見直してください。⚠️ JetBrains 2025.1 は今後 2026.1 以降へのアップグレードが推奨され、Gateway/リモート開発では inline chat が利用できません。
