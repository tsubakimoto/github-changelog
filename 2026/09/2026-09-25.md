## Enterprise managed settings in-product validator

**URL:** https://github.blog/changelog/2026-09-25-enterprise-managed-settings-in-product-validator

### 要約
GitHub Copilot のエンタープライズ管理設定に、設定ファイルを画面上で検証できるバリデーターが追加されました。`managed-settings.json`、`team-mappings.json`、およびチームマッピングから参照される設定ファイルについて、JSONの不正、未対応設定、無効なチームマッピングなどを検出し、対象ファイルとJSONパスを示します。

### ユーザーにとって良いこと
ポリシーが適用されない原因を、設定反映後に推測するのではなく、AI controlsページで具体的に特定できます。修正箇所が明確になるため、Copilotの設定不備による意図しないアクセスや機能提供を減らせます。

### アクションプラン
- `.github-private` リポジトリの `copilot/managed-settings.json`、`copilot/team-mappings.json`、参照先のチーム設定ファイルを確認する。
- AI controlsの「Copilot settings validation」でエラーとJSONパスを確認し、指摘された設定を修正する。
- 修正を `.github-private` のデフォルトブランチへコミットし、Agentsページを再読み込みして検証結果が有効になったことを確認する。
- 検証は設定の正しさを確認する機能であり、設定自体の適用範囲やポリシー選択は別途確認する。

## Usage metrics API adds pull request review stages

**URL:** https://github.blog/changelog/2026-09-25-usage-metrics-api-adds-pull-request-review-stages

### 要約
エンタープライズおよび組織のリポジトリ単位Copilot利用メトリクス（`repos-1-day`）に、プルリクエストのレビュー工程別の所要時間が追加されました。`pull_request_review_times` 配列で、レビュー準備から初回レビュー、初回から最終レビュー、最終レビューからマージまでの中央値と90パーセンタイルを取得できます。

### ユーザーにとって良いこと
マージまでの遅延を、レビュアー待ち、レビューの往復、承認後の滞留に分解して把握できます。中央値と90パーセンタイルを併用することで、通常の遅延と一部の極端に遅いPRを区別し、改善策を選びやすくなります。

### アクションプラン
- 利用メトリクスAPIのレスポンス処理に `pull_request_review_times` を追加し、フィールドが存在しない場合も扱えるようにする。
- 人間が作成し、少なくとも別の人間1人がレビューしたPRだけが対象であること、データがマージ日に帰属することをダッシュボードの説明に明記する。
- 配列が空の場合は「該当PRなし」として表示し、ゼロ件として誤解しないようにする。単一レビューでは初回から最終レビューの時間が0になる。
- 2026年9月21日より前にレビュー準備完了となったPRはこの項目にバックフィルされないため、導入直後の期間比較には注意する。
- Copilot利用メトリクスポリシーを有効化し、必要な `View Copilot Metrics` 権限を持つ担当者がアクセスできることを確認する。

## Private saved views for repository issues and “Relates to” issue relationship is generally available

**URL:** https://github.blog/changelog/2026-09-25-personal-saved-views-for-repository-issues-and-more

### 要約
リポジトリのIssuesページで、個人用の非公開Saved viewsを作成・保存できるようになりました。また、「Relates to」Issue関係がREST API、GraphQL API、Webhook、タイムラインイベント、Issues検索、Projects検索で一般提供されます。

### ユーザーにとって良いこと
各ユーザーが自分の作業に必要なフィルターを、他のメンバーの画面や共有ビューに影響させず保存できます。「Relates to」を使えば、依存や重複とは異なる関連Issueをツール間で一貫して表現できます。

### アクションプラン
- Issue担当者は、担当・ラベル・状態など日常的に使う条件を非公開Saved viewとして保存する。
- Issue連携ツールを運用している場合は、API・Webhook・検索結果に含まれる「Relates to」関係を取り込み、表示・同期処理を確認する。
- 自動化で関係種別を扱う際は、既存の依存関係や重複関係と「Relates to」を混同しないように分類する。

## Changes to query results in the GitHub Actions API and UI

**URL:** https://github.blog/changelog/2026-09-25-changes-to-query-results-in-the-github-actions-api-and-ui

### 要約
ワークフロー、イベント、ステータス、ブランチ、実行者でActionsの実行を検索した際、該当件数が2,500件を超える場合は正確な件数ではなく `2,500+` と返されるようになりました。ページング結果は従来どおり最大1,000件で、タイムアウト前の不正確な件数を返す問題を避け、APIとUIの性能・件数精度を改善します。GitHub.comとGitHub Enterprise Cloudへ順次展開されます。

### ユーザーにとって良いこと
大量の実行検索でタイムアウトした結果を正確な件数と誤認するリスクが減ります。大規模リポジトリでも検索処理が安定し、結果の上限を前提にした運用へ移行できます。

### アクションプラン
- 2,500件を超える検索結果の正確な件数を前提にしているスクリプトやダッシュボードを洗い出す。
- `2,500+` を数値としてパースせず、上限超過を示す状態として処理する。
- 全件取得が必要な場合は、日付範囲やブランチなどの条件を追加してクエリを分割し、各クエリの最大1,000件のページングを実装する。
- 件数が上限表示になるケースをテストに追加し、GitHub.comとGHES Cloudへの展開後も監視する。

## Agentic autofix now uses Copilot Memory

**URL:** https://github.blog/changelog/2026-09-25-agentic-autofix-now-uses-copilot-memory

### 要約
Copilot Memoryを有効にしているユーザーでは、agentic autofixが既存のメモリをセキュリティアラート解決のコンテキストとして参照するようになりました。修正時に得られたパターンもメモリへ保存され、後続のagentic autofixやCopilot code review、Copilot cloud agentでリポジトリ固有の安全な開発パターンに活用されます。両機能ともパブリックプレビューです。

### ユーザーにとって良いこと
過去の修正方針やリポジトリ固有の知識を反映できるため、セキュリティアラートへの修正提案がプロジェクトの実装慣行に近づきます。繰り返し現れる問題では、蓄積した修正パターンによる一貫性と効率の向上が期待できます。

### アクションプラン
- 利用可能な場合はCopilot Memoryとagentic autofixを有効化し、対象リポジトリでセキュリティアラートの修正を試す。
- 保存されるメモリに秘密情報、認証情報、個人情報が含まれないよう、リポジトリのメモリ運用と権限を確認する。
- 自動修正はプレビュー機能であるため、適用前に差分、テスト、CodeQL結果を人間がレビューする。
- 組織のセキュリティ方針に合わせ、メモリの利用可否と共有範囲を管理する。

## CodeQL 2.27.1 adds C and C++ query and Kotlin 2.4.20 support

**URL:** https://github.blog/changelog/2026-09-25-codeql-2-27-1-adds-c-and-c-query-and-kotlin-2-4-20-support

### 要約
CodeQL 2.27.1では、C/C++・C#の新しいクエリ、Kotlin 2.4.20対応、Go・JavaScript/TypeScript・Rustなどのデータフローモデルとクエリ精度が改善されました。Actionsのロック済みアクションや自己リポジトリ参照を誤検出しない変更も含まれ、GitHub.comではコードスキャン利用者へ自動展開されます。GHES 3.24にも含まれ、旧GHESでは手動更新できます。

### ユーザーにとって良いこと
対応言語・フレームワークが増え、脆弱性検出のカバレッジと精度が向上します。誤検出の減少により、開発者が重要なアラートへ集中しやすくなり、C/C++、Kotlin、Go、Rustなどの新しいAPI利用時も分析を活用できます。

### アクションプラン
- GitHub.comのコードスキャン結果を確認し、新規アラート、解消された誤検出、クエリ変更による結果差分をトリアージする。
- Kotlin 2.4.20、Go 1.27、Fastify、Rustなどを利用するリポジトリで抽出・分析が正常に完了することを確認する。
- `actions/unpinned-tag` の運用では、構造的に有効な `actions.lock` と `$/` 自己リポジトリ参照が適切に扱われることを確認する。
- GHES利用者は3.24への更新計画を確認し、旧バージョンで必要ならCodeQLバージョンを手動更新する。更新後も既存のアラート抑制・クエリスイートを検証する。

## Default Enablement of Copilot features for Copilot Business and Enterprise

**URL:** https://github.blog/changelog/2026-09-24-default-enablement-of-copilot-features-for-copilot-business-and-enterprise

### 要約
Copilot Business/Enterprise向けに、一般提供機能と対応クライアント機能のグローバルなデフォルトポリシーが導入されます。管理者はAI Controlsの「Default policy for new features」で「Enabled」「Disabled」「Let organizations decide」を選択でき、設定は2026年10月22日から適用されます。明示的な既存設定は維持され、プレビュー機能は引き続きオプトインです。

### ユーザーにとって良いこと
組織やエンタープライズ全体で、新機能の初期利用可否を一貫した方針で管理できます。明示的な許可・拒否やプレビューへの既存の選択は上書きされないため、段階的な導入と例外管理を両立できます。

### アクションプラン
- 2026年10月22日までの28日間にAI Controls > Copilotで「Default policy for new features」を選択する。
- 「Enabled」「Disabled」「Let organizations decide」が、機能提供・承認フロー・コンプライアンス要件に与える影響を各組織管理者と確認する。
- Features & clients、Copilot Code Review、CopilotのMCPサーバーで、未設定項目がどのデフォルトに従うかを棚卸しする。
- ⚠️ 期限後は未設定の一般提供機能が選択したグローバルポリシーに従うため、明示的に有効化・無効化すべき機能を事前に設定する。
- プレビュー機能は自動有効化されないこと、既にプレビューへオプトインした選択は一般提供化後も保持されることを利用者へ周知する。
