## OpenTelemetry in the GitHub Copilot app

**URL:** https://github.blog/changelog/2026-09-22-opentelemetry-in-the-github-copilot-app

### 要約
GitHub Copilot app が OpenTelemetry（OTel）に対応し、Enterprise の managed settings からエージェントの活動データを組織の監視基盤へ送信できるようになりました。セッションの流れ、モデルへのリクエスト、利用ツールのトレースを集中管理して、予期しない挙動の調査や運用分析に利用できます。プロンプトと応答本文はデフォルトでは含まれません。

### ユーザーにとって良いこと
既存の監視ツールで Copilot エージェントの実行状況を可視化でき、障害や不審な動作を段階的なトレースで調査できます。個々の開発者が設定するのではなく、Enterprise 全体へ一元的に適用できる点も運用上の利点です。

### アクションプラン
- Enterprise 管理者は `managed-settings.json` の `telemetry` プロパティに、互換性のある監視エンドポイントへの export 設定を追加してください。
- セキュリティ・プライバシー担当と、送信する属性、保持期間、アクセス権、監視基盤側の認証を確認してから有効化してください。
- ⚠️ コンテンツ取得設定を変更する前に、プロンプトや応答本文を収集する必要性とデータ取り扱い要件を確認してください。本文はデフォルトで除外されています。

## New features and improvements in Copilot for JetBrains

**URL:** https://github.blog/changelog/2026-09-22-new-features-and-improvements-in-copilot-for-jetbrains

### 要約
Copilot for JetBrains 1.18.0 で、低リスク操作を自動承認する assisted approvals、過去メッセージの再編集、組織共有の skills と custom instructions、Codex agent の plan mode が追加されました。組み込み GitHub MCP Server の有効/無効化やツール単位の永続的な制御、サイドバイサイドのチャットなど、エージェント操作と設定の管理性も向上しています。JetBrains Gateway とリモート開発環境では inline chat が非表示になり、JetBrains 2025.1 には将来のアップグレード案内が表示されます。

### ユーザーにとって良いこと
低リスクな承認の中断を減らしつつ高リスク操作の判断は利用者に残せるため、エージェント作業を効率化できます。計画を確認してから実装したり、組織の指示を共有したり、MCP ツールを細かく制御したりできるため、チーム開発での安全性と一貫性も高まります。

### アクションプラン
- JetBrains IDE の GitHub Copilot プラグインを 1.18.0 以降へ更新し、既存セッションと inline chat、Codex agent の動作を確認してください。
- assisted approvals は public preview であることを踏まえ、低リスク操作の自動承認範囲をチームの安全基準に照らして評価してください。
- 組織管理者は共有 skills・custom instructions を整備し、利用者は Codex の plan mode とメッセージ再編集を使って実装前に方針を確認してください。
- 組み込み GitHub MCP Server と個別ツールの権限を見直してください。⚠️ JetBrains 2025.1 は今後 2026.1 以降へのアップグレードが推奨され、Gateway/リモート開発では inline chat が利用できません。

## Faster C++ code intelligence with whole codebase indexing

**URL:** https://github.blog/changelog/2026-09-22-faster-c-code-intelligence-with-whole-codebase-indexing

### 要約
GitHub Copilot CLI の C++ コードインテリジェンスで、プロジェクト全体のシンボルを永続的に保持する Whole Codebase Indexing（WCI）が利用可能になりました。Microsoft C++ Language Server がコンパイル情報を使って型、シンボル、include、ファイル間の関係を索引化し、定義・参照・実装の検索時に再利用します。

### ユーザーにとって良いこと
巨大で複雑な C++ リポジトリでも、開いていないファイルを含むコードベース全体を前提にした検索が高速になります。初回索引化後は更新しながら再利用されるため、コード理解やレビューで待つ時間を減らせます。

### アクションプラン
- C++ プロジェクトを Copilot CLI で開き、WCI の初回索引化が完了するまで待ってください。進捗や状態は `/lsp logs` で確認できます。
- 初回の索引化では、特に大規模なリポジトリで時間とメモリ使用量が一時的に増えることをチームへ周知してください。
- メモリや性能上の理由で無効化が必要な場合は、Microsoft C++ Language Server の indexing ドキュメントに従って設定を変更し、その後 Copilot セッションを再起動してください。
- チームは定義・参照検索の速度と結果を確認し、問題があれば C++ language server のフィードバック窓口へ報告してください。

## Security improvements for SSH

**URL:** https://github.blog/changelog/2026-09-22-security-improvements-for-ssh

### 要約
GitHub は SSH で RSA/SHA-1 の `ssh-rsa` 署名と `diffie-hellman-group-exchange-sha256` 鍵交換を廃止し、新しい RSA 鍵には 3072 ビット以上を要求します。一方、github.com と GitHub Enterprise Cloud with Data Residency（米国リージョンを除く）では、ポスト量子鍵交換 `mlkem768x25519-sha256` が追加されます。HTTPS リモートを使う利用者には影響しません。

### ユーザーにとって良いこと
弱い SHA-1 署名や古い鍵交換方式を減らし、量子計算機への耐性を見据えた、より安全な SSH 接続へ移行できます。RSA と主要な SSH 実装が SHA-2 に対応していれば既存鍵を継続利用でき、新しい接続ではクライアントが新方式を自動選択できます。

### アクションプラン
- Git リモートが SSH のチームは、OpenSSH 7.2p1 以降など対応バージョンを確認し、`rsa-sha2-256` / `rsa-sha2-512` または Ed25519 / ECDSA を使用してください。
- 2026年10月14日以降に RSA 鍵を新規作成する場合は、3072 ビット以上にしてください。新規鍵は可能な限り Ed25519 を推奨します。
- CI、Git クライアント、JSch、Go SSH、libssh2、PuTTY などの接続元を棚卸しし、古い実装を更新してください。
- ⚠️ `ssh-rsa` 署名と `diffie-hellman-group-exchange-sha256` の brownout および廃止スケジュールを確認し、公開ページに記載された「January 13, 2026」の日付は現在時点と矛盾するため、適用前に公式ドキュメントで正しい日付を再確認してください。

## Deprecation notice: All-platform CodeQL bundle

**URL:** https://github.blog/changelog/2026-09-22-deprecation-notice-all-platform-codeql-bundle

### 要約
CodeQL CLI 2.27.0 以降、全対応プラットフォームのバイナリを含む `codeql-bundle.tar.gz` と `codeql-bundle.tar.zst` が非推奨になりました。2027年3月中旬に削除される予定で、Linux ARM64 バイナリは今後もプラットフォーム別ダウンロードからのみ提供されます。

### ユーザーにとって良いこと
利用環境に必要なバイナリだけを取得できるため、ダウンロードサイズと導入対象を抑えられます。プラットフォーム別バンドルへ早めに移行すれば、全プラットフォーム版の削除後も CodeQL の更新を継続できます。

### アクションプラン
- CodeQL CLI の取得スクリプト、CI、キャッシュ設定で `codeql-bundle.tar.gz` / `codeql-bundle.tar.zst` を参照していないか確認してください。
- 利用する OS とアーキテクチャに対応した platform-specific bundle へ切り替え、Linux ARM64 を含む各 runner で解析が成功することを確認してください。
- ⚠️ 2027年3月中旬の削除前に、依存関係や社内ミラーのダウンロード URL を更新してください。
- CodeQL CLI と対応プラットフォームの要件を定期的に確認し、固定しているバージョンを計画的に更新してください。

- [Deprecation notice: All-platform CodeQL bundle](https://github.blog/changelog/2026-09-22-deprecation-notice-all-platform-codeql-bundle)
