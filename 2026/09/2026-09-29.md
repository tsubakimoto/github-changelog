## Repository custom runner settings for Dependabot

**URL:** https://github.blog/changelog/2026-09-29-repository-custom-runner-settings-for-dependabot

### 要約
リポジトリ管理者が、Dependabot のバージョン更新およびセキュリティ更新で使用するランナーの種類、カスタムラベル、ランナーグループをリポジトリ単位で設定できるようになりました。プライベートおよび内部リポジトリの GitHub.com で利用でき、セルフホストランナーや大規模 GitHub-hosted ランナーなど、プロジェクトに適した実行環境を指定できます。

### ユーザーにとって良いこと
Dependabot のジョブを、プライベートパッケージレジストリや特殊なツールを利用できる適切なランナーで実行できます。組織全体の設定を変更せずにリポジトリごとの要件へ対応でき、標準の GitHub-hosted ランナーへ戻す選択肢もあります。

### アクションプラン
- プライベートまたは内部リポジトリの **Settings** > **Advanced Security** > **Dependency scanning** > **Dependabot version updates** でランナー設定を確認する。
- ラベル付きランナーを使う場合は、カスタムラベルとランナーグループを指定する。ラベルを指定しなければ `dependabot` ラベルが使用される。
- プライベートパッケージレジストリなどへのアクセスが必要なジョブではセルフホストまたは大規模ランナーを選び、不要な場合は Standard GitHub runner を選択する。
- この設定は GitHub.com のプライベート・内部リポジトリが対象。公開リポジトリでは設定項目が表示されず、GitHub Enterprise Server では利用できない。また、セキュリティ設定は現時点で Dependabot のランナー設定を強制しない。

## Bring business context with external custom properties

**URL:** https://github.blog/changelog/2026-09-29-bring-business-context-with-external-custom-properties

### 要約
外部のシステム・オブ・レコード（CMDB、社内開発者ポータルなど）で管理する所有者、サービス階層、ライフサイクル、コンプライアンス状況といった業務コンテキストを、外部カスタムプロパティとして GitHub のリポジトリへ同期できるようになりました。この機能はパブリックプレビューで、値は GitHub UI では読み取り専用となり、外部カスタムプロパティ API を通じて外部システムが継続的に更新します。

### ユーザーにとって良いこと
GitHub 上のリポジトリビュー、絞り込み、ルールセットの対象指定で、常に最新の業務情報を利用できます。外部システムを唯一の情報源として維持できるため、GitHub と社内システム間の値の競合や手動更新の負担を減らせます。

### アクションプラン
- 外部システムを情報源にする属性を整理し、GitHub で直接管理する通常のカスタムプロパティと、外部カスタムプロパティに分ける。
- Port.io の連携を利用する場合は連携ガイドを確認し、独自連携の場合は外部カスタムプロパティ API ときめ細かな権限を使って同期処理を実装する。
- 既存のリポジトリビュー、フィルタリング、ルールセットのターゲット指定に同期済みプロパティを組み込み、ガバナンスに利用できることを検証する。
- ⚠️ パブリックプレビュー機能のため、導入前に仕様・権限・API の変更可能性を確認し、外部システムが値を所有することと GitHub UI では編集できないことを関係者に周知する。

### リファレンス
- [Bring business context with external custom properties](https://github.blog/changelog/2026-09-29-bring-business-context-with-external-custom-properties)

## GPT-6.1 Sol in GitHub Copilot

**URL:** https://github.blog/changelog/2026-09-29-gpt-6-1-sol-in-github-copilot

### 要約
OpenAI の GPT-6.1 Sol が GitHub Copilot で一般提供され、エージェント型コーディングやターミナルワークフローで利用できるようになりました。マルチステップのコーディング性能とトークン効率に優れ、Copilot Pro+、Max、Business、Enterprise のユーザーを対象に段階的に展開されます。

### ユーザーにとって良いこと
対象プランのユーザーは、実装やターミナル作業を少ないステップとトークンで進められる新しいモデルを選択できます。VS Code、Visual Studio、Copilot CLI、coding agent、GitHub.com、モバイル、各種 IDE など複数の環境で利用でき、使用量ベースの課金ではプロバイダーの定価に基づいて費用を把握できます。

### アクションプラン
- 対象プランのユーザーはモデルピッカーで GPT-6.1 Sol を選択し、エージェント型コーディングやターミナル作業で既存モデルとの品質・速度・トークン使用量を比較する。
- Copilot Business または Enterprise の管理者は、Copilot 設定のモデルポリシーで GPT-6.1 Sol の利用可否を確認する。デフォルトのモデル有効化が有効なら新モデルは自動的に有効になる。
- 使用量ベースの課金が適用されるため、Models and pricing を確認し、チームの利用量と予算への影響を監視する。
- ロールアウトは段階的に行われるため、モデルピッカーに表示されない場合は後で再確認する。

- [GPT-6.1 Sol in GitHub Copilot](https://github.blog/changelog/2026-09-29-gpt-6-1-sol-in-github-copilot)
