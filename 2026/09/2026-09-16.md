## Automate SSO authorization for classic PATs and SSH keys

**URL:** https://github.blog/changelog/2026-09-16-automate-sso-authorization-for-classic-pats-and-ssh-keys

### 要約
Enterprise 管理者が、classic PAT と SSH key の SSO 認可を複数組織にまとめて自動化できるようになりました。enterprise-installed GitHub App と `enterprise_credentials:write` 権限を使って、最大 50 組織を 1 回の API 呼び出しで認可できます。秘密情報そのものではなく token ID や SSH key fingerprint を使うため、認可の委任をより安全に扱えます。

### ユーザーにとって良いこと
複数の SSO 保護組織をまたぐ運用で、開発者や管理者が手作業で 1 組織ずつ認可する負担を減らせます。トークンのローテーションや新しい組織の追加時に、認可漏れによる作業停止を抑えやすくなります。

### アクションプラン
- Enterprise Cloud で複数組織を運用している場合は、enterprise-installed GitHub App に `enterprise_credentials:write` を付与できるか確認してください。
- PAT / SSH key のローテーション手順に、この bulk authorization API を組み込み、最大 50 組織単位で自動認可するフローへ置き換えてください。
- ⚠️ 手動認可前提の運用は、担当者依存と漏れの原因になります。サービスアカウントや自動化用 credential を使うチームは、移行期限を決めて新 API に寄せてください。

## SCIM user responses now include a profileUrl attribute

**URL:** https://github.blog/changelog/2026-09-16-scim-user-responses-now-include-a-profileurl-attribute

### 要約
SCIM の `/Users` レスポンスに、GitHub アカウントの絶対 URL を示す `profileUrl` が追加されました。RFC 7643 の標準属性として返され、organization / enterprise の両方の SCIM レスポンスで利用できます。外部 ID と GitHub アカウントの対応付けが、追加の推測や別 API の照会なしにしやすくなりました。

### ユーザーにとって良いこと
IdP や IT チームが、SCIM レスポンスだけでアカウントの参照先を把握しやすくなります。既存の `userName` や他属性の挙動は変わらないため、現行連携を壊さずにマッピング精度を上げられます。

### アクションプラン
- SCIM 連携を持つ組織は、`profileUrl` が返る場合にそれを優先して GitHub ユーザーと突合する実装へ更新してください。
- org / enterprise の SCIM OpenAPI schema とサンプルレスポンスを確認し、監査やサポート手順書に `profileUrl` の利用方法を追記してください。
- 既存の自動化は additive change ですが、未リンクの external identity では `profileUrl` が省略されるため、その場合の分岐を残してください。

### リファレンス

## Copilot budget increase requests are generally available

**URL:** https://github.blog/changelog/2026-09-16-copilot-budget-increase-requests-are-generally-available

### 要約
Copilot の利用可能クレジットを使い切ったメンバーが、追加予算をその場で申請できるようになりました。申請は支払い元の organization / enterprise に自動ルーティングされ、オーナーや billing manager は settings 画面で承認・調整・拒否できます。承認すると、設定した額に即時更新され、AI credits へのアクセスが戻ります。

### ユーザーにとって良いこと
メンバーが予算上限に達したときの待ち時間を減らし、Copilot 利用を中断しにくくなります。管理側も、設定画面からそのまま判断できるため、追加投資の可否をスムーズに運用できます。

### アクションプラン
- Copilot Business / Enterprise の利用者は、`Requests from members` をレビューする担当者と承認基準を決めてください。
- usage-based billing を使っている organization / enterprise では、申請がどの支払い元に届くかを確認し、運用手順に反映してください。
- チームの利用状況が上限に近い場合は、申請フローだけに頼らず、定期的に予算設定を見直して枯渇を予防してください。

## Code scanning AI Scan no longer requires CodeQL default setup

**URL:** https://github.blog/changelog/2026-09-16-code-scanning-ai-scan-no-longer-requires-codeql-default-setup

### 要約
Pull request 向けの AI Scan が、CodeQL default setup を有効にしていないリポジトリでも動作するようになりました。code scanning と AI Scan 自体の有効化は依然として必要ですが、default setup の有無に縛られず、対象リポジトリへより広く展開できます。GitHub Advanced Security 顧客向けの public preview です。

### ユーザーにとって良いこと
CodeQL の既定構成を入れていないリポジトリでも、PR 時点での脆弱性検出を広げやすくなります。導入の前提条件が減るため、セキュリティ検出のカバレッジを上げるハードルが下がります。

### アクションプラン
- organization / enterprise で AI Scan を使っている場合は、CodeQL default setup がない repo も含めて実際に PR で走るか確認してください。
- GitHub Advanced Security の有効化範囲を点検し、`AI Scan for pull requests` が必要な repo に自動で適用されるかを確認してください。
- ⚠️ public preview なので、導入後は検出結果のノイズや CI 時間への影響を監視し、運用ルールを固めてから広げてください。

- [Code scanning AI Scan no longer requires CodeQL default setup](https://github.blog/changelog/2026-09-16-code-scanning-ai-scan-no-longer-requires-codeql-default-setup)
