## GitHub Enterprise Server 3.22 is now generally available

**URL:** https://github.blog/changelog/2026-09-08-github-enterprise-server-3-22-is-now-generally-available

### 要約
GitHub Enterprise Server 3.22 が一般提供になりました。Copilot CLI を GHES のディスコネクテッド / エアギャップ環境で使うための設定、enterprise teams の一般提供、secret scanning のリクエスト並び替え、ruleset による個別ユーザーの bypass、必須レビュアー指定などが含まれます。issue サイドバーの release 状態表示や、公開リポジトリの PR 一覧で contributor role ラベルが見える改善も追加されています。

### ユーザーにとって良いこと
大規模な enterprise 運用で、権限管理・レビュー統制・リリース把握がしやすくなります。特に GHES を閉域で運用している組織では、Copilot CLI の利用範囲が広がり、開発者体験を保ったまま管理性を高められます。

### アクションプラン
- GHES 3.22 を利用する場合は、Copilot CLI の GHES 接続を technical preview として有効化し、閉域環境でのモデル provider 設定を検証してください。
- ruleset を使っている組織は、チーム単位の bypass だけでなく個別ユーザー bypass や required reviewers への置き換えを検討してください。
- issue の release 状態表示や PR 一覧の contributor role ラベルを、サポート・リリース確認・トリアージ手順に反映してください。

## New customer portal help.github.com

**URL:** https://github.blog/changelog/2026-09-08-new-customer-portal-help-github-com

### 要約
サポートポータルが help.github.com に移動し、support、docs、learning、community、account リソースが 1 つの入口にまとまりました。Copilot-powered search でサインイン不要の検索ができ、GitHub の status や重要なお知らせも確認しやすくなっています。ロールアウトは段階的で、当面は support.github.com も引き続き利用できます。

### ユーザーにとって良いこと
問い合わせ先や資料の行き来が減り、必要な情報に早くたどり着けます。サインインなしで検索できるため、利用者や非開発者でもサポート情報を見つけやすくなります。

### アクションプラン
- サポート案内、社内ドキュメント、ブックマークを help.github.com に更新してください。
- 利用者向けの案内では、ロールアウトが段階的であることと、未移行時は support.github.com が使えることを明記してください。
- GitHub の status や重要なお知らせを参照する運用がある場合は、新ポータルを一次参照先に切り替えてください。

## Automatic Dependabot access to GitHub-hosted registries

**URL:** https://github.blog/changelog/2026-09-08-automatic-dependabot-access-to-github-hosted-registries

### 要約
Dependabot が、個人アクセストークンなしで GitHub-hosted registries から private パッケージを読み取れるようになりました。`Manage Actions access` で repository に Read access を付けていれば、Dependabot の `GITHUB_TOKEN` が `packages:read` を使って `*.pkg.github.com` と `ghcr.io` にアクセスします。既存の registry では、明示的な認証情報や通常の GitHub Actions のルーティングが優先されます。

### ユーザーにとって良いこと
Dependabot のために個別の PAT を管理する必要が減り、秘密情報の保守とローテーションが楽になります。package 側のアクセス許可に寄せられるので、権限管理も GitHub の標準機能で統一しやすくなります。

### アクションプラン
- GitHub-hosted registries を Dependabot に読ませる package には、`Manage Actions access` で該当 repository に Read access を付与してください。
- PAT ベースの registry エントリを `dependabot.yml` に入れている場合は、GitHub Packages 向けのものを削除して標準のアクセス付与へ移行してください。
- ⚠️ 以前に一時ロールバックされた経緯があるため、npm 更新ジョブでは explicit registry credentials や既存のルーティングが依然として優先される前提で挙動を確認してください。
