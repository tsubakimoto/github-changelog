## Enterprise-managed settings support any default model

**URL:** https://github.blog/changelog/2026-09-02-enterprise-managed-settings-support-any-default-model

### 要約
Enterprise-managed settings で、新しい会話の既定 Copilot モデルを任意のモデルに設定できるようになりました。さらに `model` キーを `overridable` にして `team-mappings.json` を更新すれば、チームごとに異なる既定モデルも割り当てられます。Copilot Business と Copilot Enterprise の GitHub Copilot app、Copilot CLI、Visual Studio Code で一般提供です。

### ユーザーにとって良いこと
組織全体で使うモデルを統一しつつ、チームの用途に合わせて既定モデルを分けられるため、会話開始時の選択コストを減らせます。新しい会話に自動適用されるので、日常運用のばらつきも抑えやすくなります。

### アクションプラン
- Enterprise managed settings で、新規会話の既定モデルを組織の標準モデルに設定してください。
- チーム単位で既定を変えたい場合は、`model` キーを `overridable` にし、`team-mappings.json` でチーム別の割り当てを更新してください。
- Copilot app、Copilot CLI、Visual Studio Code で、各チームの新規会話が期待どおりのモデルを引くか確認してください。

## Content exclusions generally available in Copilot app and CLI

**URL:** https://github.blog/changelog/2026-09-02-content-exclusions-generally-available-in-copilot-app-and-cli

### 要約
Copilot app と Copilot CLI が、enterprise / organization / repository 管理者が設定した content exclusion ポリシーを尊重するようになりました。除外対象のファイルはコンテキストとして使われないため、機密コードを agentic ワークフローから守りやすくなります。Copilot Business と Copilot Enterprise 向けに一般提供です。

### ユーザーにとって良いこと
除外したいファイルを一元管理でき、意図せず機密情報を Copilot の入力文脈に含めるリスクを減らせます。アプリと CLI の両方で同じ保護が効くため、利用経路ごとの設定差も小さくなります。

### アクションプラン
- enterprise / organization / repository の管理設定で、機密情報を含むパスを content exclusion に追加してください。
- Copilot app と Copilot CLI の両方で、除外したファイルがコンテキストに含まれない運用になっているか確認してください。
- ⚠️ 除外されたファイルは agentic ワークフローでも参照されないため、運用手順や開発者向けガイドに対象パスを明記してください。
