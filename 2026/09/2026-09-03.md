## Multiple trusted publishing configurations for npm

**URL:** https://github.blog/changelog/2026-09-03-multiple-trusted-publishing-configurations-for-npm

### 要約
npm の trusted publishing で、1 つのパッケージに複数の OIDC 設定を持てるようになりました。stable、pre-release、staging など複数のワークフローを分けても、各設定は独立して評価されます。あわせて、staged package の承認は malware scan 完了後にのみ可能になり、versions タブで staged 履歴も確認できます。

### ユーザーにとって良いこと
ワークフローごとに公開経路を分けやすくなり、長期トークンに頼らずに安全な公開運用へ移行しやすくなります。staging と承認の流れが明確になったことで、誤公開のリスクも下げられます。

### アクションプラン
- 既存の npm 公開設定を見直し、workflow ごとに trusted publishing 設定を分割してください。
- 可能なら direct publishing を無効にして、staging のみで運用する構成に寄せてください。
- ⚠️ 設定は相互に制約しないため、どの OIDC 設定が一致したかに依存するロジックは作らないでください。

### リファレンス
- [Multiple trusted publishing configurations for npm](https://github.blog/changelog/2026-09-03-multiple-trusted-publishing-configurations-for-npm)

## GitHub Actions: Early September 2026 updates

**URL:** https://github.blog/changelog/2026-09-03-github-actions-early-september-2026-updates

### 要約
GitHub Actions に 3 つの更新が入りました。runner version の deprecation 期限を取得できる REST API が追加され、`GITHUB_TOKEN` に `vulnerability-alerts` 権限が使えるようになりました。さらに reusable workflow では、自分自身の定義元を識別する新しい `job` コンテキスト属性が利用できます。

### ユーザーにとって良いこと
runner の更新計画を事前に立てやすくなり、Dependabot alerts へのアクセスも最小権限で管理しやすくなります。reusable workflow 側から定義元を正しく判定できるため、複雑な再利用構成でも監査や分岐が安定します。

### アクションプラン
- runner バージョン管理のジョブを追加し、`GET /actions/runners/deprecations/{version}` で期限を定期取得してください。
- Dependabot alerts を読む必要がある workflow では、`permissions` に `vulnerability-alerts: read` を明示してください。
- reusable workflow で呼び出し元ではなく定義元を識別したい箇所を、`job.workflow_ref` などの新しい属性に置き換えてください。

## Upcoming deprecation of selected GitHub Copilot models

**URL:** https://github.blog/changelog/2026-09-03-upcoming-deprecation-of-selected-github-copilot-models

### 要約
Copilot 全体で、Gemini 3.5 Flash、Gemini 3.6 Flash、Kimi K2.7 Code、Claude Opus 4.7 が 2026-10-02 に非推奨になります。代替モデルとして Gemini 3.8 Flash、Kimi K3、Claude Opus 5 が案内されています。Business / Enterprise では、管理者がモデルポリシーで代替モデルの利用を有効化する必要があります。

### ユーザーにとって良いこと
利用中モデルの移行先が明示されているため、Copilot の会話、補完、agent などの体験を止めずに更新できます。組織管理者はポリシーを揃えることで、利用可能モデルのばらつきを減らせます。

### アクションプラン
- 2026-10-02 までに、Copilot の設定や自動化で使っているモデルを代替候補へ切り替えてください。
- Copilot Business / Enterprise の管理者は、組織または enterprise のモデルポリシーで代替モデルを有効化してください。
- ⚠️ 期限を過ぎると対象モデルは利用できなくなるため、モデル名を固定している workflow やスクリプトを先に更新してください。

### リファレンス
- [Upcoming deprecation of selected GitHub Copilot models](https://github.blog/changelog/2026-09-03-upcoming-deprecation-of-selected-github-copilot-models)

## GitHub CLI Linux package signing key expires September 5

**URL:** https://github.blog/changelog/2026-09-03-github-cli-linux-package-signing-key-expires-september-5

### 要約
GitHub CLI の Linux 向け APT / RPM リポジトリ署名鍵が 2026-09-05 に期限切れになります。以後は新しい鍵のみで署名されるため、古いセットアップを使い続けている環境では更新が必要です。Homebrew、Conda、Windows、macOS、直接の .deb/standalone binary には影響しません。

### ユーザーにとって良いこと
鍵の更新により、Linux パッケージの配布経路を安全に保てます。影響対象が限定されているため、自分の導入経路が対象かどうかを切り分けやすくなります。

### アクションプラン
- APT / RPM から `gh` を入れていて、2026-04-08 以前のセットアップのままなら、期限前に案内された keyring 更新手順を実施してください。
- 導入時期が不明な環境やカスタムイメージでは、現在の鍵信頼状態を確認してから更新してください。
- ⚠️ 2026-09-05 以降は旧鍵だけを信頼している環境で更新エラーが起きる可能性があるため、CI やベースイメージも合わせて確認してください。

### リファレンス
- [GitHub CLI Linux package signing key expires September 5](https://github.blog/changelog/2026-09-03-github-cli-linux-package-signing-key-expires-september-5)

- 既存の Business / Enterprise 管理者は、2026-10-01 以降の seat 前払いと追加請求の影響を予算に反映してください。
- ⚠️ seat を一度外してから再付与する運用は、更新された vetting と請求挙動を引き起こす可能性があるため、手順書を見直してください。

## CodeQL 2.26.4 improves GitHub actions security detections

**URL:** https://github.blog/changelog/2026-09-03-codeql-2-26-4-improves-github-actions-security-detections

### 要約
CodeQL 2.26.4 で Go 1.27 のサポートが追加され、Rust の alert location も改善されました。C#、Java/Kotlin、JavaScript/TypeScript、Python、GitHub Actions でも解析精度が上がっています。GitHub Actions では actor フィールドの扱いが厳密になり、`actions/unpinned-tag` も reusable workflow の mutable reference を検出します。

### ユーザーにとって良いこと
新しい言語機能への追従と誤検出の削減で、code scanning のノイズを減らしやすくなります。GitHub Actions のセキュリティ検出はより現実に近い条件で動くため、見落としと過検出の両方を抑えやすくなります。

### アクションプラン
- code scanning を使っている場合は CodeQL のバージョンを 2.26.4 系へ更新してください。
- Rust の alert 位置変更で既存 alert が新規扱いになる可能性を前提に、トリアージ計画を調整してください。
- ⚠️ GitHub Actions の detection ルール変更で alert 数が増える可能性があるため、CI のセキュリティレビュー手順を再確認してください。

### リファレンス
- [CodeQL 2.26.4 improves GitHub actions security detections](https://github.blog/changelog/2026-09-03-codeql-2-26-4-improves-github-actions-security-detections)
