## Require proof of presence for high-impact actions

**URL:** https://github.blog/changelog/2026-09-24-require-proof-of-presence-for-high-impact-actions

### 要約
GitHub Enterprise Cloud で、トークン作成、Webhook 編集、組織のセキュリティ設定変更、リカバリーコードの表示などの高影響操作を実行する前に、対話的な再認証または多要素認証（MFA）を必須にできる「proof of presence」が公開プレビューになりました。GitHub の sudo mode を Enterprise 向けに拡張したもので、現在は github.com または GHEC-DR 上の Microsoft Entra ID を SAML または OIDC の SSO IdP として利用する EMU Enterprise が対象です。

### ユーザーにとって良いこと
有効なセッションCookieや長期間有効な認証トークンが盗まれた場合でも、操作時点で実際の利用者が認証を満たさなければ高影響操作を完了できません。IdP 側のポリシーで MFA、デバイスコンプライアンス、再サインインなどを要求できるため、サプライチェーン攻撃への耐性と、機密操作で最新認証を求めるコンプライアンス対応を強化できます。

### アクションプラン
- 対象となる Enterprise 管理者は、Microsoft Entra ID を SAML または OIDC の SSO IdP として利用している EMU Enterprise が、対応範囲（github.com または GHEC-DR）に該当するか確認してください。これは現時点では公開プレビューで、全 Enterprise に自動適用される変更ではありません。
- GitHub の proof of presence 設定と Microsoft Entra ID の認証ポリシーを確認し、再認証または MFA、必要に応じてデバイスコンプライアンスを高影響操作に要求するよう構成してください。
- トークン作成、Webhook 編集、組織セキュリティ設定変更、リカバリーコード表示などの代表的な操作を、管理者とメンバーの実際の権限で検証してください。IdP チャレンジ完了後は、同じブラウザーセッションで2時間、追加の proof of presence なしに高影響操作を続行できます。
- ⚠️ プルリクエストのマージ前に proof of presence を要求する機能は近日提供予定です。現時点では既存のブランチ保護ルールやレビュー要件と併用してください。
