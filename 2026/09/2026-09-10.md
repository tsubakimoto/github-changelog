## Refreshed repository pull requests page in public preview

**URL:** https://github.blog/changelog/2026-09-10-refreshed-repository-pull-requests-page-in-public-preview

### 要約
リポジトリ単位の PR 一覧ページが刷新され、public preview として利用できるようになりました。絞り込みの補助、AND/OR を使った高度検索、折りたたみ可能なサイドバー、コンパクト表示、未読更新や status check 数などの追加コンテキストが含まれます。いくつかの機能は未対応で、従来表示へ戻すこともできます。

### ユーザーにとって良いこと
大量の PR から目的のものを見つけやすくなり、レビューやトリアージの速度が上がります。表示密度が高くなるため、同じ画面でより多くの作業対象を把握できます。

### アクションプラン
- repository の PR 運用を担うチームは、新しい一覧で必要なフィルタ条件を再確認してください。
- 高度検索を使う担当者は、AND / OR 条件を含む検索パターンを共有してください。
- ⚠️ Milestone、bulk update、保存済みカスタムビューはまだ未対応なので、既存運用で依存している場合は classic view との併用手順を残してください。

## AI Scan for pull request APIs in public preview

**URL:** https://github.blog/changelog/2026-09-10-ai-scan-for-pull-request-apis-in-public-preview

### 要約
organization と repository レベルで、AI Scan for pull requests の有効/無効を REST API から管理できるようになりました。public preview として、手動設定に頼らず複数リポジトリへ段階的に展開しやすくなっています。organization 側の設定が優先され、repository 側だけで無効状態を上書きすることはできません。

### ユーザーにとって良いこと
セキュリティ検査の導入と変更を自動化しやすくなり、運用のばらつきを減らせます。GitHub Advanced Security を使う組織では、対象 repo ごとの展開管理がしやすくなります。

### アクションプラン
- `/orgs/{org}/code-scanning/ai-scan` と `/repos/{owner}/{repo}/code-scanning/ai-scan` を使う自動化を作成し、対象リポジトリを一覧管理してください。
- organization レベルの許可状態を先に確定し、その上で repository ごとのオン/オフを制御してください。
- ⚠️ GitHub Enterprise Server は対象外なので、GHES 環境では代替の運用方針を維持してください。

## Control GitHub Actions cache access with cache-mode

**URL:** https://github.blog/changelog/2026-09-10-control-github-actions-cache-access-with-cache-mode

### 要約
GitHub Actions の cache access を workflow または job レベルで `cache-mode` により制御できるようになりました。`read`、`write`、`write-only`、`none` を指定でき、job レベルの設定が workflow レベルより優先されます。reusable workflow でも、呼び出し元以上の cache 権限は与えられません。

### ユーザーにとって良いこと
必要最小限の cache 権限だけを与えられるため、cache poisoning のリスクを下げやすくなります。trusted と low-trust のイベントで同じ workflow を使う場合でも、意図したアクセス境界を保ちやすくなります。

### アクションプラン
- `pull_request_target` など low-trust イベントで動く workflow は、`cache-mode: read` か `none` を明示してください。
- build / test job だけに cache 書き込みが必要な場合は、job 単位で `write` を付けて他の job からは外してください。
- ⚠️ `write` や `write-only` を低信頼イベントで有効にすると cache poisoning のリスクが上がるため、必要性を明文化してから適用してください。

## MAI-Code-1-Flash deprecated

**URL:** https://github.blog/changelog/2026-09-10-mai-code-1-flash-deprecated

### 要約
MAI-Code-1-Flash が GitHub Copilot の各体験で非推奨になりました。Copilot Chat、inline edits、ask / agent modes、code completions から順次利用対象外になります。代替として MAI-Code-1.1-Flash の利用が案内されています。

### ユーザーにとって良いこと
より新しいモデルへ移行することで、Copilot の応答品質や継続的なサポートを維持しやすくなります。管理者はモデルポリシーを見直すことで、組織全体の利用可能モデルを整理できます。

### アクションプラン
- Copilot のモデル設定で MAI-Code-1.1-Flash が利用できるか確認し、置き換えを進めてください。
- Copilot Enterprise 管理者は、model policy で代替モデルを有効化してください。
- ⚠️ deprecated になったモデルへ依存するワークフローや統合は、早めに更新してください。

### リファレンス
- [MAI-Code-1-Flash deprecated](https://github.blog/changelog/2026-09-10-mai-code-1-flash-deprecated)

## Xcode 27 runner image now runs on macOS 27

**URL:** https://github.blog/changelog/2026-09-10-xcode-27-runner-image-now-runs-on-macos-27

### 要約
GitHub-hosted macOS runners の Xcode 27 イメージが macOS 27 上で動作するようになりました。workflow の `runs-on` は `xcode-27` または `xcode-27-xlarge` のまま使えます。対象は arm64 の macOS runner に限られます。

### ユーザーにとって良いこと
Apple アプリを最新 macOS 環境で検証しやすくなり、将来の互換性確認が進めやすくなります。runner label を変えずに移行できるので、workflow 修正の手間も小さく済みます。

### アクションプラン
- iOS / macOS の CI を持つチームは、Xcode 27 runner を使ったジョブで macOS 27 互換性を確認してください。
- `runs-on` が `xcode-27` 系の workflow はそのまま使いつつ、必要な場合だけテスト対象 OS を見直してください。
- ⚠️ arm64 専用なので、x86_64 前提の検証が必要な場合は別 runner を併用してください。

### リファレンス
- [Xcode 27 runner image now runs on macOS 27](https://github.blog/changelog/2026-09-10-xcode-27-runner-image-now-runs-on-macos-27)
