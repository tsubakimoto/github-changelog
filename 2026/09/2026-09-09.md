## CodeQL 2.27.0 adds support for Linux ARM64

**URL:** https://github.blog/changelog/2026-09-09-codeql-2-27-0-adds-support-for-linux-arm64

### 要約
CodeQL 2.27.0 で Linux ARM64 ネイティブ実行が可能になり、Rust の新しいセキュリティクエリや Java/Kotlin、C# の解析対象拡張、複数言語の精度改善が追加されました。あわせて、GitHub code scanning の既定セットアップで private registry 設定を使えるようになり、build-mode: none の復元処理も改善されています。将来の非推奨項目として、Java 9/10 のサポート終了予定と、all-platforms の codeql.zip 配布廃止予告も含まれます。

### ユーザーにとって良いこと
ARM64 の Linux 環境でも CodeQL をそのまま使えるため、クラウド実行基盤や新しい開発環境への移行がしやすくなります。解析範囲と精度の改善により、見逃しを減らしつつ、より実運用に近いアラートを得やすくなります。

### アクションプラン
- Linux ARM64 で code scanning を運用している場合は、CodeQL CLI と bundle を per-platform の ARM64 配布物に切り替えてください。
- Rust、C#、Java/Kotlin を使うリポジトリでは、再スキャンを実行して新しいクエリやモデル化の恩恵を確認してください。
- ⚠️ Java 9/10 を対象にしている分析環境は、2027-01 までに Java 11 以降へ移行してください。
- ⚠️ codeql.zip の all-platforms 配布物に依存している場合は、将来廃止に備えて per-platform 配布物へ移行してください。

## Enterprise managed permissions for GitHub Copilot agent operations

**URL:** https://github.blog/changelog/2026-09-09-enterprise-managed-permissions-for-github-copilot-agent-operations

### 要約
Copilot Business / Enterprise の管理者が、エージェントの shell 実行、ファイル読み取り・編集、ネットワーク先を中央集権で制御できるようになりました。操作ごとに block、human approval、allow を分けて設定でき、ユーザーや workspace の設定よりも管理ポリシーが優先されます。GitHub Copilot app、Copilot CLI、Agent Host を使う VS Code セッションで利用可能です。

### ユーザーにとって良いこと
危険な操作だけを止めて、それ以外のエージェントワークフローは維持できるため、セキュリティと生産性の両立がしやすくなります。チームごとに異なる制約も定義できるので、開発部門や環境ごとのガバナンスを細かく合わせられます。

### アクションプラン
- 企業の Copilot 利用方針に合わせて、shell、file、network の各操作を block / approval / allow に分類してください。
- 機密リポジトリや本番相当の workspace では、ネットワーク先とファイル編集の制限を厳しめに設定してください。
- Copilot CLI や VS Code の Agent Host を使っているチームには、管理ポリシーが user/workspace 設定より優先されることを周知してください。

## GitHub Advanced Security expands trial availability

**URL:** https://github.blog/changelog/2026-09-09-github-advanced-security-expands-trial-availability

### 要約
GitHub Enterprise Cloud の self-serve GitHub Advanced Security trial が、最大 300 ライセンスの enterprise まで対象拡大されました。GitHub Code Security と GitHub Secret Protection を試せる範囲が広がり、評価導入しやすくなっています。試用の開始は Enterprise の Billing and licensing ページから行います。

### ユーザーにとって良いこと
これまで対象外だった中規模 enterprise でも、購入前に機能と運用負荷を確認できるようになります。セキュリティ機能の導入判断を、実際の組織条件に近い形で進めやすくなります。

### アクションプラン
- 100〜300 ライセンスの Enterprise Cloud 組織は、Billing and licensing から trial を開始して評価計画を立ててください。
- Secret Protection や Code Security の導入候補がある場合は、試用期間中にアラート量、運用フロー、権限設計を確認してください。

## Block pull requests with exposed secrets from merging

**URL:** https://github.blog/changelog/2026-09-09-block-pull-requests-with-exposed-secrets-from-merging

### 要約
repository rulesets に、PR が secret scanning alert を持ち込んだ場合にマージを止める新しいルールが追加されました。head commit の secret scan 完了と、PR で導入された secret の未解決アラートがないことを確認してからマージを許可します。public preview で、Secret Protection または GitHub Advanced Security を持つ顧客向けです。

### ユーザーにとって良いこと
push protection で取りこぼした secret も、PR レベルで追加ブロックできるようになります。レビュー前後のどちらで見つかってもマージを止められるため、漏えいリスクを下げながら運用できます。

### アクションプラン
- 機密情報を扱う repository や organization の ruleset に、Require secret scanning alerts are resolved を追加してください。
- まずは provider patterns を対象に有効化し、必要に応じて custom / generic patterns も含めるかを決めてください。
- ⚠️ これは push protection の代替ではなく補完です。push 側の設定と PR 側の ruleset を両方見直してください。

## Remediate Code Quality findings with agentic autofix

**URL:** https://github.blog/changelog/2026-09-09-remediate-code-quality-findings-with-agentic-autofix

### 要約
GitHub Code Quality の findings を、Copilot にまとめて割り当てて自動修正させる agentic autofix が使えるようになりました。1 ページで最大 25 件を選択して一括で assign でき、Copilot がブランチ上で修正・検証して PR を作成します。既存の enterprise policy に従って動き、追加の個別ポリシー管理は不要です。

### ユーザーにとって良いこと
コード品質のバックログを手作業で1件ずつ処理する負担が減り、改善の着手速度を上げられます。レビュー対象の PR まで自動でまとまるため、修正と確認の流れを標準化しやすくなります。

### アクションプラン
- GitHub Code Quality を有効にしている repository で、standard findings の大量処理に Assign to Copilot を試してください。
- 自動修正が AI credits を消費する点を踏まえ、適用範囲と実行タイミングをチームで決めてください。
- 既存の個別修正フローを使っている場合は、個別 findings の Generate fix から bulk remediation への移行手順を更新してください。

### リファレンス
- [Remediate Code Quality findings with agentic autofix](https://github.blog/changelog/2026-09-09-remediate-code-quality-findings-with-agentic-autofix)

## Enterprise-managed sandbox in Copilot for JetBrains

**URL:** https://github.blog/changelog/2026-09-09-enterprise-managed-sandbox-in-copilot-for-jetbrains

### 要約
Copilot for JetBrains に、enterprise-managed sandbox policies の public preview と、次の edit 提案での cross-file cursor jumps、global project context、policy diagnostics などの改善が入っています。さらに、GitHub Copilot CLI の /ide で JetBrains IDE へ接続し、選択範囲や診断、ファイル参照を共有できるようになりました。MCP サーバーや agent セッションの信頼性改善も含まれます。

### ユーザーにとって良いこと
IDE 側の制御と CLI 側の連携が強化され、より安全で文脈の通った Copilot 利用ができます。大きな変更をまたぐ編集や、管理ポリシーの確認がしやすくなるため、JetBrains 利用チームの作業効率と統制を両立しやすくなります。

### アクションプラン
- JetBrains を使う enterprise では、sandbox enablement、filesystem/network access、proxy、developer-tool access の managed policy を定義してください。
- /ide を使う Copilot CLI のワークフローを試し、IDE の選択範囲や診断がターミナル作業に正しく反映されるか確認してください。
- グローバルな project context や MCP 構成を使うチームは、共有設定と運用ルールを更新してください。

### リファレンス
- [Enterprise-managed sandbox in Copilot for JetBrains](https://github.blog/changelog/2026-09-09-enterprise-managed-sandbox-in-copilot-for-jetbrains)
