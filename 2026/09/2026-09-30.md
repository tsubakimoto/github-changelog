## Opt-in dist-tag permissions for npm trusted publishing

**URL:** https://github.blog/changelog/2026-09-30-opt-in-dist-tag-permissions-for-npm-trusted-publishing

### 要約
npm の trusted publishing 設定で、短期間有効な OIDC 認証情報を使って dist-tag（`latest`、`next`、`beta` など）を管理できるようになりました。各設定に **Allow npm dist-tag** 権限が追加され、既存・新規設定とも初期状態では無効です。公開やステージングの権限とは独立して付与できます。

### ユーザーにとって良いこと
リリース後のタグ更新やロールバックでも長期間有効なアクセストークンを保持する必要がなくなり、OIDC ベースのトークンレスな npm ワークフローを完成できます。権限を設定単位で明示的に有効化できるため、dist-tag を操作できるワークフローを最小限に制限できます。

### アクションプラン
- パッケージの trusted publishing 設定を開き、dist-tag を管理する設定で **Allow npm dist-tag** を有効にする。
- リリース後のタグ更新やロールバックを行う CI ワークフローが、対象の trusted publishing 設定と OIDC トークンを使用していることを確認する。
- ⚠️ この権限は新規・既存の設定で自動的には有効にならない。不要な設定には付与せず、既存のトークンベースの管理を継続する場合は変更しない。

## GitHub Advanced Security trials for GitHub Team

**URL:** https://github.blog/changelog/2026-09-30-github-advanced-security-trials-for-github-team

### 要約
GitHub Team の顧客が、GitHub Advanced Security のセルフサービス試用を開始できるようになりました。試用では GitHub Code Security と GitHub Secret Protection を評価できます。組織の **Overview** ページ、**Billing and licensing > Licensing** ページ、またはリスク評価完了ページから開始できます。

### ユーザーにとって良いこと
追加購入や個別の問い合わせを行わずに、Team プランの組織でコードの脆弱性検出やシークレット保護の効果を実際の開発プロセスで評価できます。導入前にチームの運用要件や検出結果を確認し、Advanced Security の適用範囲を判断しやすくなります。

### アクションプラン
- GitHub Team の組織管理者は、組織の **Overview**、**Billing and licensing > Licensing**、またはリスク評価完了ページで試用開始の導線を確認する。
- 試用前に対象リポジトリ、コードスキャン・シークレットスキャンの運用担当者、評価期間中に確認する指標を決める。
- 試用中に検出結果の対応フロー、誤検知、必要なライセンス範囲を確認し、本導入の判断材料を記録する。

## HydraFusion in VS Code and the GitHub Copilot app

**URL:** https://github.blog/changelog/2026-09-30-hydrafusion-in-vs-code-and-the-github-copilot-app

### 要約
HydraFusion のリサーチプレビューが Copilot CLI に加えて Visual Studio Code と GitHub Copilot app でも利用できるようになりました。単一モデルではなく、単一実行・カスケード・批評という3種類のワークフローから、推論・コード生成・デバッグ・ツール利用の能力信号に基づいて効率的な実行方法を選びます。進行状況の表示や処理中のステータスも改善されています。

### ユーザーにとって良いこと
複雑な作業で複数モデルを組み合わせた実行を自動化でき、品質基準を保ちながら効率のよいモデル構成を試せます。処理の各段階や長時間タスクの進捗が見えやすくなり、Copilot が動作中かどうかを把握しやすくなります。

### アクションプラン
- VS Code ではバージョン 1.140 以降または VS Code Insiders に更新し、Copilot Chat のモデルピッカーから HydraFusion を選択する。表示されない場合は `chat.copilot.hydraFusion.enabled` を有効にする。
- GitHub Copilot app では最新版へ更新し、Settings で HydraFusion を有効にしてモデルピッカーから選択する。
- Copilot Business または Enterprise では、管理者が組織またはエンタープライズ設定でプレビュー機能を許可していることを確認する。
- ⚠️ HydraFusion はリサーチプレビューであり、Copilot Pro、Pro+、Business、Enterprise が対象。仕様や提供条件が変更される可能性を踏まえて、本番作業への依存を避けて評価する。

- [HydraFusion in VS Code and the GitHub Copilot app](https://github.blog/changelog/2026-09-30-hydrafusion-in-vs-code-and-the-github-copilot-app)

## X25519-only TLS ends for GHE.com on October 7

**URL:** https://github.blog/changelog/2026-09-30-x25519-only-tls-ends-for-ghe-com-on-september-15

### 要約
2026年10月7日から、データレジデンシー対応の GitHub Enterprise Cloud は、鍵共有に X25519 だけを提示するクライアントからの TLS 接続を受け付けなくなります。影響を受けるエンドポイントでは、FIPS 承認済みの P-256（`secp256r1`）と P-384（`secp384r1`）が引き続き利用できます。通常のブラウザー、OS、GitHub CLI、TLS ライブラリはすでに P-256 に対応しています。

### ユーザーにとって良いこと
現行の一般的なクライアントはそのまま接続できるため、多くの利用者に変更はありません。X25519 のみを強制するアプリケーションやプロキシを事前に特定して設定を更新することで、適用後の HTTPS 接続障害を防げます。

### アクションプラン
- GitHub Enterprise Cloud with data residency へ接続するアプリケーション、プロキシ、セキュリティアプライアンス、TLS ライブラリの設定を確認し、X25519 のみを提示する構成を特定する。
- 2026年10月7日までに OS、ランタイム、GitHub CLI、プロキシ、TLS ライブラリを対応バージョンへ更新し、P-256（`secp256r1`）を有効にする。必要に応じて P-384（`secp384r1`）も有効にする。
- ⚠️ 期限後は X25519 のみを提示するクライアントが HTTPS 接続できなくなる。対象はデータレジデンシー対応の GitHub Enterprise Cloud のみで、SSH 接続には影響しない。
