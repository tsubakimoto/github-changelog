## Enforce GitHub Advanced Security configurations

**URL:** https://github.blog/changelog/2026-09-15-enforce-github-advanced-security-configurations

### 要約
Enterprise 管理者が、組織やリポジトリをまたいで GitHub Advanced Security の設定を強制できるようになりました。これにより、エンタープライズで定義したセキュリティ設定を org / repo 管理者が上書きできなくなり、ポリシーを一貫して適用しやすくなります。従来はリポジトリ所有者への制限が中心でしたが、今回の更新で適用範囲が広がりました。

### ユーザーにとって良いこと
セキュリティとコンプライアンスの基準を、組織ごとの運用差に左右されずに統一できます。大規模な Enterprise ほど、設定のばらつきを抑えて監査対応や標準化を進めやすくなります。

### アクションプラン
- 既存の security configuration を確認し、エンタープライズ標準として固定したいものは `Enforce for repository and organization owners` に切り替えてください。
- org / repo 管理者向けに、エンタープライズ側で強制された設定は上書きできないことを周知してください。
- 監査・コンプライアンスの手順書に、Enforcement の選択肢と運用ルールを追記してください。

## GitHub Copilot suggests custom properties definitions

**URL:** https://github.blog/changelog/2026-09-15-github-copilot-suggests-custom-properties-definitions

### 要約
GitHub Copilot が、組織のリポジトリ向け custom property 定義を作成するときに、許可値の候補を提案するようになりました。GitHub Copilot Business / Enterprise 向けの public preview で、Enterprise もしくは Organization の管理者が使えます。提案は property の種類に応じて変わり、たとえば `FedRAMP` や `internet-facing` のような実用的な候補を素早く選べます。

### ユーザーにとって良いこと
custom properties の設計をゼロから考える手間が減り、rulesets の対象指定に使うメタデータを早く整備できます。大きなリポジトリ群でも、命名や値の揺れを抑えて governance を進めやすくなります。

### アクションプラン
- custom properties を rulesets のスコープ指定に使っている場合は、まず小さな範囲で Copilot の候補提案を試してください。
- `Repository custom property suggestions Copilot` policy の有効化範囲を確認し、必要に応じて Enterprise / Organization 単位で制御してください。
- 受け入れた値が運用ルールと一致しているかをレビューし、既存の property 命名規則を更新してください。

## SHA-1 in HTTPS on GitHub sunset

**URL:** https://github.blog/changelog/2026-09-15-sha-1-in-https-on-github-sunset

### 要約
予定どおり、GitHub は github.com と partner CDN で HTTPS 経由の SHA-1 を無効化しました。GitHub Enterprise Cloud と Data Residency 付きの GitHub Enterprise Cloud も対象で、GitHub Enterprise Server は影響を受けません。旧告知で案内されていた sunset が実施された形です。

### ユーザーにとって良いこと
弱いハッシュアルゴリズムへの依存を減らし、HTTPS 接続のセキュリティを高められます。GitHub 側の挙動が明確になることで、今後の運用はより安全な前提で統一できます。

### アクションプラン
- GHEC / Data Residency を利用している場合は、SHA-1 前提の古いクライアント、プロキシ、TLS 中間装置が残っていないか確認してください。
- Git 取得、Webhook、API 連携、証明書検証を行う自動化が失敗していないか、エラー率と接続ログを点検してください。
- もし SHA-1 依存が残っているなら、即時に更新計画を立て、影響範囲を利用者へ周知してください。
