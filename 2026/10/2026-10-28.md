## Route and orchestrate models with GitHub Copilot Fusion

**URL:** https://github.blog/changelog/2026-10-28-route-and-orchestrate-models-with-github-copilot-fusion

### 要約
GitHub Copilot Fusion が一般提供され、タスクごとに適したモデルを自動選択し、必要に応じて複数モデルを連携させる機能が追加されました。Standard、High、Max の作業強度を選べるほか、管理者は利用可能なモデルや既定モデルを制御できます。Fusion の利用料は選択された各モデルの標準料金で計算され、期間限定で有料プランにはモデル料金の 30% 割引が適用されます。

### ユーザーにとって良いこと
作業ごとにモデルを選び直す手間を減らし、日常的な作業から複雑な推論まで性能とコストのバランスを自動で調整できます。管理者は組織で許可したモデルの範囲内で運用できます。

### アクションプラン
- VS Code、GitHub Copilot app、Copilot CLI、JetBrains IDE を更新し、モデルピッカーで Copilot Fusion と目的に合う作業強度を選択してください。利用可能なクライアントでの一般提供機能です。
- Enterprise 管理者は、モデルポリシーで Fusion が利用できるモデルを確認し、必要に応じて Enterprise managed settings で既定モデルを設定してください。
- 各モデルの利用料が発生するため、AI 利用予算を確認してください。30% 割引は有料プラン向けの期間限定です。

## GitHub Copilot app, Universe releases

**URL:** https://github.blog/changelog/2026-10-28-github-copilot-app-universe-releases

### 要約
GitHub Copilot app に Projects がパブリックプレビューとして追加され、複数リポジトリや Slack、Figma、会議メモなどのコンテキストをまとめ、複数エージェントにまたがる作業を管理できます。また、チャットから自然言語で画像を生成・編集できる機能と、macOS・Windows のデスクトップアプリを操作する Computer use がプレビューで利用可能になりました。Computer use ではアプリ操作前にユーザーの承認が必要で、組織は管理設定で無効化できます。

### ユーザーにとって良いこと
複数プロジェクトに関わる調査や計画を一か所で進め、デザインや会話の情報も作業に活用できます。画像作成やデスクトップアプリの操作による作業も Copilot app 内で依頼できます。

### アクションプラン
- Copilot Projects を試す場合はアプリを更新し、プロジェクトを作成して関連リポジトリや設計資料などのコンテキストを追加してください。パブリックプレビューです。
- Computer use を利用する場合は Settings > Computer Use で有効化してください。macOS では Accessibility と Screen Recording の権限が必要です。操作ごとに承認が必要で、Organization 管理者は managed settings で利用を制限できます。
- 接続ツールやデスクトップアプリのデータをエージェントに渡す前に、共有範囲と権限を確認してください。

## GitHub Enterprise now includes access to GitHub Copilot

**URL:** https://github.blog/changelog/2026-10-28-github-enterprise-now-includes-access-to-github-copilot

### 要約
GitHub または Microsoft のアカウントチームと契約している Enterprise は、ライセンスを持つユーザーに GitHub Enterprise の一部として Copilot を提供できるようになりました。Copilot の利用は最初のリクエストから Enterprise 予算に計上され、座席ごとの月間 AI クレジットは含まれません。セルフサービス契約への提供は段階的に開始予定で、既存の契約や Copilot Business・Copilot Enterprise の提供には影響しません。

### ユーザーにとって良いこと
Enterprise のライセンスユーザーに Copilot をまとめて提供し、従来の Copilot 座席数ではなく Enterprise 予算を中心に利用量を管理できます。予算がなくなっても座席とコード補完・次の編集候補は維持されますが、Copilot Chat、コードレビュー、クラウドエージェントには利用可能な予算が必要です。

### アクションプラン
- GitHub または Microsoft のアカウントチームと契約している Enterprise は、営業担当者に新規導入または既存アカウントの移行を相談してください。セルフサービス契約は現時点で対象外で、利用可能になるまで既存プランを維持してください。
- 管理者は Enterprise の AI 利用予算、ポリシー、アラート、利用量の帰属設定を確認してください。機能ごとの予算要件もユーザーに周知してください。
- GitHub Enterprise ライセンスのない Enterprise ユーザーは Copilot Standalone の対象となり、ユーザーあたり月額 $10 です。必要なライセンス構成を確認してください。

## Security extension for the GitHub Copilot app

**URL:** https://github.blog/changelog/2026-10-28-security-extension-for-the-github-copilot-app

### 要約
GitHub Copilot app の GitHub security extension がパブリックプレビューとなり、リポジトリの code scanning アラートを一覧・検索し、Copilot に説明や修正を依頼できます。修正はローカルの作業コピーにのみ適用され、自動でコミットやプッシュはされません。現在の変更に対する `/security-review` も実行でき、既存アラートと並べて結果を確認できます。

### ユーザーにとって良いこと
アラート確認から修正案の作成までを Copilot app 内で行い、ツール間の切り替えを減らせます。変更をコミット・プッシュする前にローカルでレビューや反復ができます。

### アクションプラン
- Copilot CLI で `copilot plugin install github-security@awesome-copilot` を実行するか、Copilot app の Customize から `github-security` をインストールしてください。パブリックプレビューで、GitHub Enterprise Server は対象外です。
- 組織の Copilot Business / Enterprise 利用者は、管理者に GitHub Copilot app ポリシーとプラグイン制御の設定を確認してください。
- アラートの表示には code scanning が有効であることと閲覧権限が必要です。プライベートリポジトリでは GitHub Code Security が必要です。Copilot の説明・修正や `/security-review` は AI クレジットを消費します。

## GitHub intelligence puts your code, context, and history to work

**URL:** https://github.blog/changelog/2026-10-28-github-intelligence-puts-your-code-context-and-history-to-work

### 要約
GitHub intelligence により、Copilot がチームの知識や開発履歴を活用する機能が拡張されました。Copilot Memory は有料プランで一般提供となり、個人の好みやリポジトリの規約をセッション間で利用できます。過去の作業からメモリやカスタマイズを継続的に改善する Copilot dreaming はオプトインのパブリックプレビューで、GitHub code search はチェックアウト外の関連リポジトリも検索してエージェントに文脈を提供します。

### ユーザーにとって良いこと
同じ指示やリポジトリのルールをセッションごとに繰り返す手間を減らし、チームの既存パターンに沿った提案を得やすくなります。関連リポジトリを横断してコードや履歴を探せるため、複数サービスにまたがる調査や変更計画も進めやすくなります。

### アクションプラン
- Copilot Memory を利用する場合は、Copilot app、CLI、VS Code などでメモリを確認し、Copilot settings から個人メモリを閲覧・削除してください。Memory は有料 Copilot プランで一般提供されています。
- Dreaming を試す場合は、個人設定と対象リポジトリの設定でオプトインしてください。Organization / Enterprise では管理者ポリシーが必要で、実行には AI クレジットを消費します。生成・更新されるメモリを確認してください。
- 横断検索で利用できるリポジトリの範囲を管理者設定で確認し、複数リポジトリにまたがる調査には Copilot の `/research` を活用してください。利用可能な機能や設定は機能ごとに異なります。

## Build shared workflows for your team with Copilot Automations

**URL:** https://github.blog/changelog/2026-10-28-build-shared-workflows-for-your-team-with-copilot-automations

### 要約
Copilot Automations の共有機能が段階的に提供され、チームで AI ワークフローを作成・編集できるようになります。共有オートメーションはリポジトリに属し、閲覧権限を持つメンバーが参照し、書き込み権限を持つメンバーが編集できます。AI クレジットは作成者ではなくリポジトリ所有者に請求され、GitHub 上の操作は Copilot 名義で記録されます。

### ユーザーにとって良いこと
作成者がチームを離れてもワークフローがリポジトリに残り、チームで継続的に保守できます。ツール、トリガー、プロンプトの変更履歴も確認でき、チーム共通の繰り返し作業を自動化できます。

### アクションプラン
- Copilot Pro、Pro+、Max、Business、Enterprise の対象ユーザーは、利用可能になったら github.com、Copilot app、または VS Code でオートメーション作成時に `Shared` を選択してください。作成後に個人用・共有の種別は変更できません。
- Organization 所有リポジトリで実行する場合は、管理者に「Allow use of Copilot cloud agent billed to the organization」ポリシーの有効化を依頼してください。
- オーナーはリポジトリの AI クレジット消費と、Copilot 名義で実行される操作を確認してください。利用可能時期は段階的なロールアウトにより異なります。

## GitHub Copilot in VS Code, Universe releases

**URL:** https://github.blog/changelog/2026-10-28-github-copilot-in-vs-code-universe-releases

### 要約
VS Code の Copilot で、クラウドエージェントの開始・継続を VS Code、Copilot app、GitHub Mobile、github.com、Copilot CLI 間で行えるようになり、VS Code を閉じても作業を継続できます。Agent Host によるウィンドウ間・リモートマシンでのセッション継続、モデル結果の並列比較、Customizations Marketplace、Copilot connectors なども追加・拡張されました。Computer use やマーケットプレイス、コネクターなど一部機能はプレビューまたは実験的機能で、管理者ポリシーによる制御にも対応します。

### ユーザーにとって良いこと
複数クライアントや開発マシンをまたいで同じ作業を続けられ、ローカル環境に常時張り付かずにエージェントを活用できます。モデルや拡張機能、外部サービスのコンテキストを用途に応じて使い分けられます。

### アクションプラン
- クラウドセッションを使う場合は VS Code の Agents window から開始し、対応する Copilot クライアントで同じセッションを再開してください。リモート Agent Host を使う場合は接続先マシンと Agent Host の稼働を維持してください。
- 自分の開発マシン上のエージェントを GitHub Mobile から操作するには、そのマシンのプロジェクトで `code agent host --github-environment` を実行してください。マシンと Agent Host が停止すると操作できません。
- Computer use、Marketplace、connectors、モデル比較などのプレビューを有効にする前に、VS Code の設定とデータアクセス範囲を確認してください。組織では Editor preview features や Enterprise managed settings のポリシーが適用される場合があります。
- 管理者はプラグインの許可・ブロック、マーケットプレイスの登録、承認済みソースからのインストール制限を確認してください。`.github/copilot/settings.json` の設定は既定値であり、Enterprise ポリシーのような強制制御ではありません。

## Generate and edit images directly in Copilot

**URL:** https://github.blog/changelog/2026-10-28-generate-and-edit-images-directly-in-copilot

### 要約
Copilot のチャットから自然言語で画像を生成・編集し、結果をインラインでプレビューしてワークスペースに保存できる機能がパブリックプレビューとして追加されました。画像生成には専用ツールが使われ、チャットモデルとは別に画像トークンに基づいて AI クレジットが請求されます。Organization と Enterprise の管理者はモデルポリシーで画像生成を無効化でき、生成画像への「Made with AI」透かしは任意で有効化できます。

### ユーザーにとって良いこと
別の画像生成ツールへ切り替えたり、生成した画像を手動でプロジェクトに取り込んだりせず、コーディングの文脈を保ったまま視覚素材を作成できます。

### アクションプラン
- VS Code、GitHub Copilot app、または Copilot CLI のチャットで画像を説明して試してください。パブリックプレビューの対象は Copilot Pro、Pro+、Business、Enterprise です。
- 利用前に画像トークン分の AI クレジット消費を確認し、必要なら管理者が Copilot モデルポリシーで画像生成を無効化してください。
- 透かしを付ける運用が必要な場合は、生成・編集画像の「Made with AI」表示を有効にしてください。初期状態ではオフです。

## GitHub Copilot Fusion now supports selection of local models

**URL:** https://github.blog/changelog/2026-10-28-github-copilot-fusion-now-supports-selection-of-local-models

### 要約
Copilot Fusion がローカルモデルとクラウドモデルを選択する機能が、オプトインの実験的プレビューとして Copilot CLI、Copilot app、VS Code に追加されました。対応する Windows 環境では Windows ML 経由で MAI Code 1.1 Flash を管理ダウンロードでき、CLI では Windows、macOS、Linux 上の OpenAI 互換ローカルサーバーも利用できます。Copilot app の自動ルーティングは現在、管理された Windows ML モデルに限られます。

### ユーザーにとって良いこと
対応タスクでローカルモデルを利用でき、毎回手動でモデルを切り替えずに端末の計算資源を活用できます。管理ダウンロードに対応する Windows 端末ではモデルの導入・設定も簡素化されます。

### アクションプラン
- 実験機能を有効にして、Windows では各クライアントの Windows ML 設定からモデルを準備し、Copilot Fusion の Standard を選択してください。Copilot CLI は `/model` のセットアップ案内を利用できます。
- 手動設定のローカルモデルを使う場合は、CLI で対応する OpenAI 互換サーバーとモデルを用意し、実験的なローカルルーティングを有効にしてください。BYOK でモデルを追加しただけでは Fusion のルーティング対象になりません。
- ローカル推論でもルーティング判断にはクラウド接続が必要です。端末要件、モデルごとの安全保護の違い、ローカル環境のデータ取り扱いを事前に確認してください。

## GitHub Agentic Workflows generally available

**URL:** https://github.blog/changelog/2026-10-28-github-agentic-workflows-generally-available

### 要約
GitHub Next のオープンソースプロジェクト GitHub Agentic Workflows が一般提供となり、自然言語の Markdown で issue のトリアージ、CI 失敗の分析、ドキュメント更新、テスト作成などの推論を伴う自動化を定義できます。ワークフローは標準的な GitHub Actions YAML に変換され、既存の Runner グループやポリシー制約を利用できます。読み取り専用権限を既定とし、サンドボックス実行、出力検証、脅威検出などの多層保護が組み込まれています。

### ユーザーにとって良いこと
既存の Actions 環境を活用しながら、ルールベースの記述だけでは扱いにくい調査・分析・変更提案を自動化できます。Copilot または別のコーディングエージェントを選択でき、セルフホスト ARC ランナーなどにも対応します。

### アクションプラン
- GitHub Agentic Workflows のクイックスタートに従って CLI 拡張を導入し、まずはトリアージやレポートなど限定したワークフローを試してください。GitHub Free、Team、Enterprise の github.com で一般提供されています。
- ワークフローの権限、Runner グループ、サンドボックス、出力検証、脅威検出の設定を確認し、提案変更を適用する前にレビューする手順を整えてください。
- 既定の GitHub Copilot CLI エンジンを使う場合は Copilot ライセンスが必要です。AI クレジットの見積もりには `gh aw forecast` を利用してください。
