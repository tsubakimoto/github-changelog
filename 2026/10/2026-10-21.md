## GitHub CLI: Opt in to expiring, auto-refreshing OAuth tokens

**URL:** https://github.blog/changelog/2026-10-21-github-cli-opt-in-to-expiring-auto-refreshing-oauth-tokens

### 要約
GitHub CLI v2.103.0 から、期限付きアクセストークンとローテーションするリフレッシュトークンを使う認証にオプトインできます。`gh` は必要に応じてトークンを自動更新するため、通常の CLI 利用時に再認証は不要です。期限付き認証はパブリックプレビューで、現時点では明示的に有効化した場合のみ適用されます。

### ユーザーにとって良いこと
アクセストークンが漏えいしても数時間で無効になるため、長期間有効な認証情報を使う場合よりリスクを抑えられます。`gh` に認証更新を任せることで、日々の操作を続けながらトークンを新しい状態に保てます。

### アクションプラン
- GitHub CLI v2.103.0 以降で利用する場合は、ログイン時に `gh auth login --expiring` を指定してください。以後のログインでも有効にするには `gh config set expiring_credentials enabled` を実行します。どちらも明示的なオプトインであり、設定しなければ既存の認証動作は変わりません。
- HTTPS で Git を利用する場合は `gh auth setup-git` で `gh` を Git の credential helper に設定し、期限付き認証を正しく更新できるようにしてください。Git 2.46 以降へのアップグレードも推奨されます。
- `gh auth token` の値を保存・再利用するスクリプトや拡張機能は、期限切れトークンを使わないよう都度 `gh auth token` を実行して最新の値を取得してください。トークンの長期有効性を前提とするワークフローでは、対応できるまでオプトインを見合わせてください。
- github.com と ghe.com で利用できます。GitHub Enterprise Server は 3.23 以降で発行され、それ以前では通常の非期限付きトークンにフォールバックします。サーバーが期限付き認証に対応しない場合も同様にフォールバックします。
