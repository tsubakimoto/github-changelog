## Custom skills, agents, and MCP servers in usage metrics API

**URL:** https://github.blog/changelog/2026-10-22-custom-skills-agents-and-mcp-servers-in-usage-metrics-api

### 要約
Copilot 使用状況メトリクス API で、組織が作成したスキル、カスタムエージェント、MCP サーバー、スラッシュコマンド、プラグインの利用状況が、`other` や `custom` ではなく設定名で表示されるようになりました。各 `totals_by_*` 配列に含まれる項目数も最大 5 件から 25 件に増え、残りは `other` に集約されます。

### ユーザーにとって良いこと
組織独自の Copilot カスタマイズがどの程度使われているかを把握しやすくなり、導入後の定着状況や追加の支援が必要な領域を評価できます。利用数の計算方法は変わりませんが、名前の報告はリリース後に処理された日から始まり、過去のレポートには反映されません。

### アクションプラン
- Copilot 使用状況メトリクス API のレポートで、`totals_by_skill`、`totals_by_custom_agent`、`totals_by_mcp`、`totals_by_slash_cmd`、`totals_by_plugin` の名前付き項目を確認し、社内ツールの利用状況や導入施策の効果を評価してください。
- 名前は設定値のまま報告され、最大 128 文字に切り詰められます。レポートを組織外に共有する前に、内部情報を含む名前がないか確認してください。ファイルパスに見える名前は `other` または `custom` にまとめられます。
- 正確な集計が必要な場合は、Copilot CLI を 1.0.97 以降（Copilot SDK は 1.0.21 以降）に更新し、テレメトリが有効な状態で利用してください。数値はクライアントテレメトリに基づくため、厳密な会計ではなく傾向把握に使用してください。
- レポートの閲覧には Copilot 使用状況メトリクスポリシーの有効化と「View Copilot Metrics」権限が必要です。名前の表示には管理者による追加設定は不要です。

## Global default for Copilot features generally available

**URL:** https://github.blog/changelog/2026-10-22-global-default-for-copilot-features-generally-available

### 要約
Copilot Business および Copilot Enterprise で、一般提供中の対象機能と対応クライアント機能に対するグローバル既定ポリシーの適用が始まりました。10 月 26 日まで段階的に反映され、未設定の対象機能は選択された既定値（有効、無効、または組織に委任）に一度だけ設定されます。個別に明示設定済みの機能やプレビュー機能のオプトイン状態は維持されます。

### ユーザーにとって良いこと
新しい一般提供機能の既定動作を組織全体で統一でき、管理者が機能ごとに未設定項目を手動で決める負担を減らせます。適用後にグローバル既定を変更しても、すでに設定された機能のポリシーは変更されません。

### アクションプラン
- GitHub の **AI Controls → Copilot → Default policy for new features** で現在のグローバル既定を確認し、未設定の一般提供機能を有効、無効、または組織ごとの判断に委ねる設定のどれにするか決めてください。
- 「Features & clients」と「MCP servers in Copilot」で未設定の対象項目を確認してください。適用は 10 月 26 日まで段階的に行われるため、組織や Enterprise ごとに反映時期が異なる場合があります。
- 個別機能の設定を維持したい場合は、ロールアウト前に明示的に有効または無効を選択してください。プレビュー機能は引き続きオプトインで、既にオプトインしている機能の選択も保持されます。
- この変更は対象の未設定項目への一度限りの適用です。グローバル既定を後から変えても、既に設定された機能には遡及適用されません。

## Meta API endpoints updated for Actions blob storage

**URL:** https://github.blog/changelog/2026-10-22-meta-api-endpoints-updated-for-actions-blob-storage

### 要約
GitHub Actions の容量と信頼性向上のため、github.com の Actions blob storage に新しいホストが追加され、Meta API のエンドポイント一覧に含まれました。個別ホストでネットワーク許可リストを管理している場合、追加ホストを許可しないとジョブのサマリーやログに影響する可能性があります。

### ユーザーにとって良いこと
新しいストレージエンドポイントを事前に許可することで、ネットワーク制限のある環境でも Actions のジョブサマリーやログへのアクセスを継続できます。ワイルドカードで `productionresultssa*.blob.core.windows.net` を許可済みの場合、追加対応は不要です。

### アクションプラン
- GitHub Actions blob storage への通信に個別ホストの許可リストを使っている場合、次の範囲のホストを許可してください: `productionresultssa30.blob.core.windows.net`～`productionresultssa49.blob.core.windows.net` および `productionresultssa100.blob.core.windows.net`～`productionresultssa199.blob.core.windows.net`。
- `productionresultssa*.blob.core.windows.net` を既に許可している場合、この追加に対する変更は不要です。
- 固定のホスト一覧を運用している場合は、REST API の Meta エンドポイントから最新一覧を取得する手順を確認し、今後のエンドポイント変更にも追随できるようにしてください。

## Public monitoring now available with data residency

**URL:** https://github.blog/changelog/2026-10-22-public-monitoring-now-available-with-data-residency

### 要約
GitHub Enterprise Cloud with data residency（GHEC DR）で、パブリックコミットに含まれる漏えい認証情報を監視する「Public monitoring」がパブリックプレビューとして利用可能になりました。データレジデンシー環境では、Enterprise が検証済みのドメインとの照合だけでコミット作成者を特定し、アラートを指定リージョン内のダッシュボードへ暗号化して届けます。

### ユーザーにとって良いこと
内部リポジトリだけでなく github.com 上の公開コミットも監視対象にでき、Enterprise に関連する認証情報の漏えいをより早く把握できます。テナント間のメンバー情報共有を行わずにアラートを配信し、利用料金は既存ライセンスに含まれます。

### アクションプラン
- GHEC with data residency を利用し、GitHub Advanced Security または GitHub Secret Protection の有効なライセンスがある場合、Enterprise のセキュリティ設定で Public monitoring を有効化するか検討してください。機能はパブリックプレビューです。
- Enterprise 管理者または Enterprise セキュリティマネージャーは、有効化前に Enterprise が使用するドメインの検証状況を確認してください。データレジデンシー環境での照合には検証済みドメインが必要です。
- Public monitoring はオプトインです。対象ライセンスがあれば追加料金はありませんが、ライセンスがない場合は利用条件を満たすか確認してください。

## Pull requests: Saved whitespace preferences and improved split view

**URL:** https://github.blog/changelog/2026-10-22-pull-requests-saved-whitespace-preferences-and-improved-split-view

### 要約
Pull request の「Files changed」ページで、空白変更の表示設定を Pull request 間で保存できるようになりました。また、分割表示では新規・削除ファイルが左右 2 列全体を使って表示され、レビュー時の表示領域が広がります。

### ユーザーにとって良いこと
空白差分を常に表示するか隠すかを一度設定すれば、以後のレビューにも個人設定として適用できます。新規・削除ファイルは折り返しが減り、分割表示でも読みやすくなります。

### アクションプラン
- 空白差分の表示をカスタマイズする場合は **Settings → Whitespace changes** で **Always show**、**Always hide**、または **Hide for this diff only** を選んでください。保存設定は個人に適用されます。
- 保存した設定を変更せずに一時的に空白を表示するには、差分上部の **Hide whitespace** フィルター横にある **X** を選択してください。
- 新規・削除ファイルの分割表示を確認してください。表示差分に応じてファイル数と差分統計も変わります。

## Industry comparisons in the Copilot impact dashboard

**URL:** https://github.blog/changelog/2026-10-22-industry-comparisons-in-the-copilot-impact-dashboard

### 要約
Copilot impact dashboard に、参加企業の集計ベンチマークと比較できる「Industry comparison」が追加されました。Agent-first／multi-agent のユーザー割合や、エージェント利用者と非利用者の Pull request マージ率を、企業規模や業種別の同業他社と比較できます。

### ユーザーにとって良いこと
自組織の Copilot 活用度を同規模・同業種の傾向と照らし合わせ、現実的な目標設定や導入ギャップの把握に役立てられます。ベンチマークは識別情報を含まず、30 日後に削除されます。データレジデンシー利用企業は同じリージョンの参加企業とのみ比較されます。

### アクションプラン
- Enterprise のオーナー、または Enterprise に属さない Organization のオーナーは、Copilot impact dashboard または Copilot ポリシーから参加をオプトインしてください。参加は初期状態で無効です。Enterprise 所有の Organization は Enterprise を通じて参加します。
- 参加前に Copilot 使用状況メトリクスポリシーが有効であることを確認してください。ダッシュボードからオプトイン／オプトアウトすると、同じポリシーが適用されます。
- 比較結果を使う際は、参加企業数が少ない場合に中央値だけが表示されたり、選択した業種より広い比較グループが使われたり、ランキングが表示されなかったりする点に留意してください。比較は毎日更新されます。
- オプトアウトすると比較表示は直ちに停止し、データは次回の日次更新から集計対象外になります。誰でも結果を閲覧できるため、共有範囲も確認してください。
- 比較データは dashboard のみで利用できます。Copilot usage metrics API、NDJSON エクスポート、ダウンロードには含まれません。
