## Triage role users or higher can now archive pull requests

**URL:** https://github.blog/changelog/2026-10-08-triage-role-users-or-higher-can-now-archive-pull-requests

### 要約
リポジトリの Triage 権限以上を持つユーザーが、プルリクエストをアーカイブおよびアーカイブ解除できるようになりました。アーカイブするとPRは自動的にクローズされ、コメント・リアクション・自動コメントを含む新しい活動が禁止されます。アーカイブ解除後もPRは再オープンされません。

### ユーザーにとって良いこと
コードを変更する権限を与えずに、信頼できるトリアージ担当者へスパムや重複、放置されたPRの整理を委任できます。アーカイブ中の会話が完全に読み取り専用になるため、管理者以外がアーカイブ後にコメントを追加することも防げます。

### アクションプラン
- リポジトリ管理者は、PRの整理を委任する担当者に Triage 権限を付与するか検討してください。Triage、Write、Maintain、Admin 権限のユーザーがアーカイブ操作を利用できます。
- アーカイブはPRをクローズし、一般公開ビューから非表示にします。アーカイブ解除でコメントやリアクションは再び可能になりますが、PRは自動で再オープンされないため、再開が必要な場合は別途操作してください。
- アーカイブ中は新しいコメント、リアクション、自動コメントがブロックされます。アーカイブ対象と解除の運用ルールをチーム内で共有してください。

## Screen readers can navigate timelines as lists

**URL:** https://github.blog/changelog/2026-10-08-screen-readers-can-navigate-timelines-as-lists

### 要約
スクリーンリーダーで課題やプルリクエストなどのタイムラインを操作すると、リスト構造、項目数、現在位置、イベント間の移動方法が読み上げられるようになりました。「さらに読み込む」または「すべて読み込む」を選んだ際には、読み込まれたイベント数も通知されます。見た目や通常の操作方法は変わらず、GitHub.com と GitHub Enterprise Server 3.23 で利用できます。

### ユーザーにとって良いこと
視覚的な位置関係に頼らず、長い履歴の全体像や現在位置を把握し、必要な更新へ移動しやすくなります。追加読み込み時の通知により、イベントが読み込まれたこととその件数も確認できます。

### アクションプラン
- スクリーンリーダーを使う利用者は、課題、PR、コミット、Secret scanning アラート、ライセンスコンプライアンスアラートのタイムラインでリスト構造と読み込み通知を確認してください。
- アクセシビリティ担当者やチームは、VoiceOver、NVDA、JAWS などで長いタイムラインを操作し、位置・項目数・追加読み込みの読み上げを確認してください。機能の有効化や設定変更は不要です。
- GitHub Enterprise Server を利用している場合は、バージョン 3.23 で利用可能です。

## Draft pull requests count toward pull request limits

**URL:** https://github.blog/changelog/2026-10-08-draft-pull-requests-count-toward-pull-request-limits

### 要約
プルリクエストの作成数制限に、ドラフトPRも含めるよう設定できるようになりました。従来はドラフトPRがユーザーごとの上限に数えられず、通常のPRに制限を設定していてもドラフトを無制限に作成できました。

### ユーザーにとって良いこと
リポジトリの管理者は、ドラフトPRを大量に作成することによる一覧の混雑、通知、CI実行を抑えやすくなります。

### アクションプラン
- PR作成数制限を運用しているリポジトリの管理者は、制限設定を確認し、必要に応じてドラフトPRも上限に含めるよう設定してください。この変更は設定可能になったものであり、既存設定への自動適用とは告知されていません。
- 設定後は、ドラフトPRもユーザーの上限に数えられることをコントリビューターに周知してください。
