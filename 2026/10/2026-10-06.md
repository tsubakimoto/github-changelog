## Update your IDE to restore agent activity in Copilot usage metrics

**URL:** https://github.blog/changelog/2026-10-06-update-your-ide-to-restore-agent-activity-in-copilot-usage-metrics

### 要約
Copilot SDK を使う IDE の一部で、エージェントの利用状況が Copilot usage metrics に正しく計上されない問題が修正されます。修正版は VS Code 1.139.0 以降で利用可能で、他の IDE にも 2026 年 11 月までに順次提供される予定です。影響期間中のデータはバックフィルされず、一部の IDE 活動が Copilot CLI の利用として計上されていた場合も過去分は修正されません。請求額への影響はありません。

### ユーザーにとって良いこと
修正版に更新すると、IDE ごとのエージェント利用状況やエージェントのコード変更量がダッシュボードと API に再び正しく反映され、利用状況をより正確に把握できます。

### アクションプラン
- Copilot の利用状況を管理しているチームは、影響対象の IDE と Copilot 拡張機能を確認してください。VS Code は 1.139.0 以降へ更新し、Visual Studio、JetBrains、Eclipse、Xcode は修正版が公開され次第更新してください。
- バージョンを一括管理している場合は、修正版へ直接更新できるよう展開を計画してください。更新前の利用状況の欠落は復元できません。
- IDE のテレメトリを有効にし、プロキシやファイアウォールで Copilot のテレメトリエンドポイントが遮断されていないことを確認してください。Copilot CLI 利用者に更新作業は不要です。

## Stacked pull requests generally available

**URL:** https://github.blog/changelog/2026-10-06-stacked-pull-requests-generally-available

### 要約
Stacked pull requests が一般提供され、大きな変更を複数の依存する小さなプルリクエストに分けてレビュー・マージできるようになりました。ベースブランチ更新後のリベースで変更のないコードの承認を維持でき、署名付きコミット、マージキューとの統合、スタックの自動リターゲットなどにも対応します。スタックの自動マージは今後数週間かけて順次提供されます。

### ユーザーにとって良いこと
依存関係のある変更を段階的にレビュー・マージしやすくなり、スタックの状態確認や PR 間の移動も簡単になります。GitHub CLI の `gh stack` 拡張は Git worktree に対応し、`pull_request` webhook では PR がスタックに加わったことを示す `stacked` アクションが通知されます。

### アクションプラン
- GitHub.com の全プランで利用可能です。大きな変更を分割してレビューするチームは、スタックを使った開発フローを試してください。GitHub Enterprise Server では今後のリリースに含まれる予定です。
- 既存のブランチ保護ルール、承認維持、コミット署名、マージキューの動作をチームの運用に合わせて確認してください。ルールのバイパス権限を持つユーザーは、スタック内の最下位の未マージ PR にその権限を使えます。
- 自動マージは今後数週間かけて順次提供されるため、利用可能になったら必要に応じてスタック単位で設定してください。`gh stack` を利用するチームは拡張を更新し、Git worktree 対応を活用できます。

## Code scanning AI Scan enablement status in security overview

**URL:** https://github.blog/changelog/2026-10-06-code-scanning-ai-scan-enablement-status-in-security-overview

### 要約
組織およびエンタープライズの管理者は、Security overview の coverage ビューで、リポジトリごとの AI Scan for pull requests の有効化状態を確認できるようになりました。概要には有効・未有効のリポジトリ数が表示され、ビューのフィルターや CSV エクスポートでも状態を確認できます。

### ユーザーにとって良いこと
組織やエンタープライズ全体で AI Scan の導入状況を把握し、未有効のリポジトリを特定しやすくなります。

### アクションプラン
- 組織・エンタープライズ管理者は Security overview の code scanning coverage を確認し、必要に応じて `code-scanning-ai-scan-pr-scan:enabled` または `code-scanning-ai-scan-pr-scan:not-enabled` で絞り込んでください。
- CSV で棚卸しする場合は、`Code Scanning AI Scan for pull requests` 列を利用してください。この機能は有効化状態の可視化であり、未有効のリポジトリは必要に応じて別途設定してください。
