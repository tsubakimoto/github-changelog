## Download GitHub Code Quality license usage as a CSV

**URL:** https://github.blog/changelog/2026-10-15-download-github-code-quality-license-usage-as-a-csv

### 要約
GitHub Code Quality のライセンス使用状況を CSV でダウンロードできるようになりました。レポートには、直近 90 日間にコミットしたアクティブな利用者、コミット先リポジトリ、および利用者が単一のリポジトリまたは組織に固有かどうかが含まれます。GitHub Team と GitHub Enterprise Cloud が対象です。

### ユーザーにとって良いこと
実際の利用者とリポジトリを自社の記録と照合でき、次の請求期間にライセンスを解放できるリポジトリを判断しやすくなります。利用者のライセンス数を見直しても、現在の請求額は変わりません。

### アクションプラン
- 対象プランの Organization または Enterprise 管理者は、**Billing and licensing** の **Licensing** ページで **Code Quality** カードから CSV をダウンロードしてください。
- 利用者やリポジトリごとの使用状況を社内記録と照合し、Code Quality の無効化によって次の請求期間にライセンスを解放できる対象がないか確認してください。

- [Download GitHub Code Quality license usage as a CSV](https://github.blog/changelog/2026-10-15-download-github-code-quality-license-usage-as-a-csv)

## Upcoming deprecation of selected GitHub Copilot models in mid-November

**URL:** https://github.blog/changelog/2026-10-15-upcoming-deprecation-of-selected-github-copilot-models-in-mid-november

### 要約
2026 年 11 月 16 日に、Claude Opus 4.8、Claude Opus 5、GPT-5.6 Terra が、Copilot Chat、インライン編集、Ask / Agent モード、コード補完を含むすべての GitHub Copilot 体験で廃止されます。代替モデルはそれぞれ Claude Opus 5.5、Claude Opus 5.5、GPT-6.1 Sol または GPT-6 Luna です。Claude Opus 4.8 は年次プランの個人 Copilot 契約者には引き続き提供されます。

### ユーザーにとって良いこと
代替モデルを前もって選定し、廃止日以降にモデル指定を使うワークフローや連携が停止するのを防げます。既定のモデル有効化が適用される Copilot Enterprise / Business では、管理者が設定を変更していなければ代替モデルは自動的に有効になります。

### アクションプラン
- 2026 年 11 月 16 日までに、対象モデルを指定しているワークフローや連携を確認し、推奨される代替モデルへ切り替えてください。
- Copilot Enterprise / Business 管理者は、モデルポリシーで代替モデルが利用可能か確認してください。全体の既定を無効化している場合は、Copilot 設定のモデルポリシーから代替モデルへのアクセスを有効にしてください。
- Claude Opus 4.8 を利用している年次プランの個人契約者は廃止対象外です。その他の利用者は、廃止後のモデル選択を確認してください。

## AI Scan for pull requests generally available

**URL:** https://github.blog/changelog/2026-10-15-ai-scan-for-pull-requests-generally-available

### 要約
プルリクエスト向け Code scanning の AI Scan が一般提供されました。CodeQL が現在カバーしていない言語やフレームワーク（PHP、Shell/Bash、Terraform、Dockerfile、Java の JSP、C# の Blazor など）の変更から脆弱性を検出し、リスクの説明や自動修正案を提示する場合があります。設定が有効ならプルリクエストで自動実行され、結果は CodeQL と並んで表示されますが、チェックを失敗させたりマージをブロックしたりするものではありません。

### ユーザーにとって良いこと
CodeQL の対象外だったコードにも追加のセキュリティ確認を行い、プルリクエストの段階で修正候補を得られます。AI Scan は GitHub Copilot ライセンスなしで利用できます。

### アクションプラン
- 対象リポジトリの管理者は、Code scanning と有効な AI Scan 設定を確認してください。パブリックリポジトリは個人または Organization 所有が対象です。プライベート・内部 Organization リポジトリでは GitHub Code Security または GitHub Advanced Security が必要です。
- AI Scan の結果は助言として扱い、コードと提案をレビューしてください。フォークからのプルリクエストおよび Dependabot が作成したプルリクエストでは実行されません。
- AI Scan は Code Security AI クレジットを消費します。利用量は Enterprise の課金・ライセンス設定にある **AI usage** の **Advanced Security** として確認し、必要に応じて SKU 単位の予算を設定してください。

## Agentic autofix for code scanning alerts general availability

**URL:** https://github.blog/changelog/2026-10-15-agentic-autofix-for-code-scanning-alerts-general-availability

### 要約
コードスキャンアラート向け Agentic autofix が一般提供されました。アラートを Copilot に割り当てると、関連ファイルの調査、修正案の作成、CodeQL の再実行による検証を行い、確認用のドラフトプルリクエストを作成します。GitHub Enterprise Cloud（データレジデンシー付き環境を含む）の GitHub Code Security または GitHub Advanced Security の顧客が対象です。

### ユーザーにとって良いこと
アラートごとに調査から検証までを支援し、修正内容と検証手順の説明付きプルリクエストを作成できます。リポジトリのアラート一覧やセキュリティキャンペーンからは、最大 25 件をまとめて一つのプルリクエストにできます。

### アクションプラン
- Enterprise 管理者は Advanced Security ポリシーで **Agentic autofix** を有効にし、その後 Organization またはリポジトリ管理者が Code Security 設定で機能を有効にしてください。Copilot の課金方法も必要です。
- 利用時はデフォルトブランチ上のコードスキャンアラートを Copilot に割り当ててください。プルリクエストまたは他ブランチでのみ検出されたアラートは割り当てできません。
- AI クレジット（Code Security 予算）と GitHub Actions 分数を消費します。課金設定の **AI usage** と SKU 単位の予算を確認してください。生成された修正プルリクエストはレビューしてからマージしてください。
- REST API から利用する場合は、Update a Code Scanning Alert API の `assignees` に `copilot-swe-agent[bot]` を指定してください。

## Email notifications for repository push events have been retired

**URL:** https://github.blog/changelog/2026-10-15-email-notifications-for-repository-push-events-have-been-retired

### 要約
2026 年 10 月 15 日をもって、リポジトリへの push イベントに関するメール通知が廃止され、送信されなくなりました。受信者の同意なしにメールを送れる仕組みがスパムや悪用につながるため、GitHub のメール基盤を保護する目的で終了しました。

### ユーザーにとって良いこと
望まないメール通知や GitHub のメール基盤の悪用を防げます。引き続き push のメール通知が必要なチームは、自社のメール配信手段を使うことで通知を継続できます。

### アクションプラン
- push 通知をメールで受け取っていたチームは、通知要件を確認し、必要であれば push イベントをトリガーとする GitHub Actions ワークフローを設定してください。
- メールを継続する場合は、GitHub の通知メールではなく、自社の SMTP サーバーまたはメールプロバイダーを Actions から利用してください。
