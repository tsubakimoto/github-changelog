## Open source license compliance generally available

**URL:** https://github.blog/changelog/2026-10-16-open-source-license-compliance-generally-available

### 要約
オープンソースライセンスコンプライアンスが一般提供され、GitHub Enterprise Cloud（データレジデンシーを含む）で、GitHub Code Security が有効なリポジトリを対象に、企業全体のライセンスポリシーを適用できるようになりました。依存関係を追加・変更するプルリクエストはルールセットで検査され、ポリシーに適合しない依存関係には注釈が付きます。承認申請用の新しい Enterprise ロール、監査ログイベント、ポリシー管理・適合性確認 API も利用できます。

### ユーザーにとって良いこと
組織や Enterprise でライセンス方針を一元化し、依存関係が取り込まれる前にルール違反を把握できます。データレジデンシー環境でもライセンス情報を利用でき、依存グラフや SBOM の確認、外部システムとの連携、コーディングエージェントによるポリシー準拠パッケージの選択にも役立ちます。

### アクションプラン
- GitHub Enterprise Cloud の Enterprise 管理者は、適用対象リポジトリを決め、ルールセットに **Require license compliance results before merging** 条件を追加してください。対象リポジトリでは GitHub Code Security が有効であることを確認してください。
- 非準拠の依存関係が検出された場合は、依存関係を削除または置換するか、ライセンスポリシーを見直すか、パッケージ例外を申請してください。
- 承認申請を扱う担当者には **Enterprise Open-Source License Manager** ロールを割り当ててください。ポリシー変更の監査ログや、新しい API による更新・適合性確認が必要な場合は連携を確認してください。

## Xcode 27 runner image generally available

**URL:** https://github.blog/changelog/2026-10-15-xcode-27-runner-image-generally-available

### 要約
GitHub Actions で Xcode 27 の GitHub ホストランナーイメージが一般提供されました。macOS 27 上で動作し、Xcode 27 ツールチェーンと Apple SDK を含みます。Xcode ベースのイメージは特定の OS バージョンではなく Xcode のメジャーバージョンを基準に選択できます。

### ユーザーにとって良いこと
Apple アプリのビルド・テストで、必要な Xcode ツールチェーンを明示してランナーを選べます。すでに `xcode-27` または `xcode-27-xlarge` を使っているワークフローは、変更せずに一般提供版を利用できます。

### アクションプラン
- Xcode 27 でビルドするワークフローでは、`runs-on` に `xcode-27` または `xcode-27-xlarge` を指定してください。
- 既に上記ラベルを利用している場合、ワークフローの変更は不要です。
- これらのイメージは Apple Silicon（arm64）ランナーのみで利用できます。Intel ランナーが必要なワークフローでは別のイメージを選んでください。
- インストール済みソフトウェアの詳細確認や問題報告は、runner-images リポジトリを参照してください。

## Multi-repository support and other improvements for GitHub in Slack and Teams

**URL:** https://github.blog/changelog/2026-10-15-copilot-in-slack-and-teams-adds-model-and-repository-updates

### 要約
Slack と Microsoft Teams の GitHub で、1 つの会話から複数リポジトリをまたいで作業できるようになりました。会話の文脈を使った Issue 作成、コード変更とプルリクエスト作成、複数リポジトリの PR 状況確認、フロントエンドとバックエンドを横断した調査などを依頼できます。さらに、メッセージ内の任意の位置での `@GitHub` メンション、リポジトリ切り替え、Slack の共有メッセージやスレッドの文脈利用、信頼性も改善されました。

### ユーザーにとって良いこと
リポジトリや会話を切り替えずに、複数のプロジェクトに関係する作業を進められます。Slack のスレッドをそのまま文脈として利用できるため、内容をコピーして貼り付ける手間も減ります。

### アクションプラン
- Slack または Teams で複数リポジトリに関係する作業を依頼する際は、対象リポジトリを明記し、必要に応じて会話やスレッドの文脈を参照するよう `@GitHub` に依頼してください。
- チームでは、Issue 作成・PR 作成・複数リポジトリの調査など、リポジトリをまたぐユースケースを試し、結果を確認してください。
- `@GitHub` はメッセージの冒頭以外でもメンションできます。既存の運用に合わせて会話中に利用してください。
