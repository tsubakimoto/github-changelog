## Copilot model policy API for enterprise, orgs, and teams

**URL:** https://github.blog/changelog/2026-10-19-copilot-model-policy-api-for-enterprise-orgs-and-teams

### 要約
Copilot のモデルポリシーを取得・更新する REST API の GET / PATCH エンドポイントが、エンタープライズ、エンタープライズチーム、エンタープライズアプリ、Organization 向けに一般提供されました。エンタープライズでは、設定モードに応じて Organization、チーム、アプリにモデル制御を委任できます。

### ユーザーにとって良いこと
管理者はポリシーを API 経由で確認・変更でき、組織階層に沿ったモデル提供状況を効率的かつ一貫して管理できます。

### アクションプラン
- Copilot のモデル提供ポリシーを自動管理する場合は、対象階層に対応する GET / PATCH エンドポイントを管理用ワークフローに組み込んでください。
- エンタープライズの設定モードと委任先（Organization、チーム、アプリ）を確認し、必要なモデルが利用可能なポリシーになっているか点検してください。利用には管理者による設定が必要です。

- [Copilot model policy API for enterprise, orgs, and teams](https://github.blog/changelog/2026-10-19-copilot-model-policy-api-for-enterprise-orgs-and-teams)

## GitHub Copilot models deprecated on October 19, 2026

**URL:** https://github.blog/changelog/2026-10-19-github-copilot-models-deprecated-on-october-19-2026

### 要約
2026年10月19日付で、Copilot Chat、インライン編集、Ask / Agent モード、コード補完など、ほとんどの Copilot 機能で複数のモデルが非推奨になりました。代替モデルは Gemini 3.8 Flash、GPT-6.1 Sol、GPT-6 Luna、Grok 4.7 です。

### ユーザーにとって良いこと
後継モデルに切り替えることで、Copilot のワークフローや連携を継続して利用できます。モデル提供を管理者ポリシーで制御している組織は、代替モデルを明示的に許可できます。

### アクションプラン
- ワークフローや連携で非推奨モデルを指定している場合は、Gemini 3.7 Flash を Gemini 3.8 Flash、GPT-5.5 / GPT-5.4 を GPT-6.1 Sol、GPT-5.4 mini / GPT-5 mini を GPT-6 Luna、Grok 4.5 を Grok 4.7 に更新してください。
- Copilot Enterprise の管理者は、利用者に必要な代替モデルを Copilot のモデルポリシーで有効にしてください。
- 非推奨モデルを削除する追加作業は不要です。

### リファレンス
- [GitHub Copilot models deprecated on October 19, 2026](https://github.blog/changelog/2026-10-19-github-copilot-models-deprecated-on-october-19-2026)

## Some Git over HTTPS may temporarily require authentication

**URL:** https://github.blog/changelog/2026-10-19-some-git-over-https-may-temporarily-require-authentication

### 要約
異常なトラフィックが発生している間、GitHub は github.com 上の一部の公開リポジトリに対する HTTPS の clone / fetch に、一時的に認証を求める場合があります。これは公開リポジトリ全般の認証必須化ではなく、認証済み HTTPS、SSH、push、および Web / API トラフィックには影響しません。

### ユーザーにとって良いこと
GitHub は影響範囲を限定しながらサービスの可用性を保護します。自動 clone / fetch を認証付きにしておけば、一時的な保護措置による失敗を減らせます。

### アクションプラン
- GitHub Actions で自動 clone / fetch を行う場合は `GITHUB_TOKEN` を使用してください。他の CI では GitHub App の installation access token を推奨し、必要に応じて personal access token を使用してください。
- 認証できない操作が一時的に拒否された場合は、認証して再試行するか、保護措置が解除されるまで待ってから再試行してください。

## CodeQL changes for macOS 27, Xcode 27, and Swift 6.4

**URL:** https://github.blog/changelog/2026-10-19-codeql-changes-for-macos-27-xcode-27-and-swift-6-4

### 要約
macOS 27 と Xcode 27 では、一部のシステムバイナリから Intel（x86_64）コードが除かれるため、CodeQL のビルドトレース抽出に影響します。Xcode 27 では C/C++、C#、Go、Java、Kotlin、Swift のトレース抽出が利用できず、Swift 6.4 はすべてのプラットフォームでサポートされません。Intel Mac のサポートも2026年12月中旬に非推奨となる予定です。

### ユーザーにとって良いこと
影響するツールチェーンと抽出方式が明確になり、CodeQL スキャンの失敗を避けるための移行方法を選べます。

### アクションプラン
- Swift のスキャン、またはビルドトレースを使うスキャンがある場合は、影響を受けるワークフローの runner とツールチェーンを macOS 26 以前、Xcode 26 以前に固定してください。GitHub Actions では runner イメージとツールチェーンの両方を指定してください。
- C/C++、C#、Java のスキャンでは、トレースが不要な `build-mode: none` への切り替えを検討してください。
- Swift 6.4 を使用している場合は、サポート対象の Swift バージョンへ変更してください。Intel Mac を利用している場合は、2026年12月中旬のサポート非推奨に備えて移行を計画してください。

- [CodeQL changes for macOS 27, Xcode 27, and Swift 6.4](https://github.blog/changelog/2026-10-19-codeql-changes-for-macos-27-xcode-27-and-swift-6-4)
