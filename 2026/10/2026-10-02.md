## Stateless GitHub App installation tokens rolled out

**URL:** https://github.blog/changelog/2026-10-02-stateless-github-app-installation-tokens-rolled-out

### 要約
GitHub Appインストールトークンのステートレス形式への段階的な移行が完了し、新しく発行されるトークンは原則 `ghs_APPID_JWT` 形式になりました。トークンは従来の約40文字から約520文字になりますが、権限、リポジトリ範囲、有効期限1時間、REST APIエンドポイントは変わりません。

### ユーザーにとって良いこと
トークンの発行と検証が高速化され、GitHub APIの信頼性が向上します。既存トークンは有効期限まで利用できるため、移行期間中も直ちに処理を止めずに対応できます。

### アクションプラン
- GitHub Appのインストールトークンを扱うシステムで、トークンを不透明な文字列として処理し、40文字固定の検証や旧形式専用の正規表現を使っていないことを確認する。
- データベース、シークレットストア、環境変数、プロキシ、ゲートウェイ、ミドルウェアが約520文字のトークンや長いAuthorizationヘッダーを受け入れるか検証する。
- ログ出力とシークレットマスキングが新しい形式にも適用されることを確認する。
- ⚠️ 検証用の一時リクエストヘッダー `X-GitHub-Stateless-S2S-Token` は2026年11月30日に非推奨となるため、本番コードからそれまでに削除する。以後、GitHubはこのヘッダーを尊重しない。

## Copilot code review: API support and new default effort level

**URL:** https://github.blog/changelog/2026-10-02-copilot-code-review-api-support-and-new-default-effort-level

### 要約
GitHub Copilot code reviewをREST APIとGraphQL APIからリクエストできるようになり、リクエストごとにレビューの努力レベルも指定できるようになりました。新規・既存のリポジトリおよび組織で、既定の努力レベルはBalancedになっています（2026年9月28日適用）。

### ユーザーにとって良いこと
既存のスクリプト、ワークフロー、社内ツールからコードレビューを起動でき、開発プロセスへ組み込みやすくなります。Liteを明示的に選択していた設定は維持され、Enterprise、Organization、Repository、Personalの各レベルで必要に応じて上書きできます。

### アクションプラン
- Copilot Pro、Pro+、Max、Business、Enterpriseの対象プランで、RESTまたはGraphQL APIを使ったレビュー自動化の候補を洗い出す。
- APIリクエストに必要なレビュー努力レベルを設定し、既存のレビュー時間・品質・利用量への影響を確認する。
- Enterprise、Organization、Repository、Personalの各設定で、BalancedまたはLiteの意図した継承・上書き関係になっているか確認する。
- 2026年9月28日に既定値がBalancedへ変更済みのため、レビュー負荷を抑えたいチームは管理対象レベルでLiteを明示的に選択する。

## Selected models in GitHub Copilot deprecated

**URL:** https://github.blog/changelog/2026-10-02-selected-models-in-github-copilot-deprecated

### 要約
2026年10月2日付で、GitHub Copilotの全ての利用体験からGemini 3.5 Flash、Gemini 3.6 Flash、Kimi K2.7 Code、Claude Opus 4.7が非推奨になりました。代替モデルとして、それぞれGemini 3.8 Flash、Kimi K3、Claude Opus 5.5が案内されています。

### ユーザーにとって良いこと
対応モデルへ早めに切り替えることで、Copilot Chat、インライン編集、エージェントモード、コード補完などのワークフローを継続できます。Enterprise管理者はモデルポリシーで代替モデルの利用可否を組織的に管理できます。

### アクションプラン
- 既存のワークフロー、設定、連携で非推奨モデル名を指定している箇所を洗い出し、推奨代替モデルへ更新する。
- Copilot Enterprise管理者は、Copilot設定のモデルポリシーで代替モデルを有効化し、利用者のモデルセレクターに表示されることを確認する。
- VS Codeとgithub.comのCopilot Chat、インライン編集、ask／agentモード、コード補完で切り替え後の品質とコストを検証する。
- ⚠️ 非推奨日は2026年10月2日。モデルを削除するための追加操作は不要だが、既存の明示指定は早急に更新する。

## New fields for SecurityAdvisory GraphQL API

**URL:** https://github.blog/changelog/2026-10-02-new-fields-for-securityadvisory-graphql-api

### 要約
SecurityAdvisory GraphQL APIの `SecurityAdvisory` オブジェクトに、CVE ID、影響ソースコード、GitHubレビュー日時、NVD公開日時、関連リポジトリアドバイザリURLの5フィールドが追加されました。`securityAdvisories` クエリには `severities` と `isWithdrawn` の2つのフィルターも追加されています。

### ユーザーにとって良いこと
REST APIへ切り替えずにアドバイザリの詳細を取得でき、通信回数、認証経路、レート制限の消費を減らせます。重大度別のトリアージ、撤回済みアドバイザリの監査、NVD公開からGitHubレビューまでの追跡などを効率的に構築できます。

### アクションプラン
- SecurityAdvisoryを取得する既存GraphQLクエリで、必要に応じて追加フィールドと `severities`／`isWithdrawn` フィルターを利用する。
- REST APIとの二重取得やクライアント側フィルタリングを見直し、不要なラウンドトリップとレート制限消費を削減する。
- 既存クエリはそのまま動作する追加・読み取り専用変更のため、段階的にスキーマと生成型を更新してテストする。

## Confidential comments on repository security advisories

**URL:** https://github.blog/changelog/2026-10-02-confidential-comments-on-repository-security-advisories

### 要約
リポジトリのセキュリティアドバイザリに、書き込み権限を持つユーザーだけが閲覧できる機密コメントを投稿できるようになりました。機密コメントはタイムライン上で明示され、報告者や書き込み権限のない招待済みコラボレーターには表示・通知されません。

### ユーザーにとって良いこと
悪用の疑い、調査内容、チーム内の調整事項を、アドバイザリの履歴から離れずにメンテナー間で共有できます。閲覧権限の変更は現在のリポジトリ権限に従い、機密コメントの閲覧は監査ログにも記録されます。

### アクションプラン
- Private vulnerability reportingを有効にした公開リポジトリで、機密情報や内部調査事項はコメント作成時に `Confidential` を選択する運用を定める。
- 投稿後は機密コメントと通常コメントを相互変換できないため、宛先と公開範囲を投稿前に確認する。
- 書き込み権限の付与・削除が機密コメントの閲覧範囲に直結することを、メンテナーとセキュリティ担当者へ周知する。
- GraphQL APIでは利用できるがREST APIの応答には含まれない。GitHub Free、Pro、Team、Enterprise Cloudの対象公開リポジトリで提供される。

## Repository security advisory comments API in public preview

**URL:** https://github.blog/changelog/2026-10-02-repository-security-advisory-comments-api-in-public-preview

### 要約
リポジトリセキュリティアドバイザリのコメントをREST APIで一覧取得、単一取得、追加、編集できるようになりました。アドバイザリの応答にはコメント数も追加され、更新日時による絞り込みにも対応します。

### ユーザーにとって良いこと
アドバイザリの議論を監査や移行のためにエクスポートしたり、トリアージメモを自動追加したりできます。IssueやPull Requestと同様の自動化ワークフローに組み込めるため、脆弱性対応の可視性と一貫性が向上します。

### アクションプラン
- REST API連携で、コメント数を使った活動判定や `since` による差分取得を実装し、必要なコメントだけを取得する。
- アドバイザリの閲覧権限と適切なrepository security advisories権限またはトークンスコープを付与し、権限不足時の処理を検証する。
- ⚠️ パブリックプレビュー機能のため、本番利用では仕様変更に備えてAPIバージョンとエラー処理を管理する。
- 機密コメントはRESTエンドポイントから返されず、コメント削除も未対応であることを運用と監査設計に反映する。
- GitHub Free、Pro、Team、Enterprise Cloudの公開リポジトリで利用できる。非コラボレーターは内部コメントを閲覧できない。
