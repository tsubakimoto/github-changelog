## HydraFusion updates and new Max option

**URL:** https://github.blog/changelog/2026-10-14-hydrafusion-updates-and-new-max-option

### 要約
複数モデルを使って応答を生成する HydraFusion のモデルプールに Claude Opus 5.5、GPT-6 Astra、GPT-6.1 Sol、GPT-6 Luna が加わり、各工程に応じて推論レベルを調整するようになりました。Cascade は必要に応じて初期結果を判定・修正する工程を追加でき、Critique は並列のレビューモデルとワークスペースを直接調べるツールを活用します。より高度なタスク向けの **HydraFusion Max** も登場し、両方とも VS Code、GitHub Copilot app、Copilot CLI で研究プレビューとして利用できます。

### ユーザーにとって良いこと
複数モデルの強みを組み合わせながら、タスクに応じたレビューや修正を行えるため、モデル選択の手間を減らし、複雑な作業ではより深い推論を活用できます。HydraFusion は速度・コストとのバランスを取り、Max は特に難しいタスクに向けてより高い推論能力を重視します。

### アクションプラン
- Copilot Pro、Pro+、Business、Enterprise の利用者は、対象クライアントのモデル選択画面で HydraFusion または HydraFusion Max が利用可能か確認してください。研究プレビュー機能が有効であることが必要です。
- Business / Enterprise 管理者は、組織のモデルポリシーで対象モデルの利用が許可されているか確認してください。利用可否は契約プランと組織のポリシーに従います。
- 通常のエージェント作業では HydraFusion を、深い推論や徹底したレビューが必要な作業では HydraFusion Max を試し、品質とトークン使用量を比較してください。

## GitHub Actions workflow lockfiles in public preview

**URL:** https://github.blog/changelog/2026-10-14-github-actions-workflow-lockfiles-in-public-preview

### 要約
GitHub Actions のワークフロー依存関係ロックファイルがパブリックプレビューになりました。`gh actions-lock` 拡張機能で `.github/workflows/actions.lock` を生成・更新し、Actions、推移的依存関係、再利用可能なワークフローを特定のコミットに固定できます。ロックファイル対応済みのワークフローでは、依存関係のロックファイルへの記載が必須となり、タグやブランチが移動しても記録されたコミットで実行されます。プレビューは GitHub Enterprise Cloud、データレジデンシー付き GitHub Enterprise Cloud、Team、Free が対象です。

### ユーザーにとって良いこと
レビュー後にタグやブランチが別のコミットへ移動しても、ワークフローが実行する依存関係を固定でき、意図しないコード変更の混入リスクを抑えられます。Dependabot は、導入済みワークフローの Actions 更新時に対応するロックファイルも同じプルリクエストで更新します。

### アクションプラン
- 対象プランを利用しているリポジトリでは、`gh-actions-lock` 拡張機能を導入し、依存関係を確認したうえで `.github/workflows/actions.lock` を生成してコミットしてください。ロックファイルはワークフロー単位で段階的に導入できます。
- CI でロックファイルの古さを検査する場合は、拡張機能の検証機能を使い、ファイルを変更せずに最新状態をチェックしてください。
- Enterprise、Organization、Repository 管理者は、対象範囲でロックファイルを必須にする場合、プレビュー中の **Require lockfile** ポリシーを確認してください。
- ロックは依存関係の安全性を保証しません。固定する前に依存先をレビューし、Dependabot による更新プルリクエストとロックファイルの差分も確認してください。
