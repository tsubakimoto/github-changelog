## GitHub App improvements for least privilege and management

**URL:** https://github.blog/changelog/2026-10-13-github-app-improvements-for-least-privilege-and-management

### 要約
GitHub Apps と fine-grained PAT に、リポジトリ作成用の `repository_creation:write` と、組織内のインストールにリポジトリを追加・削除する `installation_repositories:write` が追加されました。組織で承認済みの GitHub App は、リポジトリ管理者が組織オーナーの追加承認なしで自分のリポジトリへ追加できるようになり、GitHub App は有効期限付きユーザーアクセストークンへの段階的な移行向けに `offline_access` にも対応しました。また、アプリ詳細の取得対象が共有オーナーや同じ Enterprise 内の非公開・内部アプリに拡大され、資格情報は専用の **Credentials** タブで管理されます。

### ユーザーにとって良いこと
必要な操作に限定した権限を付与しやすくなり、広範な PAT や過剰な権限に頼らずにリポジトリ作成やアプリのインストール管理を自動化できます。アプリの監査やトークン有効期限の段階的な導入も容易になります。

### アクションプラン
- GitHub App や fine-grained PAT でリポジトリを作成している場合は、`repository_administration:write` の代わりに `repository_creation:write` を使えるか確認してください。アプリのインストールには引き続き組織管理者の承認が必要です。
- 組織内のインストール対象リポジトリを自動管理する場合は、`installation_repositories:write` を付与し、ユーザーとして API を呼び出す場合は組織オーナーまたは対象リポジトリの管理者であることを確認してください。
- 組織でリポジトリ管理者による承認済みアプリの追加を許可しない場合は、**Restricting GitHub App Installation to Organization Owners** の設定を確認してください。
- 有効期限のないユーザーアクセストークンを段階的に移行するアプリでは、`offline_access` を要求してリフレッシュトークンを使うテスト・展開計画を検討してください。この変更はその認証要求にのみ適用されます。
- GitHub Enterprise Server では、`offline_access` は 3.23、それ以外の改善は 3.24 での提供予定です。

## Gemini 4 Argon in GitHub Copilot

**URL:** https://github.blog/changelog/2026-10-13-gemini-4-argon-in-github-copilot

### 要約
Google の最新モデル **Gemini 4 Argon** が GitHub Copilot で一般提供され、複雑なコーディング、エージェント、推論タスクに利用できるようになりました。Copilot Pro+、Max、Business、Enterprise が対象で、VS Code、Visual Studio、Copilot CLI、Copilot coding agent、Copilot app、JetBrains IDE、Xcode、Eclipse から選択できます。利用量に応じた課金ではプロバイダーの定価が適用され、ロールアウトは段階的に進みます。

### ユーザーにとって良いこと
難度の高い開発タスクで新しいモデルを選択でき、特に Copilot CLI を含む複数の環境でモデルの推論・コーディング能力を活用できます。

### アクションプラン
- 対象プランの利用者は、利用中の Copilot クライアントのモデル選択画面で **Gemini 4 Argon** が利用可能か確認してください。段階的な展開のため、表示されるまで時間がかかる場合があります。
- Copilot Business / Enterprise 管理者は、Copilot 設定のモデルポリシーを確認してください。既定のモデル有効化が許可されていれば新モデルは自動的に有効になり、全体の既定を無効化している場合や個別に無効化した場合は利用できません。
- 使用量ベースの課金を利用する場合は、プロバイダー定価で請求されることを踏まえ、モデル利用と予算を確認してください。

- [Gemini 4 Argon in GitHub Copilot](https://github.blog/changelog/2026-10-13-gemini-4-argon-in-github-copilot)

## Audit GitHub Code Quality finding dismissals and reopenings

**URL:** https://github.blog/changelog/2026-10-13-audit-github-code-quality-finding-dismissals-and-reopenings

### 要約
GitHub Code Quality のバックログ検出結果を手動で却下・再オープンした操作が、組織または Enterprise の監査ログに記録されるようになりました。`repo.code_quality_findings_dismissed` と `repo.code_quality_findings_reopened` のイベントには、実行者、日時、リポジトリ、ルール、対象検出結果の識別子と件数が含まれます。GitHub Team と GitHub Enterprise Cloud で一般提供され、Enterprise Server は対象外です。

### ユーザーにとって良いこと
コード品質の検出結果に対する判断の経緯を追跡でき、組織の監査や誤った却下・再オープンの調査に役立ちます。

### アクションプラン
- Code Quality を有効にしている組織は、組織または Enterprise の監査ログで上記2つのイベント名を検索し、必要な監査手順に加えてください。追加設定は不要です。
- GitHub Enterprise Cloud では、監査ログ API からこれらのイベントを取得する連携が必要か確認してください。
- GitHub Enterprise Server を利用している場合、このリリースの対象外であることを踏まえてください。

### リファレンス
- [Audit GitHub Code Quality finding dismissals and reopenings](https://github.blog/changelog/2026-10-13-audit-github-code-quality-finding-dismissals-and-reopenings)

## Secret scanning blocks Anthropic keys by default, adds Salesforce

**URL:** https://github.blog/changelog/2026-10-13-secret-scanning-blocks-anthropic-keys-by-default-adds-salesforce

### 要約
Secret scanning に Salesforce の `salesforce_marketing_cloud_api_oauth2_token`、Anthropic の `anthropic_service_api_key` と `anthropic_user_api_key`、Cloudsmith の `cloudsmith_api_key` の検出が追加されました。Anthropic の2種類のキーは、secret scanning が有効なリポジトリ（無料のパブリックリポジトリを含む）で push protection の既定対象となり、含まれるコミットは自動的にブロックされます。Salesforce は secret scanning パートナーにも加わりました。

### ユーザーにとって良いこと
新たな種類の認証情報の漏えいを検出し、Anthropic キーについてはプッシュ時点で防止できます。公開リポジトリで検出されたパートナーシークレットは、パートナープログラムを通じて発行元へ報告されます。

### アクションプラン
- secret scanning を有効にしているリポジトリで、Anthropic キーが含まれるコミットが push protection により拒否された場合は、キーをコードから除去し、必要に応じてローテーションしてから再度プッシュしてください。
- Salesforce、Anthropic、Cloudsmith の認証情報を利用するチームは、シークレットの保管場所や既存リポジトリへの誤登録がないか確認してください。ユーザーシークレットのアラートはパブリック・プライベート両方のリポジトリで生成されます。
- 公開リポジトリで検出されたパートナーシークレットは発行元に自動報告されるため、該当する認証情報を速やかに無効化またはローテーションできる手順を整えてください。

## Enterprise managed settings enforcement updates

**URL:** https://github.blog/changelog/2026-10-13-enterprise-managed-settings-enforcement-updates

### 要約
Enterprise 管理者は、対応する GitHub Copilot クライアントに起動時の最新サーバー管理設定の取得を必須化する `forceRemoteSettingsRefresh` を設定できるようになりました。Copilot CLI、VS Code、GitHub Copilot app が対応し、最新ポリシーを確認できない場合はキャッシュ済みの古い設定で動作せず、フェイルクローズします。また、sandbox キーを含む管理設定では、最低クライアントバージョン要件の適用が始まり、古いバージョンに固定した利用者は更新が必要になります。

### ユーザーにとって良いこと
ポリシー変更を古いキャッシュに依存せずクライアントへ反映でき、管理者は sandbox などのガバナンス設定をサポート対象バージョンで確実に適用できます。

### アクションプラン
- Enterprise 管理者は、ポリシーをクライアント起動前に必ず最新化する必要がある場合、サーバー管理、MDM 管理、またはファイルベースの設定で `forceRemoteSettingsRefresh` を `true` にしてください。MDM とファイルベースの設定は初回サインイン前から最新設定を要求できます。
- この設定を有効にすると、最新ポリシーを確認できないクライアントは動作できません。ネットワークやサービス障害時の影響を評価し、展開前に利用者への案内とサポート手順を用意してください。
- sandbox キーを管理設定に含める場合は、ユーザーが最低要件を満たす Copilot クライアントへ更新できるよう、クライアント更新計画を確認してください。

## Improved detection for withdrawn Dependabot alerts

**URL:** https://github.blog/changelog/2026-10-13-improved-detection-for-withdrawn-dependabot-alerts

### 要約
Dependabot が脆弱性情報の無効化などを理由にアラートを撤回したことを、Webhook と REST API で判別しやすくなりました。`dependabot_alert` Webhook に `withdrawn` アクションが追加され、削除前のアラート番号、GHSA・CVE ID、パッケージ、マニフェストパスなどが含まれます。また、撤回済みアラートの取得・更新は `404 Not Found` ではなく `410 Gone` を返します。GitHub.com のすべてのリポジトリで利用でき、GitHub Enterprise Server 3.24 にも含まれる予定です。

### ユーザーにとって良いこと
アラートが存在しなかったのか、撤回されたのかを区別でき、脆弱性管理ツールや通知連携で古いアラートの状態を正確に処理できます。

### アクションプラン
- `dependabot_alert` Webhook を購読している連携では、`withdrawn` アクションを処理し、アラートが削除された後も識別情報を記録できるようにしてください。購読設定の追加変更は不要です。
- Dependabot アラートの REST API を使う連携では、`410 Gone` を撤回済みとして処理し、従来の `404 Not Found` と区別してください。
- GitHub Enterprise Server を利用している場合は、3.24 へのアップグレード計画を確認してください。

- [Improved detection for withdrawn Dependabot alerts](https://github.blog/changelog/2026-10-13-improved-detection-for-withdrawn-dependabot-alerts)

## Search and filter for budgets now available

**URL:** https://github.blog/changelog/2026-10-13-search-and-filter-for-budgets-now-available

### 要約
GitHub の課金設定にある **Budgets and alerts** ページで、すべての予算を一つの一覧から検索・絞り込みできるようになりました。スコープ、製品、SKU で検索・フィルタリングでき、Enterprise と組織ではユーザーによる検索も可能です。スコープメニューで組織やコストセンターなどに絞り込め、ユーザー単位の予算も同じ一覧で確認できます。

### ユーザーにとって良いこと
ページをまたいで予算を探す手間が減り、個人、組織、Enterprise の管理者が対象の予算やユーザーへの適用状況を把握しやすくなります。

### アクションプラン
- 予算を管理する場合は、課金設定の **Budgets and alerts** ページでスコープ、製品、SKU、または対象ユーザーを使って必要な予算を検索してください。
- 複数の組織やコストセンターを管理している場合は、スコープフィルターを利用して対象範囲ごとに予算を確認してください。機能利用に追加設定は不要です。

## Code scanning AI Scan metrics in security overview

**URL:** https://github.blog/changelog/2026-10-13-code-scanning-ai-scan-metrics-in-security-overview

### 要約
Organization と Enterprise の管理者は、Security overview で pull request 向け AI Scan の検出件数、解決数、修正率、対象リポジトリごとの状況、期間別の傾向、自動修正提案の適用頻度を確認できるようになりました。従来の **CodeQL pull requests** ページは **Code scanning on pull requests** に改称され、CodeQL と AI Scan のタブに分かれます。このパブリックプレビューは GitHub.com と GitHub Enterprise Cloud の GitHub Code Security または GitHub Advanced Security の顧客が対象で、Enterprise Server は非対応です。

### ユーザーにとって良いこと
セキュリティチームは個々の pull request を調べずに、AI Scan の検出や開発者の対応状況、自動修正の効果を組織・Enterprise 全体で評価し、導入や投資の判断に活用できます。

### アクションプラン
- 対象プランを利用する Organization / Enterprise 管理者は、Security overview の **Code scanning on pull requests** にある AI Scan タブで、利用可能なメトリクスと報告期間を確認してください。
- AI Scan の導入効果を評価する際は、検出件数だけでなく解決数、修正率、自動修正提案の適用頻度も併せて確認してください。
- パブリックプレビューの提供範囲は GitHub.com と GitHub Enterprise Cloud です。GitHub Enterprise Server はこのリリースでは利用できません。
