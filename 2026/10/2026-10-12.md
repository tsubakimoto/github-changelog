## Client telemetry user attribution and configurable capture

**URL:** https://github.blog/changelog/2026-10-12-client-telemetry-user-attribution-and-configurable-capture

### 要約
Enterprise 管理者は、Copilot のクライアントテレメトリで、プロンプトや応答、ツール内容を収集せずに利用者を特定できるようになりました。ユーザー名などの ID 情報と、プロンプト、応答、ツール引数・出力、ポリシー詳細の各収集クラスは個別に制御でき、すべて既定で無効です。管理設定の値はローカル設定、SDK 設定、環境変数より優先されます。

### ユーザーにとって良いこと
監査目的に応じて利用者の識別とコンテンツ収集を分けて制御できるため、必要な可視性を確保しながら、プロンプトやソースコードなどの機微情報を収集するリスクを抑えられます。

### アクションプラン
- Enterprise 管理者は、テレメトリを利用する場合、まず `telemetry.capture.identity` と各収集クラスの管理設定を確認してください。ID 情報も既定では収集されません。
- 監査要件に必要な収集クラスだけを有効にし、承認済みの収集エンドポイントへ送信してください。プロンプト、ツール、ポリシーのデータにはソースコード、コマンド、実行結果、ファイルパスなどが含まれる可能性があります。
- `captureContent` は従来のコンテンツ収集設定として引き続き使えますが、ID 情報の収集は有効にしません。個別制御を使う場合は、意図しない収集がないか管理設定を確認してください。

## Push attribution for commits in limited public preview

**URL:** https://github.blog/changelog/2026-10-12-push-attribution-public-preview

### 要約
GitHub は、コミットの author・committer 情報とは別に、各コミットをプッシュした認証済みユーザーを記録し、UI と API で確認できるようにしました。また、プッシュしたユーザーの検証済みメールアドレスと committer 情報の一致を求めるリポジトリルールが追加され、コミットのなりすまし対策に利用できます。この機能は GitHub Enterprise 顧客向けの限定パブリックプレビューです。

### ユーザーにとって良いこと
クライアントが任意に設定できる author・committer の文字列に頼らず、実際にプッシュした認証済みユーザーを監査できるため、不審なコミットの調査や身元の偽装防止に役立ちます。

### アクションプラン
- GitHub Enterprise でプレビューへの参加を希望する場合は、アカウント担当者に連絡してアクセスを依頼してください。現時点では全ユーザーに一般提供されていません。
- プレビューを利用できる場合、厳格なコミット ID 検証が必要なリポジトリのルールセットに **Committer must match pusher** を追加してください。
- UI または API で表示される pusher 情報を使って、監査・インシデント調査時に author や committer の申告情報と照合してください。

## Anonymous organization-level registries for Dependabot

**URL:** https://github.blog/changelog/2026-10-12-anonymous-organization-level-registries-for-dependabot

### 要約
Dependabot の組織レベルのプライベートレジストリで、認証方式として **Anonymous** を選択できるようになりました。資格情報なしで読み取り可能な内部ミラーなどを登録でき、設定したレジストリはアクセスを許可したすべてのリポジトリに適用されます。GitHub.com では一般提供中で、GitHub Enterprise Server 3.24 でも提供予定です。

### ユーザーにとって良いこと
匿名読み取りが可能なレジストリに不要なトークンを設定せずに済み、Dependabot が依存関係を取得できるリポジトリを組織単位で管理できます。

### アクションプラン
- GitHub.com の組織で匿名アクセス可能なレジストリを使う場合は、**Settings > Secrets and variables > Private registries > New private registry** から登録し、認証方式に **Anonymous** を選択してください。
- プレースホルダートークンを使って登録したレジストリがある場合は、その登録を削除して Anonymous 方式で作り直してください。既存レジストリの認証方式は変更できません。
- 組織レベルのレジストリは、`dependabot.yml` がないリポジトリや Dependabot security updates のみを利用するリポジトリにも、アクセスを許可すれば適用されます。対象リポジトリと GitHub.com の egress allowlist を確認してください。
- GitHub Enterprise Server を利用している場合は、3.24 での提供を確認してから設定してください。
