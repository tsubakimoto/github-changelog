## Usage metrics API adds usage from tools like OpenCode

**URL:** https://github.blog/changelog/2026-10-23-usage-metrics-api-adds-usage-from-tools-like-opencode

### 要約
Copilot 使用状況メトリクス API に `totals_by_client` が追加され、OpenCode、Claude Code、Codex など、Copilot をモデルプロバイダーとして使うクライアント別にリクエスト数、セッション数、トークン使用量を確認できるようになりました。Enterprise、Organization、ユーザー単位の 1 日・28 日レポートが対象で、既存フィールドへの変更はありません。

### ユーザーにとって良いこと
IDE のテレメトリがない外部ツールからのモデル利用もサーバー側で集計され、Copilot の利用実態やツールごとのトークン量に基づくガバナンス判断がしやすくなります。`request_count` はプロンプト数ではなくモデル呼び出し数であり、クライアント名はリクエストに含まれる識別子に基づく参考情報です。

### アクションプラン
- Copilot 使用状況メトリクス API の 1 日・28 日レポートで `totals_by_client` を読み取り、クライアント別のリクエスト数、セッション数、トークン使用量を確認してください。28 日集計では各 `day_totals` 内に含まれます。
- ダッシュボードや分析処理では `client`、`totals_by_model`、およびモデル選択方法を示す `model_selection_mode` を使って、ツールごとの利用状況を評価してください。`request_count` をプロンプト数として扱わないようにしてください。
- レポート閲覧には Copilot 使用状況メトリクスポリシーの有効化と、対象の閲覧権限が必要です。データがない場合は `totals_by_client` は空配列になります。

## Turn notifications into code with GitHub Copilot in Teams

**URL:** https://github.blog/changelog/2026-10-23-turn-notifications-into-code-with-github-copilot-in-teams

### 要約
Microsoft Teams 向けの新しい GitHub アプリで、チャネルやチャットに届く GitHub 通知から `@GitHub` に依頼し、Issue の調査や修正、Pull request の作成へつなげられるようになりました。従来の GitHub notifications アプリを使っている場合は、既存の通知機能を維持したまま最新アプリに更新できます。

### ユーザーにとって良いこと
Teams の会話から離れずに Issue を対応に移し、チームで修正内容を確認できます。GitHub と Copilot の連携により、通知を実際のコード変更や Pull request へつなげやすくなります。

### アクションプラン
- Teams で GitHub notifications アプリを利用中の場合は、新しい統合 GitHub アプリへ更新してください。新規利用の場合はアプリを追加し、`@GitHub` にメンションして案内に沿って GitHub アカウントとリポジトリを接続してください。
- チームで Copilot による Issue 調査や Pull request 作成を試す場合は、生成された変更を通常のレビュー・テスト手順で確認してください。
- ⚠️ 旧式の GitHub アプリは「GitHub (deprecated)」に改称され、2026 年 11 月 16 日に廃止予定です。Copilot in Teams を継続利用するには、それまでに統合 GitHub アプリをインストールしてください。

## EMU deletions fix

**URL:** https://github.blog/changelog/2026-10-23-emu-deletions-fix

### 要約
2026 年 6 月 1 日から 13 日にかけて、SCIM による Enterprise Managed User（EMU）の一部のプロビジョニング解除で、本来の停止・匿名化ではなくアカウント削除が発生していました。GitHub は影響したユーザー記録を 2026 年 10 月に復元し、同じ問題を防ぐコード変更も行いました。

### ユーザーにとって良いこと
影響アカウントは期待される停止・匿名化状態に戻され、Issue、Pull request、監査ログにおける追跡可能性が保たれます。GitHub による復元が行われるため、Enterprise オーナーによる修復作業は必要ありません。

### アクションプラン
- Enterprise の監査ログで、2026 年 6 月 1 日から 13 日の期間に EMU アカウントの `user.delete` イベントがあるか確認してください。該当イベントがなければ影響はありません。
- 該当イベントがある場合も、GitHub が影響レコードを復元済みのため、追加対応は不要です。対象のハードプロビジョニング解除済みアカウントは設計上再プロビジョニングできません。

## Public monitoring adds triage, validity, API, and webhooks

**URL:** https://github.blog/changelog/2026-10-23-public-monitoring-adds-triage-validity-api-and-webhooks

### 要約
Public monitoring に、Enterprise セキュリティダッシュボードでのアラート却下・再オープン、アクティビティ履歴、絞り込みに加え、対応するシークレットの有効性を継続確認する機能が追加されました。アラート情報を取得する REST API と、新たな漏えいを通知する Enterprise webhook も利用できます。

### ユーザーにとって良いこと
公開リポジトリで検出されたシークレットを状態や有効性で優先順位付けし、既存のインシデント対応フローに連携できます。ただし、アラートを閉じても認証情報は失効せず、公開リポジトリから削除もされません。

### アクションプラン
- GitHub Enterprise Cloud の Enterprise 管理者または Enterprise セキュリティマネージャーは、Enterprise セキュリティダッシュボードで Public monitoring を有効化し、アラートの状態・履歴・フィルターを運用してください。機能はパブリックプレビューです。
- 対応プロバイダーの漏えい認証情報の `Active`、`Inactive`、`Unknown` 状態を確認し、アクティブなものは別途プロバイダー側で失効・ローテーションしてください。
- カスタム対応フローに組み込む場合は `GET /enterprises/{enterprise}/secret-scanning/public-monitoring-alerts` と `secret_scanning_public_monitoring_alert` Enterprise webhook を利用してください。
- 利用には GitHub Advanced Security または GitHub Secret Protection のライセンスが必要です。Public monitoring は追加料金なしで提供されます。

## Enterprise installations for GitHub Apps generally available

**URL:** https://github.blog/changelog/2026-10-23-enterprise-installations-for-github-apps-generally-available

### 要約
GitHub Apps の Enterprise へのインストールが一般提供となり、Enterprise のポリシー、セキュリティ設定、プロフィール、メンバー権限、リポジトリアクセスなどを扱う権限と API 対応が拡張されました。組織レベルの検証済みドメインや IP 許可リスト、既存権限の一部 API にも対応が追加されています。

### ユーザーにとって良いこと
Enterprise や Organization の管理自動化で classic PAT に頼らず、必要な権限だけを付与した GitHub App へ移行しやすくなります。ガバナンスやセキュリティ設定を含む幅広い自動化に対応できます。

### アクションプラン
- Enterprise や Organization の管理に classic PAT を使っているワークフローを棚卸しし、対象 API に必要な権限を GitHub App に設定して移行できるか確認してください。
- 移行前に、利用する Enterprise・Organization REST API または GraphQL の操作と、それに対応する GitHub App の権限を照合してください。特に設定変更系の権限は必要最小限にしてください。
- GitHub Enterprise Server で利用する場合は GHES 3.24 への対応を確認してから導入してください。

## GitHub Copilot in Visual Studio — September update

**URL:** https://github.blog/changelog/2026-10-22-github-copilot-in-visual-studio-september-update-2

### 要約
Visual Studio 2026 の Copilot に、Git エージェントによる Pull request の要約、Bring Your Own Model（BYOM）の拡張、NuGet の脆弱性警告からの修正支援が追加されました。Git エージェントには GitHub または Azure DevOps の MCP サーバー接続が必要で、BYOM はプレビュー機能です。

### ユーザーにとって良いこと
Pull request のコメントやファイルをチャット内からたどり、チームが選んだモデルを利用し、NuGet Audit の警告から脆弱なパッケージの修正を依頼できます。これらの Copilot 機能は Free、Student、Pro、Pro+、Max、Business、Enterprise を含む各プランで利用可能です。

### アクションプラン
- Pull request の要約を使うには、GitHub または Azure DevOps の MCP サーバーを接続し、GitHub Copilot Chat で Git エージェントを選択して Git Repository ウィンドウから Pull request をコンテキストに追加してください。
- BYOM を使う場合は新しい Agent（Preview）を利用してください。Microsoft Foundry、OpenAI、Anthropic、Ollama が対応しています。
- ⚠️ BYOM は新しい Agent（Preview）を必須とし、従来の Ask／Agent モードでは利用できなくなりました。更新後に既存の Ollama モデルを再追加する必要があります。
- NuGet の脆弱性修正を使う場合は GitHub Copilot にサインインし、Copilot Chat のツールメニューで NuGet MCP サーバーを有効にしてください。提案されたパッケージ変更は適用前にレビューしてください。

- [GitHub Copilot in Visual Studio — September update](https://github.blog/changelog/2026-10-22-github-copilot-in-visual-studio-september-update-2)
