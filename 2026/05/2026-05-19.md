## Easily apply Copilot code review feedback with Copilot cloud agent

**URL:** https://github.blog/changelog/2026-05-19-easily-apply-copilot-code-review-feedback-with-copilot-cloud-agent

### 要約
Copilot code review の「Implement suggestion」が「Fix with Copilot」に置き換わり、修正方法を選べるダイアログ付きになりました。Pull Request Overview では複数コメントをまとめて Copilot cloud agent に渡す「Fix batch with Copilot」も使えます。

### ユーザーにとって良いこと
レビュー指摘をそのまま修正依頼へつなげやすくなり、個別対応の手間が減ります。修正先やモデル、追加指示を選べるため、意図に合う形で変更を進めやすくなります。

### アクションプラン
- レビュー運用で `Fix with Copilot` と `Fix batch with Copilot` を使う手順をチームに共有してください。
- Copilot cloud agent の利用権限と、PR への直接反映か新規 PR 作成かの運用方針を確認してください。
- ⚠️ 自動適用前提にせず、レビューと承認の確認フローを残してください。

- [Easily apply Copilot code review feedback with Copilot cloud agent](https://github.blog/changelog/2026-05-19-easily-apply-copilot-code-review-feedback-with-copilot-cloud-agent)

## Gemini 3.5 Flash is generally available for GitHub Copilot

**URL:** https://github.blog/changelog/2026-05-19-gemini-3-5-flash-is-generally-available-for-github-copilot

### アクションプラン
- VS Code / Visual Studio / JetBrains / Xcode / Eclipse の対応バージョンを確認してください。
- Business / Enterprise では Gemini 3.5 Flash ポリシーを有効化するか判断してください。
- モデル選定の基準を整え、軽い作業にこのモデルを使う運用を試してください。

## Expanded OIDC support for Dependabot and code scanning

**URL:** https://github.blog/changelog/2026-05-19-expanded-oidc-support-for-dependabot-and-code-scanning

### 要約
Dependabot と code scanning が、組織レベルの private registry 向け OIDC 認証で Cloudsmith と Google Artifact Registry に対応しました。短期有効の認証情報を IdP から動的に取得でき、対応レジストリが増えています。

### ユーザーにとって良いこと
長期保存の資格情報を減らしながら、依存関係更新やスキャンの自動化を進めやすくなります。組織全体で OIDC の設定を統一しやすくなり、運用負荷も下がります。

### アクションプラン
- 組織の private registry 構成が Cloudsmith または Google Artifact Registry を使っているか確認してください。
- Dependabot と code scanning の OIDC 設定を組織レベルで見直してください。
- 既存の静的資格情報を使っている場合は、OIDC への移行計画を立ててください。

### リファレンス
- [Expanded OIDC support for Dependabot and code scanning](https://github.blog/changelog/2026-05-19-expanded-oidc-support-for-dependabot-and-code-scanning)

## Start a GitHub Advanced Security trial from a risk assessment

**URL:** https://github.blog/changelog/2026-05-19-start-a-github-advanced-security-trial-from-a-risk-assessment

### 要約
対象の enterprise 管理者は、Secret Protection または Code Security の risk assessment 画面から直接 GitHub Advanced Security の trial を開始できるようになりました。対象外でも、その画面から有効化したり GitHub に相談したりできます。

### ユーザーにとって良いこと
評価開始までの手順が短くなり、機能検証を始めやすくなります。導入判断に必要な試用を、risk assessment の流れの中でスムーズに進められます。

### アクションプラン
- enterprise の risk assessment 画面から trial 開始できるかを管理者権限で確認してください。
- Secret Protection と Code Security の評価手順を、trial 開始を起点に見直してください。
- 対象外の組織では、直接有効化するか GitHub への相談窓口を明示してください。

### リファレンス
- [Start a GitHub Advanced Security trial from a risk assessment](https://github.blog/changelog/2026-05-19-start-a-github-advanced-security-trial-from-a-risk-assessment)

## Removal of code_scanning_upload field from rate_limit API endpoint

**URL:** https://github.blog/changelog/2026-05-19-removal-of-code_scanning_upload-field-from-rate_limit-api-endpoint

### 要約
`/rate_limit` REST API のレスポンスから `code_scanning_upload` フィールドが削除されました。この値は実際には core 制限プールと結合されていたため、独立したレート制限カテゴリとしては表示されなくなりました。

### ユーザーにとって良いこと
レート制限の表示が実態に近づき、誤解を減らせます。API 応答の扱いが明確になるため、監視や自動化のロジックも整理しやすくなります。

### アクションプラン
- `code_scanning_upload` を参照している `/rate_limit` パース処理を削除してください。
- 代わりに core のレート制限値を使うように、監視・通知・運用スクリプトを更新してください。
- ⚠️ 互換性のない変更なので、API 依存ツールの影響範囲を先に洗い出してください。

### リファレンス
- [Removal of code_scanning_upload field from rate_limit API endpoint](https://github.blog/changelog/2026-05-19-removal-of-code_scanning_upload-field-from-rate_limit-api-endpoint)
