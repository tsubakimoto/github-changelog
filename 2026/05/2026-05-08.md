## Upcoming deprecation of Grok Code Fast 1

**URL:** https://github.blog/changelog/2026-05-08-upcoming-deprecation-of-grok-code-fast-1

### 要約
Grok Code Fast 1 が GitHub Copilot の各体験で 2026-05-15 に非推奨になります。Copilot Chat、inline edits、ask/agent modes、code completions など広い範囲に影響し、代替は GPT-5 mini か Claude Haiku 4.5 です。

### ユーザーにとって良いこと
利用モデルを早めに置き換えることで、Copilot の機能停止や挙動変化を避けやすくなります。Enterprise 環境では、利用可能モデルをポリシーで揃えることで運用の一貫性も保ちやすくなります。

### アクションプラン
- Grok Code Fast 1 を指定している Copilot の設定、スクリプト、運用手順を GPT-5 mini か Claude Haiku 4.5 に更新してください。
- Copilot Enterprise 管理者は、代替モデルが model policy で有効になっているか確認してください。
- ⚠️ 2026-05-15 以降は使えない前提で、モデル名を固定している自動化を点検してください。

### リファレンス
- [Upcoming deprecation of Grok Code Fast 1](https://github.blog/changelog/2026-05-08-upcoming-deprecation-of-grok-code-fast-1)

## Copilot code review comment types now in usage metrics API

**URL:** https://github.blog/changelog/2026-05-08-copilot-code-review-comment-types-now-in-usage-metrics-api

### 要約
Copilot usage metrics API に、コードレビュー提案を comment type 別に集計する `copilot_suggestions_by_comment_type` が追加されました。security や bug_risk など、Copilot がどの種類の指摘をどれだけ出しているかを追跡できます。

### ユーザーにとって良いこと
Copilot code review が何を見つけているか、そして開発者がどの種類の指摘を採用しているかを把握しやすくなります。組織単位の傾向が見えるので、導入効果の説明や改善の優先順位付けに役立ちます。

### アクションプラン
- Enterprise または organization の usage metrics API で `pull_requests` の新しい配列を取得するよう更新してください。
- comment type ごとの提案数と採用数を比較し、レビュー運用の改善点を洗い出してください。
- ⚠️ いまは repository レベルの内訳がないため、必要なら集計粒度の制約を前提に運用してください。

### リファレンス
- [Copilot code review comment types now in usage metrics API](https://github.blog/changelog/2026-05-08-copilot-code-review-comment-types-now-in-usage-metrics-api)

## Disable commit comments on the user level

**URL:** https://github.blog/changelog/2026-05-08-disable-commit-comments-on-the-user-level

### 要約
個人アカウント所有のリポジトリに対して、commit comments をユーザーレベルの既定値で有効・無効に設定できるようになりました。既存のリポジトリ単位設定がある場合は保持され、未設定のリポジトリだけが新しい既定値の影響を受けます。

### ユーザーにとって良いこと
複数の個人リポジトリをまとめて管理しやすくなり、コメント可否の設定を一つずつ直す手間が減ります。コメントを無効にしても既存コメントは保持されるため、運用方針を変えやすくなります。

### アクションプラン
- 個人アカウント配下のリポジトリで commit comments の既定値を見直してください。
- リポジトリごとにコメント許可を明示している場合は、その設定が優先されることを確認してください。
- ⚠️ 無効化すると REST API / GraphQL API からの新規 commit comment 作成もブロックされるため、運用への影響を確認してください。

### リファレンス
- [Disable commit comments on the user level](https://github.blog/changelog/2026-05-08-disable-commit-comments-on-the-user-level)

## More flexible secrets and variables for Copilot cloud agent

**URL:** https://github.blog/changelog/2026-05-08-more-flexible-secrets-and-variables-for-copilot-cloud-agent

### 要約
Copilot cloud agent 用に、Actions とは別の `Agents` secrets and variables が導入されました。組織レベルで秘密情報や変数を共有でき、repository-level でも専用の Agents 設定として管理できます。

### ユーザーにとって良いこと
複数リポジトリへ同じ MCP サーバー設定やトークンを配る作業が楽になります。Copilot cloud agent の構成を大規模に統一しやすくなり、設定の重複も減らせます。

### アクションプラン
- 組織で共有したい secrets / variables を Actions から Agents に移してください。
- repository-level の設定を使う場合は、`Agents` セクションで必要な値が入っているか確認してください。
- ⚠️ どのリポジトリが各 secret / variable にアクセスできるかを、配布前に見直してください。

### リファレンス
- [More flexible secrets and variables for Copilot cloud agent](https://github.blog/changelog/2026-05-08-more-flexible-secrets-and-variables-for-copilot-cloud-agent)

## CodeQL 2.25.3 adds Swift 6.3 support

**URL:** https://github.blog/changelog/2026-05-08-codeql-2-25-3-adds-swift-6-3-support

### 要約
CodeQL 2.25.3 が Swift 6.3 をサポートし、C/C++ の複数クエリが default suite に昇格しました。Python、Java/Kotlin、JavaScript/TypeScript、GitHub Actions でも、精度向上や誤検知削減が入っています。

### ユーザーにとって良いこと
新しい言語機能を使っているコードでも、CodeQL による検査を継続しやすくなります。アラートの品質が上がることで、セキュリティ対応のノイズを減らしやすくなります。

### アクションプラン
- Swift 6.3 を使っているプロジェクトは、CodeQL のバージョンを 2.25.3 以降に更新してください。
- C/C++ の default suite 追加により増えるアラートを確認し、既存のトリアージ基準を調整してください。
- GHES 利用時は、対応バージョンに合わせて CodeQL の手動更新が必要か確認してください。

### リファレンス
- [CodeQL 2.25.3 adds Swift 6.3 support](https://github.blog/changelog/2026-05-08-codeql-2-25-3-adds-swift-6-3-support)

## Upcoming deprecation of GPT-4.1

**URL:** https://github.blog/changelog/2026-05-07-upcoming-deprecation-of-gpt-4-1

### 要約
GPT-4.1 が GitHub Copilot の各体験で 2026-06-01 に非推奨になります。推奨代替は GPT-5.5 で、Copilot Chat、inline edits、ask/agent modes、code completions に影響します。

### ユーザーにとって良いこと
早めに代替モデルへ移行すれば、Copilot の利用継続性を保ちやすくなります。Enterprise 管理者も、モデルポリシーを先に整えて利用モデルのばらつきを減らせます。

### アクションプラン
- GPT-4.1 を指定している設定や自動化を GPT-5.5 に更新してください。
- Copilot Enterprise 管理者は、GPT-5.5 が必要なポリシーで有効か確認してください。
- ⚠️ 2026-06-01 以降は利用できない前提で、固定指定のモデル名を洗い出してください。

### リファレンス
- [Upcoming deprecation of GPT-4.1](https://github.blog/changelog/2026-05-07-upcoming-deprecation-of-gpt-4-1)
