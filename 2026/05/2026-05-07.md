## Claude Sonnet 4 deprecated

**URL:** https://github.blog/changelog/2026-05-07-claude-sonnet-4-deprecated

### 要約
GitHub Copilot 全体で Claude Sonnet 4 の提供が終了し、推奨モデルは Claude Sonnet 4.6 になりました。Copilot Chat、inline edits、ask/agent modes、code completions など、主要な利用面に影響します。

### ユーザーにとって良いこと
サポート対象のモデルに揃えることで、Copilot の挙動を安定して使い続けやすくなります。Enterprise 環境でも、モデルポリシーを整えれば利用可能モデルを明確に管理できます。

### アクションプラン
- Copilot のワークフローや自動化で Claude Sonnet 4 を指定している箇所を Claude Sonnet 4.6 に更新してください。
- Copilot Enterprise 管理者は、必要なモデルが model policy で有効になっているか確認してください。
- ⚠️ 旧モデルの継続利用はできない前提で、モデル名を固定している設定やスクリプトを点検してください。

### リファレンス
- [Claude Sonnet 4 deprecated](https://github.blog/changelog/2026-05-07-claude-sonnet-4-deprecated)

## Enterprise Live Migrations is now in public preview

**URL:** https://github.blog/changelog/2026-05-07-enterprise-live-migrations-is-now-in-public-preview

### 要約
Enterprise Live Migrations が public preview になりました。GHES から GitHub Enterprise Cloud へ、開発者の作業を止めにくいまま大規模リポジトリを移行できるようになります。

### ユーザーにとって良いこと
長いコードフリーズや大きな切り替え停止を避けやすくなり、移行中も開発を継続しやすくなります。巨大な monorepo や履歴の深いリポジトリでも、移行の見通しを立てやすくなります。

### アクションプラン
- GHES からの移行候補がある場合は、GEI と ELM のどちらを使うべきか比較してください。
- ELM を使う場合は、GHES の対応バージョン条件と `elm` CLI の導入手順を確認してください。
- ⚠️ public preview のため、本番移行前に小規模な対象で手順と切り戻しを検証してください。

### リファレンス
- [Enterprise Live Migrations is now in public preview](https://github.blog/changelog/2026-05-07-enterprise-live-migrations-is-now-in-public-preview)

## Rubber Duck in GitHub Copilot CLI now supports more models

**URL:** https://github.blog/changelog/2026-05-07-rubber-duck-in-github-copilot-cli-now-supports-more-models

### 要約
Copilot CLI の Rubber Duck が、GPT セッションでは Claude ベースの critic を使い、Claude セッションではより強い GPT-5.5 の second opinion を使うようになりました。モデルファミリーをまたいでレビュー精度を高める更新です。

### ユーザーにとって良いこと
普段のオーケストレータとは別系統のモデルで見直すため、見落としや跨ぎのある不整合を拾いやすくなります。長めの作業や複数ファイルにまたがる修正で、より信頼しやすい二次レビューになります。

### アクションプラン
- Copilot CLI で `/experimental` を有効にして Rubber Duck の動作を確認してください。
- GPT セッションと Claude セッションの両方で、第二のレビュー結果がどう変わるか比較してください。
- チームでレビュー品質を重視する場合は、Rubber Duck を標準の確認手順に含めてください。

- [Rubber Duck in GitHub Copilot CLI now supports more models](https://github.blog/changelog/2026-05-07-rubber-duck-in-github-copilot-cli-now-supports-more-models)

## Repository rulesets: User bypass and branch renaming

**URL:** https://github.blog/changelog/2026-05-07-repository-rulesets-user-bypass-and-branch-renaming

### 要約
Repository rulesets に、個人ユーザーを bypass actor として追加する機能と、ruleset の範囲内なら保護ブランチを rename できる機能が追加されました。UI、REST API、GraphQL から操作でき、管理負荷を下げられます。

### ユーザーにとって良いこと
単一ユーザーや service account のために専用チームを作らなくてよくなり、権限管理が簡単になります。`master` から `main` へのような定常的な rename も、ルール範囲を維持できるなら管理者の介入なしで進めやすくなります。

### アクションプラン
- 既存の bypass 用 team / role がある場合は、単一ユーザーを直接追加できるか見直してください。
- ブランチ rename 運用がある組織は、ruleset のスコープ条件を満たす rename パスを確認してください。
- ⚠️ 重要な ruleset 変更は、UI・REST API・GraphQL のどの経路で適用しても意図通りの権限になるか確認してください。
